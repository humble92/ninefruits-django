# 17. 科目と卒業要件

メニュー: **教育課程・開講科目 > 科目**、**卒業要件**(権限 `科目・バージョン・履修条件の管理`、`卒業要件の管理`)

## 科目とバージョン

科目は、変わることのない **コード** と、有効期間を持つ **バージョン** で構成されます。科目名、単位、時間数、科目区分、評価方法、履修条件はバージョンに属します。旧システム(YUSTIC)は科目コードと開始日で科目を区別していましたが、成績は科目コードしか参照していなかったため、学生がどのバージョンを履修したのかがあいまいでした。新システムでは、開講科目と成績はバージョンを参照します。

- 同じ科目のバージョンの期間は重ねられません(データベース制約)。どの日付においても、有効なバージョンは必ず 1 つです。
- 開講科目は、授業期間の開始日に有効なバージョンで開講されます。

| 項目 | 説明 |
|---|---|
| 科目コード | 例: `CSE2010`。コード自体に業務上の意味は持たせません(旧システムの `009*` による単位互換の判定のような規則は、以下の項目に置き換えられています) |
| 管理組織 | 科目を管理する組織単位。その開講科目の既定の開講組織になります |
| 科目名、説明 | 言語ごとに入力します |
| 単位、講義時間・実習時間 | 0.5 刻み |
| 科目区分 | 基準データ > 科目区分 |
| 評価方法 | 段階評価または合否 |
| 履修単位上限に含める | オフにすると、その科目は履修登録の単位上限の計算から除外されます(単位互換科目など) |
| 授業評価 | オフにすると、その科目は授業評価の対象外になります(実習、インターンシップなど。[第 22 章](22-course-evaluation.md)) |
| 繰り返し単位取得可 | 再度履修したときに再履修扱いではなく、改めて単位を取得します(テーマが変わるゼミなど) |

## 科目の改訂

単位や科目名が変わるときは、バージョンを編集せずに **改訂** します。科目の **編集** 画面の **バージョン** タブで、現行バージョンの **日付を指定して改訂** をクリックし、新バージョンの適用開始日、変更する値、理由を入力します。

- 現行バージョンは適用開始日の前日で終了し、新バージョンは現行バージョンとその履修条件をコピーして始まります。
- すでに開講されている開講科目と過去の成績は、以前のバージョンを参照したままです。
- バージョンを直接編集するのは、誤字など意味の変わらない修正に限ります(データ変更履歴に記録されます)。

## 先修科目と同時履修科目

**バージョン** タブ(行のリンク)からバージョンを開き、バージョン画面の下部にある **履修条件** で入力します。新しいバージョンは科目画面の **科目バージョンを追加** で追加します。

| 項目 | 説明 |
|---|---|
| 種類 | 先修科目(先に修了している必要がある)または同時履修科目(同じ学期に一緒に履修する。すでに修了していれば満たしたものとみなす) |
| グループ | 同じグループの科目は、いずれか 1 つを修了すれば足ります(または)。すべてのグループを満たす必要があります(かつ) |
| 最低成績 | 既定の成績評価基準の成績コード(例: `C0`)。空欄: 合格となる成績 |
| 同一学期の履修可 | 先修科目を同じ学期に履修してもよい場合 |

例: グループ 1 に `CSE1001`、グループ 2 に `MAT1001` と `MAT1002` → `CSE1001` かつ(`MAT1001` または `MAT1002`)。履修登録時に先修科目ルールがこれを確認します([第 20 章](20-registration.md))。

## 代替科目

教育課程の改編で科目が置き換わるときは、科目の **編集** 画面の **代替科目** タブに、代わりの科目とその期間を入力します。**相互代替** をオンにすると互いに代替として扱い、オフにすると代替科目がこの科目の代わりとしてのみ認められます。再履修の判定([第 20 章](20-registration.md))と卒業判定([第 26 章](26-graduation.md))で使われます。

## 卒業要件

要件セットは、プログラム、**プログラム区分**(主専攻、第二専攻、副専攻)、**教育課程年度** の範囲ごとに 1 つ作成します。学生には、学籍の教育課程年度に合う要件セットが適用されます。

- 同じプログラム・プログラム区分の教育課程年度は重ねられません。終了年度を空欄にすると、次の要件セットが始まるまで適用され続けます。
- 要件の種類

| 種類 | 入力 | 例 |
|---|---|---|
| 区分別単位 | 科目区分、最低単位数 | 教養(必修)9 単位 |
| 必修科目 | 科目の一覧 | 専攻必修科目 4 科目すべて |
| 選択科目群 | 科目の一覧、最低単位数または最低科目数 | 専攻選択科目から 12 単位 |
| 試験合格 | 試験種別 | 英語総合試験に合格([第 24 章](24-assessments.md)) |

第二専攻と副専攻には、主専攻より小さい独自の要件セットを設けます(例: 第二専攻 36 単位、副専攻 21 単位)。要件は卒業判定([第 26 章](26-graduation.md))で確認されます。

## CSV 取り込み

科目一覧の **CSV 取り込み**(`科目・バージョン・履修条件の管理` 権限)で、科目バージョンを一括で読み込みます。1 行が 1 つのバージョンです。科目はコードで照合され(存在しなければ作成されます)、バージョンはコードと適用開始日で照合されるため、同じファイルを再度取り込むと更新になり、適用開始日が異なる行は改訂になります。期間が重なる行は、その行だけが失敗します。

| 列 | 説明 |
|---|---|
| `code` | 科目コード(必須) |
| `org_unit` | 管理組織単位のコード。新しい科目では必須 |
| `effective_start_date`, `effective_end_date` | バージョンの期間(`YYYY-MM-DD`) |
| `title_en`, `title_ko`, `title_zh-hans`, `title_lo` | 言語ごとの科目名。新しい科目では英語が必須 |
| `credits`, `lecture_hours`, `lab_hours` | 単位数(新しいバージョンでは必須、0–30)、時間数(0–40) |
| `category` | 科目区分のコード |
| `grading_basis` | `graded` または `pass_fail` |
| `counts_toward_credit_limit` | `1`/`0` |

同じことを `uv run manage.py reference_import courses <file> --actor=<email>` でも行えます([第 9 章](09-csv-import.md))。
