# 21. 成績

メニュー: **成績 > 成績入力状況**、**評価方式変更申請**、**成績訂正**、**学期記録**、**設定 > 成績規程**。教員はポータルの **担当授業 > 成績を入力** を使います。

| 権限 | できること |
|---|---|
| `成績・成績入力状況・学期記録の閲覧` | 成績入力状況、学期記録、学生の成績表の閲覧 |
| `成績の確定・差し戻し、教員に代わる成績入力、成績締め` | 開講科目の成績の確定または差し戻し、教員に代わる成績入力(期間にかかわらず)、成績分布上限を超えた成績の例外提出、成績締め、再計算。組織単位の範囲付きで割り当てた場合は、その組織が開講する開講科目のみ |
| `成績分布上限を超えた成績提出の通知を受ける(学科長、教務課)` | 例外提出の通知を受け取ります。組織単位の範囲付きで学科長と教務課長に割り当てます |
| `確定成績の訂正申請` | 自分が担当していない開講科目の訂正申請(例: 学術不正による成績の取消) |
| `成績訂正の承認・却下(自分の申請を除く)` | 成績訂正申請の判断 |
| `GPA・再履修・学業状況・成績優秀者の規程の管理` | 成績規程の設定 |

教員は、権限がなくても自分の開講科目の成績を入力し、訂正を申請できます。ロールの既定: 学籍担当は閲覧、確定、承認、例外の確認を、教務担当は閲覧、訂正申請、規程を、証明書担当と学科助手は閲覧を持ちます。評価方式変更申請は `開講科目の編成(教員・時間・教室)` 権限で判断します。

## 旧システムとの違い

- 旧システム(YUSTIC)では、教員が保存した成績がそのまま確定となり、教務課は画面上で直接修正していました。理由の入力も承認の手順もなく、一部のアカウントによる修正はバックアップ記録にすら残りませんでした。新システムには **入力 → 提出 → 確定** の段階があり、確定した成績は **別の人が訂正申請を承認したとき** にだけ変わります。アプリケーションとデータベース(トリガー)の両方でこれを保証しています。
- 旧システムでは、リクエストを操作すれば、教員が担当していない開講科目の成績を保存できました。新システムでは、割り当てられた教員と権限の範囲をサーバーとデータベースで確認します。
- GPA、学業警告、成績優秀者は、画面ごとにその場で計算するのではなく、**学期記録** として保存されます。成績締めのときに、その学期の公式記録になります。
- 再履修の場合、以前の成績が累積 GPA から除かれるのは **新しい成績が確定した後** だけです(旧システムは履修登録の時点で除外し、開講科目が取り消されても元に戻しませんでした)。
- 旧システムは成績メニューを無効にするだけで、アドレスを直接入力すれば成績が見えていました。新システムは成績閲覧の制限をサーバーで適用します。

## 学期の流れ

1. **業務期間**([第 10 章](10-terms.md)): 授業期間ごとの **成績入力** の期間。教員はこの期間中にのみ入力・提出できます。
2. 教員が成績を入力して提出します。`uv run manage.py grades_remind_missing {term}` は、未提出の教員に催促メールを送ります。
3. **成績入力状況** で、開講科目ごとに確定するか、教員に差し戻します。
4. すべての開講科目が確定したら、**学期記録 > 成績締め** を行います。学期記録、学業状況、成績優秀者が確定し、学期は **成績締め済み** になります。
5. それ以降に変更する成績は **成績訂正** を通します。

## 成績評価基準と評価方式

**成績評価基準は導入時に固定され、変更できません**(2026-10-23 の決定)。すべての成績と GPA がその基準に基づいているためです。`uv run manage.py setup_install --grade-scale=4.5|4.3` で設定します。指定しない場合は最初のプロファイルの基準が使われます(韓国の大学 4.5、旧 YUST 4.3)。基準データ > 成績評価基準 の **既定** の印は移動できず、既定の基準は削除できません。各成績の **素点の範囲**(下限・上限 %)とグレードポイントはその画面で編集します([第 11 章](11-course-categories-and-grade-scales.md))。

すべての開講科目には **評価方式** があります。既定は **絶対評価** です。

| 評価方式 | 教員が入力するもの | 保存されるもの | 提出条件 |
|---|---|---|---|
| 絶対評価(既定) | 学生ごとの **素点(0–100)**。成績は素点の範囲から決まり、選べません(I など素点のない成績だけを直接選びます) | 素点(原点数)、成績、グレードポイント | 全学生の成績 |
| 相対評価 | 学生ごとの **成績**。素点は入力しません(入力すると拒否されます) | 成績、グレードポイント | 全学生の成績 + **成績分布上限** の遵守 |
| 合否科目 | 評価方式にかかわらず P/NP | 成績 | 全学生の成績 |

- 相対評価にしたい教員は、成績入力画面で **相対評価 を申請** をクリックします(理由付き)。開講組織に対する `開講科目の編成(教員・時間・教室)` 権限を持つ人(学科助手、教務担当)が **成績 > 評価方式変更申請** で承認または却下し(メモが必要)、教員にはメールで通知されます。承認されると、以前の方式で入力された下書きの成績は消去されます。成績が **提出済み** になった後は、申請も変更もできません。職員は開講科目画面でも方式を変更できますが、成績が入力されるまでに限ります。
- 再履修時の最高成績: 絶対評価では、上限より高い成績になる素点は **上限の成績に引き下げ** られます(素点はそのまま残ります)。相対評価では、上限を超える成績は選べません。

## 成績分布上限(相対評価)

**設定 > 成績規程 > 相対評価**: 成績グループごとの上限(既定: A グループ 30%、B グループ 40%)、上限の許容幅(既定 1 ポイント)、確認の対象とする評価対象学生の最低人数(既定 10 名)。

- 成績グループは文字で分けます。A+、A0、A- が A グループ、B+、B0、B- が B グループです。上限のないグループ(C、D、F)は制限がありません。
- 分母は、開講科目の学生のうち GPA に算入される成績を持つ学生の数です。履修中止の学生と P/NP/I は除外されます。
- 最低人数に満たない開講科目は確認されません(7 名で A を 30% に収めることはできないため)。
- 教員は成績入力画面の **成績分布上限を確認** で、上限に対する現在の分布を確認でき、上限を超えている場合は **提出できません**。
- 成績管理の権限を持つ職員は上限を超えて提出できますが、**例外提出** になります。理由は必須で、分布と理由は業務ログに記録され、`成績分布上限を超えた成績提出の通知を受ける(学科長、教務課)` 権限の保有者(組織単位の範囲付きで割り当てられた学科長、教務課長)にメールが届き、開講科目には **例外として提出** の印が付きます。**成績入力状況** では、例外提出だけに絞り込めます。

## 成績入力(教員)

ポータルの **担当授業** で、開講科目の **成績を入力** を開きます。画面の上部には、開講科目の評価方式、入力の案内、評価方式変更申請が表示されます。

- 絶対評価: 素点を入力するとすぐに成績が表示されます。
- 相対評価: 成績だけを選びます。素点の列はありません。**成績分布上限を確認** で上限を確認してから提出します。
- 成績の選択肢は科目の評価方法に従います。段階評価科目では文字の成績が、合否科目では P/NP が表示されます([第 11 章](11-course-categories-and-grade-scales.md))。
- **下書き保存** はいつでもできます。学生には下書きの成績は見えません。
- **成績を提出** するには全学生の成績が必要です。提出後は教員が変更できなくなります。成績に誤りがある場合は、確定前なら教務課に差し戻しを依頼し、確定後なら訂正を申請します。
- 履修中止の学生は W と表示され、成績は付きません。

## 確定と差し戻し(教務課)

**成績入力状況**: 学期の開講科目と、未提出・提出済み・確定の件数。**確定可能** の絞り込みでは、全学生の成績が提出済みの開講科目だけが表示されます。

- **確定**: 提出された成績を確定します。履修は **修了** になり、学生が成績を見られるようになります。学生の学期記録は再計算されます。複数の開講科目を選んで **選択項目を確定** で確定することもできます。未提出の学生がいる開講科目はスキップされます。
- **教員に差し戻し**: 理由を付けて提出を取り消します。成績は下書きに戻り、教員にメールが届きます。
- **成績**: 成績入力画面を開きます。教務課は、確定前であれば期間にかかわらず成績を入力・変更できます。教員が **提出済み** にした成績を職員が変更すると、変更前後の値が監査イベント `grades.submitted_changed` に記録されます。

## 成績訂正

確定した成績を変更する唯一の方法です。

1. 申請: 教員が成績入力画面で学生の **訂正を申請** をクリックします(理由付き。絶対評価では新しい素点、相対評価では新しい成績を入力)。再履修時の上限は訂正にも適用されます。担当していない開講科目については、`確定成績の訂正申請` 権限を持つ職員が同じ画面で申請します。1 つの成績につき、処理中の申請は 1 件までです。
2. 判断: **成績 > 成績訂正**(既定: 承認待ちの一覧。メニューに承認待ちの件数が表示されます)で **承認** または **却下** をクリックします(メモが必要)。申請者は自分の申請を判断できません(データベース制約でも保証されます)。
3. 承認されると成績(絶対評価では素点と成績)がすぐに変わり、学生の学期記録と以降の学期の累積 GPA が再計算されます。学業状況と成績優秀者は、成績締めのときに確定した値のままです。

申請者は承認待ちの間、**申請を取消** できます。すべての申請と判断は理由とともに業務ログに記録されます。

## GPA の計算

| 項目 | 規則 |
|---|---|
| 履修単位 | 確定したすべての科目(F、P、NP、I を含む) |
| 修得単位 | 合格の成績(F、NP、I を除く) |
| GPA 対象単位 | GPA に算入される成績。F は 0 点として算入し、P/NP/I は除外します |
| GPA | 合計(グレードポイント × 単位)÷ GPA 対象単位。合否科目だけの学期には GPA がありません |
| 小数 | 小数点以下の桁数と端数処理(四捨五入、切り捨て)は規程に従います。整数演算のため、境界で誤差は生じません(例: 3.4375 → 3.438) |
| 学期 GPA | その学期のすべての成績(再履修によって置き換えられた以前の成績も、その学期の GPA には算入されます) |
| 累積 GPA | 再履修した科目は規程に従って 1 回だけ算入します。**最新の履修**(既定。成績が下がっても最新のもの)または **最高の成績**。置き換えられた成績は累積単位からも除かれ、成績画面には「累積 GPA では再履修の成績に置き換え」と表示されます |

再履修の関係は履修登録のときに設定されます([第 20 章](20-registration.md))。同じ科目または代替科目を再び履修すると、以前の履修と結び付けられます。

## 学業状況と成績優秀者(成績締め)

| 規程 | 既定 | 旧 YUST プロファイル |
|---|---|---|
| 警告の基準 | 学期 GPA 1.75 未満 | 1.3 未満 |
| 正規学期のみ判定 | はい | はい |
| 除籍審査となる警告回数 | 0(無効) | 4 |
| 連続した警告のみ数える | いいえ(通算回数) | いいえ |
| 成績優秀者の最低 GPA、最低 GPA 対象単位 | 4.0、15 単位 | 0、0(旧システムは単純に上位 N 名を選んでいました) |
| 不合格科目がある場合は成績優秀者の対象外 | はい | いいえ |
| GPA の小数点以下の桁数 | 2、四捨五入 | 3、四捨五入 |
| 成績評価基準(導入時に固定) | 4.5(KR45) | 4.3(YUST43) |
| 成績分布上限(相対評価) | A 30%、B 40%、許容幅 1 ポイント、10 名以上で確認 | 同じ |

- **学業警告**: 学期 GPA が基準 **未満**。合否科目だけの学期では警告になりません。
- **除籍審査**: 警告回数が基準に達すると対象として表示されます。除籍そのものは学籍異動で行います([第 13 章](13-status-changes-and-advisors.md))。
- 正規学期のみを判定する場合、夏季・冬季学期には学業状況がなく、連続した警告の数え方も途切れません。
- **成績優秀者**: 基準を満たす学生を、プログラムごとに学期 GPA で順位付けします(同点は同順位とし、次の順位は飛ばします)。
- 学籍の **学業状況** は最新の結果に変わります。業務期間と開講科目の履修対象の「学業状況」の条件はこの値を使います。

**学期記録** 画面では、学期、学業状況、成績優秀者、プログラムで絞り込むと、学業警告の学生の一覧と成績優秀者の一覧(旧システムの警告・成績優秀者の帳票)が表示されます。**成績締め** は、まず **プレビューのみ** をオン(既定)にしたまま実行して確定していない開講科目を確認し、その後オフにして再度実行します。**再計算** は、変更した規程を過去の学期の記録に適用します(理由が必要)。

## 学生の画面と成績表

職員が学生の成績表を開くと、監査イベント `transcript.viewed` に記録されます(学籍番号付き)。

- ポータルの **成績**: 学期ごとの確定成績(履修中止は W)、学期 GPA と修得単位、累積 GPA、学業状況、成績優秀者。卒業生も閲覧できます。確定していない成績は表示されません。
- **印刷**、**PDF**: 確認用の非公式の成績表。PDF は Gotenberg で作成されます。正式な成績証明書は証明書として発行します([第 23 章](23-certificates.md))。職員は学籍画面または学期記録の **成績表** で学生の成績表を開きます(`成績・成績入力状況・学期記録の閲覧` 権限)。
- **制限措置** で **成績閲覧を制限** がオンになっている学生は、成績画面と成績表を見られません([第 20 章](20-registration.md))。
- 授業評価の期間中、その学期の授業評価を終えていない学生には、その学期の成績が表示されません(設定による。[第 22 章](22-course-evaluation.md))。

## 成績規程

**設定 > 成績規程**(`GPA・再履修・学業状況・成績優秀者の規程の管理` 権限)。上の表の項目を変更します。変更した規程は次の計算から適用されます。過去の学期の記録に適用するには **再計算** します。学業状況と成績優秀者は成績締めのときに確定するため、締め済みの学期には改めて適用されません。

## このインストールでの画面

画面と機能は原版(Filament、Livewire)と同じですが、操作方法が少し異なります。

- **成績入力状況** の行メニュー: **成績**(ポータルの成績入力画面)、**確定**(確認画面)、**教員に差し戻し**(理由の入力画面)。複数の開講科目を確定するには、一覧で選択して操作リストから **選択項目を確定** を選びます。フィルター: 学期(既定: 現在の学期。すべての学期は **全体**)、開講組織、例外として提出、確定可能。
- **成績訂正** と **評価方式変更申請** の行メニューにある **承認** と **却下** は、メモを入力する画面を開きます。既定の一覧には処理待ちの申請が表示され、メニューには処理待ちの件数が表示されます。
- **学期記録** 一覧の上にある **成績締め**: 学期、**プレビューのみ**(既定でオン)、理由。プレビューでは、成績締めが可能かどうかと確定していない開講科目(最大 30 件)がメッセージで表示されます。開始した成績締めは、学生 100 人ずつのキュータスク(Celery)として実行され、進行中の成績締めは学期記録一覧の上に進捗が表示されます。完了すると学期は **成績締め済み** になり、開始した職員にメールが届きます。タスクが失敗した場合、成績締めは完了せず学期はそのままです。原因を解決してから再度成績締めを行ってください(同じ結果になります)。コマンドラインからは `uv run manage.py term_close {term} --dry-run`、`uv run manage.py term_close {term} --reason=...` で実行します([コマンド](../operations/commands.md))。
- **成績規程** では、成績分布上限を評語と割合をカンマで区切って入力します。例: `A=30, B=40`。空欄は上限なしを意味します。
- ポータルの成績入力: 絶対評価では、素点を入力すると少し後にその横に成績が表示されます。**下書き保存**、**成績分布上限を確認**、**成績を提出** は画面の下部にあります。保存に失敗した場合(例: 範囲外の点数)、入力した値がエラーとともに再表示されます。学生の行の **訂正を申請** で、表の下に申請欄が開きます。
- 職員用の成績表のアドレス: `/student-records/{student record id}/transcript/`(学籍画面の **成績表** ボタン、学期記録の行の **成績表**)。PDF にするには `?format=pdf` を付けます。
- LMS に連携された開講科目では、成績入力画面で LMS の点数を下書きとして読み込めます([第 28 章](28-lms-integration.md))。授業評価が実施中で未完了の学期の成績は、案内と **授業評価** へのリンクとともに非表示になります([第 22 章](22-course-evaluation.md))。
