# 3. 二要素認証

## ユーザーの登録方法

ユーザーはポータルの **セキュリティ** ページ(`/portal/security/`、管理画面ではユーザーメニューの **二要素認証**)で登録します。登録または無効化の前に、パスワードをもう一度確認します。

### 認証アプリ(推奨)

1. **二要素認証を有効にする** を押します。
2. Google Authenticator や Microsoft Authenticator などの認証アプリで QR コードを読み取ります。
3. アプリに表示される 6 桁のコードを入力し、**確認** を押します。
4. 画面に表示される **リカバリーコード** を安全な場所に保管します。スマートフォンを紛失した場合、各コードを 1 回ずつ使用できます。

### メールのコード

システム管理者が許可している場合にのみ表示されます。認証アプリを使えないユーザー向けの方法で、認証アプリより安全性は低くなります。

1. **メールのコード** の欄で **設定用のコードを送信** を押します。
2. アカウントのメールアドレスに送られた 6 桁のコードを入力し、**確認** を押します。
3. 以降はログインのたびにメールでコードが届きます。コードは 10 分以内に 1 回だけ使用できます。5 回間違えると新しいコードが必要です。コードの送信は 1 分に 1 回、1 時間に最大 5 回までです。

両方の方法を登録できます。ポリシーが「必須」の場合、最後に残った方法は無効にできません。

## ポリシー設定(システム管理者)

管理画面の **設定 > セキュリティ** で設定します。保存すると、すべてのユーザーに次のページ読み込みから適用されます。

| 設定 | 説明 |
|---|---|
| ポリシー | **使用しない** / **推奨(任意)**: 未登録のユーザーには案内のみ表示 / **選択したロールに必須**: 選択したロールを持つユーザーは登録が必要 / **全員に必須** |
| 二要素認証を必須とするロール | ポリシーが「選択したロールに必須」の場合に選択します |
| 猶予期間(日) | 要件が初めて適用されてから、登録せずに作業を続けられる期間。この期間中はポータルと管理画面の上部に期限の案内が表示されます。期間が過ぎると、セキュリティページしか使用できません。0 は即時を意味します |
| デバイスを記憶する期間(日) | **このデバイスを記憶する** を選択したデバイスでコードの入力が省略される期間。0 にするとこの機能は無効になります |
| メールでのコードを許可 | オフにすると、メールのコードは二要素認証として扱われません。メールのコードだけを登録したユーザーには、ポリシーに従って認証アプリの登録が求められます |

推奨運用: 職員のロール(学籍担当、教務担当、システム管理者など)には **選択したロールに必須**、学生には推奨。

## リセット(スマートフォンの紛失など)

1. **ユーザーとアクセス > ユーザー** でユーザーを開きます。
2. ページ上部の **二要素認証をリセット** を押し、理由を入力します(`二要素認証のリセット` 権限が必要)。
3. ユーザーの認証アプリ、リカバリーコード、メールのコード、記憶されたデバイスがすべて消去されます。猶予期間は再び開始されます。

自分自身のアカウントはリセットできません。リセットは理由とともにセキュリティイベントと業務ログに記録されます。

唯一の管理者がスマートフォンを紛失して管理画面にアクセスできない場合は、IT 運用者が `uv run manage.py security_reset_mfa` でリセットします(Docker: `docker compose exec app uv run manage.py security_reset_mfa`、[コマンドリファレンス](../operations/commands.md))。
