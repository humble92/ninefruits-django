# 4. 監査

**監査** メニューの 3 つの画面は読み取り専用で、誰も編集・削除できません(`監査記録の閲覧` 権限と `セキュリティイベントの閲覧` 権限が必要)。一覧には追加・変更・削除のボタンがなく、行を開くと詳細が読み取り専用で表示されます。

| 画面 | 表示内容 | 例 |
|---|---|---|
| 業務ログ | 誰が何を、**なぜ** 行ったか。理由と詳細 | ロール割り当て(理由: 学期中の代行)、権限の変更(追加・削除の一覧)、設定の変更(変更前・変更後)、コマンドの実行 |
| データ変更履歴 | テーブルの行の変更前・変更後の値。アプリケーションを経由しない直接の変更も記録されます | `users` UPDATE、変更された列 `locale` |
| セキュリティイベント | ログイン、ログイン失敗、二要素認証、権限関連のイベント、パスワードとメールアドレスの変更、監査記録の削除(`audit_prune`) | ログイン失敗(ログイン名、IP) |

## 見方

- **ユーザー** 列: 画面での操作はユーザー名または `user:番号`、自動ジョブ(Celery)は `system:task:...`、コマンドは `system:command:...` と表示されます。
- パスワード、二要素認証のシークレットなどの値は `[redacted]` とマスクされます。
- 同じ **リクエスト ID** を持つ記録は、1 回の画面リクエストで作成されたものです。同じリクエスト ID を各画面で検索すると、1 つの操作の経緯をすべて確認できます。コマンドの実行には `cmd-` で始まる実行 ID が使われます。

## よくある調べ方

一覧右上の **フィルター** で条件を選び、検索欄に値を入力します。

| 知りたいこと | 方法 |
|---|---|
| ユーザーの権限がいつ変わったか | 業務ログで、ログ `security`、イベント `role.assigned`、`role.assignment_revoked` |
| ログイン失敗が多いアカウント | セキュリティイベントでイベント `ログイン失敗` で絞り込み、ログイン名の列を確認 |
| セキュリティポリシーを変更した人 | 業務ログのイベント `settings.updated` |
| 特定の行がどのように変わったか | データ変更履歴でテーブルを絞り込み、レコード ID で検索 |
