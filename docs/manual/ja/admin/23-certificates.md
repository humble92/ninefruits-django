# 23. 証明書

メニュー: **証明書 > 発行済み証明書**、**証明書 > 証明書種別**、**設定 > 証明書設定**。証明書は学籍画面(**学生・教職員 > 学籍** で学籍を開きます)の **証明書を発行** ボタンで発行します。学生はポータルの **証明書** で自分の証明書の PDF をダウンロードします。証明書は誰でも `/verify/{code}/` ページで検証できます。

| 権限 | できること |
|---|---|
| `証明書の発行・再作成・失効` | 発行、再作成、失効、発行済み証明書の閲覧(学籍閲覧の範囲内) |
| `証明書種別・テンプレート・設定の管理` | 種別と言語ごとのテンプレート、発行番号の形式、発行者名義 |

ロールの既定: 証明書担当は発行を、学籍担当は両方を、教務担当は種別とテンプレートの管理を持ちます。発行権限は **全体範囲** で付与してください(データベースのポリシーは全体範囲の付与のみを受け付けます)。職員がどの学生の証明書を発行できるかは、その職員の学籍閲覧範囲に従います。たとえば、ある学部の証明書担当には `証明書の発行・再作成・失効` を全体範囲で、`学籍の閲覧` をその学部の範囲で付与します。

## 旧システムとの違い

- **発行台帳。** 旧システム(YUSTIC)は画面から直接印刷しており(`aca3/cti_*`)、台帳(`SRCERT`)は番号の採番のためだけに存在したため、誰が発行したのか、失効したのかが分かりませんでした。新システムは発行ごとに発行番号、検証コード、職員、用途、部数、PDF ファイル、チェックサムを記録し、失効した証明書もその行が残ります。
- **検証。** 旧システムにはありませんでした。すべての証明書に検証コードと QR コードが付き、公開ページで発行の事実、種別、発行日、マスクされた所持者(氏名の最初と最後の文字、学籍番号の先頭 4 文字)が表示されます。
- **テンプレート。** 旧システムは種別と言語ごとに別々の PDF スクリプトを持っていました。新システムでは、種別ごとに言語別のテンプレート(表題、本文、フッター、発行者名義)を画面で編集します。
- **制限。** 旧システムは履修登録拒否の一覧にかかわらず証明書を発行していました。新システムは証明書発行の制限がある学生には発行しません([第 20 章](20-registration.md))。
- 手数料は記録しません(旧システムは金額を記録するだけでした)。
- 学生によるオンライン申請はありません(移行計画 17.5)。証明書は職員が発行します。

## 種別とテンプレート

**証明書種別**: コード(発行番号に使用)、名称(言語ごと)、対象(すべての学籍 / 学生(卒業前) / 卒業生)、成績を含む、写真を含む、有効、順序。韓国の大学プロファイル(`setup_install --profile=korean-university`)では 3 つの種別が 4 言語(韓国語、英語、簡体字中国語、ラオ語)のテンプレートとともにあらかじめ登録されます。種別が 1 つでも存在すると何も追加しないため、編集した内容は保持されます。

| コード | 種別 | 対象 | 備考 |
|---|---|---|---|
| `ENR` | 在学証明書 | 学生(卒業前) | |
| `GRD` | 卒業証明書 | 卒業生 | 卒業日、学位記番号 |
| `TRN` | 成績証明書 | すべての学籍 | 学期ごとの確定成績の表、累積 GPA、修得単位 |

**テンプレート**(種別編集画面の下部にある **テンプレート** セクション): 言語ごとに 1 つ。言語、表題、本文(段落は空行で区切ります)、フッター、発行者名義。本文には波かっこで囲んだプレースホルダーを使います。

| プレースホルダー | 値 |
|---|---|
| `{institution}` | 機関名(その言語のもの) |
| `{student_name}`、`{student_number}` | 氏名(その言語の表記。なければラテン文字表記)、学籍番号 |
| `{program}`、`{org_unit}` | プログラム、組織単位 |
| `{admission_date}`、`{graduation_date}`、`{degree_number}` | 入学日、卒業日、学位記番号 |
| `{status}`、`{year_level}` | 学籍状態、学年 |
| `{birth_date}`、`{gender}`、`{nationality}` | 生年月日、性別、国籍 |
| `{issue_date}`、`{serial_number}`、`{purpose}`、`{copies}` | 発行日、発行番号、用途、部数 |

日付はその言語の形式で出力されます(例: `October 24, 2026`、`2026년 10월 24일`)。値がない場合(例: 卒業日)は空欄として出力されます。一覧にないプレースホルダーは書かれたまま残ります。本文の上には、個人情報の表(氏名、学籍番号、生年月日、性別、国籍、プログラム、入学日、さらに卒業生には卒業日、それ以外には学籍状態と学年)が自動的に追加されます。証明書全体(表の項目名、日付、学籍状態)はテンプレートの言語で出力されます。

## 設定

**設定 > 証明書設定**(`証明書種別・テンプレート・設定の管理`)

- **発行番号の形式**: 既定は `{TYPE}-{YYYY}-{SEQ:6}` → `ENR-2026-000001`。トークンは `{TYPE}`(種別コード)、`{YYYY}` と `{YY}`(発行年。機関のタイムゾーン基準)、`{SEQ:n}`(n 桁の連番)です。`{SEQ:n}` はちょうど 1 つ必要で、その後ろには通常の文字だけを置けます。連番は、異なる接頭部分ごとに別々に数えられます。`{TYPE}-{SEQ:6}` は年をまたいで種別ごとに、`{YYYY}{SEQ:5}` は種別をまたいで年ごとに数えます。同時に発行しても番号が重なることはありません(カウンターはデータベースで原子的に増やされます)。
- **検証の有効期間(日)**: 0 は無期限です。期間を過ぎると、検証ページは「期限切れ」と答えます。発行自体は台帳に残ります。
- **言語別の発行者名義**: 印影の上に印刷される名義(「Ninefruits 大学 学長」)。機関がサポートする言語ごとに 1 つの欄があります。テンプレートの発行者名義が優先されます。

## 発行

学籍画面の **証明書を発行**: 種別(有効なもの)、言語(機関の言語)、用途、部数(1〜20)。**証明書を発行** を押すと PDF を作成・保存して学籍画面に戻り、通知に発行番号と **PDF** リンクが表示されます。

次の場合は発行が拒否されます(画面に理由が表示されます)。

- 種別の対象が合わない(卒業生への在学証明書、在学生への卒業証明書)
- 種別が無効になっている
- その言語のテンプレートがない
- 学生に **証明書発行の制限** が有効になっている(制限措置、[第 20 章](20-registration.md))。先に解除してください。職員がその制限措置を閲覧できない場合でも発行は拒否されます。
- 学籍が閲覧範囲外である、または職員に発行権限がない
- PDF サービス(Gotenberg)が応答しない。何も発行されず、「PDF を作成できませんでした」と表示されます。後でもう一度発行してください。

発行は業務ログに記録されます(`certificate.issued`: 学籍番号、種別、言語、発行番号、部数。用途は理由として記録)。

## 発行済み証明書

**証明書 > 発行済み証明書**: 発行日、発行番号、種別と言語、学籍番号、氏名、用途、部数、状態、職員、そして **PDF** と **検証ページ** のリンク(新しいタブ)。種別と状態で絞り込み、発行番号、学籍番号、氏名で検索できます。閲覧範囲は学籍と同じです。

- **PDF**: 保存されたファイルを開きます。再作成はしないため、発行時のままです。
- **検証ページ**: 公開ページを開きます。
- **再作成**(行メニュー): テンプレートを修正した後などに、現在のデータから新しい PDF を作成し、ファイルを置き換えます。発行番号と検証コードはそのままで、チェックサムは変わります。監査イベントは `certificate.rerendered`。コマンド `certificate_render` と同じです。失効した証明書は再作成されません。
- **失効させる**(行メニュー): 理由が必要です。行とファイルは残り、状態は失効になり、検証ページは「失効」と答えます。監査イベントは `certificate.revoked`。失効した証明書は元に戻さず、新しく発行します。

台帳の行は画面で編集・削除できません(行を開くと、チェックサムを含む読み取り専用の詳細が表示されます)。

## 検証

- 証明書の下部には、検証 URL(`{機関のアドレス}/verify/{code}/`)と QR コードが印刷されます。コードはランダムな 20 文字の文字列(英大文字と数字)で、大文字・小文字は区別しません。アドレスは環境変数 `APP_URL` から取られます。
- このページはログインせずに開け、アドレス(IP)ごとに 1 分あたり 30 リクエストに制限されています(超えると HTTP 429)。検索エンジンにはインデックスしないよう指示します(`noindex`)。証明書が発行されたかどうか、種別、発行番号、発行日、マスクされた氏名と学籍番号が表示されます。失効、期限切れ、存在しないコードには、それぞれ異なる答えが返ります。ページのコード入力欄でもコードを確認できます(`/verify/?code=...`)。
- 提出された PDF ファイルそのものを確認するには、台帳の詳細にあるチェックサム(SHA-256)とファイルのハッシュを比較します。コマンド `uv run manage.py certificate_verify {code}` でもコードを確認できます([コマンド](../operations/commands.md))。
- 他のシステムは同じ確認を同じ内容の JSON で受け取れます: `GET /api/v1/certificates/verify/<検証コード>/`(ログイン不要、アドレスごとに 1 分あたり 30 リクエスト、[LMS 連携ガイド](../../../lms-integration-guide.md))。

## 学生ポータル

**証明書**(学生と卒業生のメニュー): 学生本人の学籍で発行された証明書(発行日、種別と言語、発行番号、状態)と PDF。失効した証明書も状態付きで一覧に表示されますが PDF リンクはなく、学生は失効した証明書の PDF をダウンロードできません(発行した職員は記録確認のために開けます)。他の学生のファイルは開けません(アプリケーションとデータベースで保証)。PDF のアドレスは `/certificates/{issue id}/download/` です。

## よくある質問

- **氏名の綴りが間違っている。** 人物の(その言語の)氏名表記を修正し、**再作成** します。証明書がすでに提出されている場合は、失効させて新しく発行します。
- **テンプレートを変更したが、発行済みの証明書はどうなるか。** 変わりません。必要に応じて **再作成** します(多数をまとめて行う場合はコマンド `certificate_render`)。
- **発行番号が飛んでいる。** 発行中にエラーが発生すると(例: PDF サービスの停止)、番号は消費されますが台帳の行は残りません。番号は一意であることが保証されますが、連続することは保証されません。
- **QR コードが `localhost` を指している。** 本番サーバーの `APP_URL` を機関のアドレスに設定し、該当する証明書を **再作成** します。

## このインストールの画面

画面と機能は元のシステム(Filament、Livewire)と同じですが、操作方法が少し異なります。

- **証明書を発行** はダイアログではなくフォームのページを開きます。元のシステムは発行後に新しいタブで PDF を開いていましたが、ここでは学籍画面に戻り、通知の **PDF** リンクで開きます。
- 台帳では、**PDF** と **検証ページ** は行の末尾のリンクで、**再作成**(確認ページ)と **失効させる**(理由入力ページ)は行メニューにあります。再作成は失効していない証明書にのみ使えます。
- テンプレートは種別編集画面の下部で編集します。同じ言語のテンプレートを 2 つ作ることはできません。`基準データの閲覧` だけを持つ場合、種別とテンプレートは読み取り専用です。
- 発行中に PDF サービスが失敗すると、何も発行されません(元のシステムでは PDF のない台帳の行が残ることがありました)。
- 発行権限は全体範囲で付与された場合にのみ有効です(元のシステムでは範囲付きの付与でも画面上は通り、その後データベースがエラーで行を拒否していました)。
- デモ(`setup_demo`)では、`certificate-officer@demo.test` で台帳を、`student@demo.test` でポータルの **証明書** を確認できます。
