# 22. 授業評価

メニュー: **授業評価 > 学期の授業評価**、**評価票**、**開講科目別回答**、**設定 > 授業評価**。学生はポータルの **授業評価** を、教員はポータルの **担当授業 > 授業評価結果** を使います。

| 権限 | できること |
|---|---|
| `授業評価の回答率と結果の閲覧` | 開講科目ごとの回答数と回答率、公開された結果。組織単位の範囲付きで割り当てた場合は、その組織が開講する開講科目のみ |
| `評価票・学期の授業評価・公開の管理` | 評価票と設問、学期の授業評価の設定、結果の公開、授業評価の設定 |

ロールの既定: 教務担当は両方、学科助手は閲覧(学科の範囲)を持ちます。

## 旧システムとの違い

- **匿名性。** 旧システム(YUSTIC)はすべての回答に学籍番号を保存しており、教員のアカウントで元のテーブルを読むことができました。新システムでは、**誰が評価したか(完了記録)** と **何を回答したか(回答)** を分けて保存します。回答には学生、連番、時刻のいずれも含まれません。監査記録には実行者が残るため、回答はデータ変更履歴(監査)にも書き込まれません。
- **結果を表示する基準。** 旧システムの教員画面には最低回答数の基準がなく、教員は他の開講科目の結果も見ることができました。新システムでは、学期の結果が **公開** された後、**最低回答数と最低回答率を満たした開講科目に限り** 結果とコメントを表示します。教員は自分の開講科目だけを見られます。
- **成績閲覧の制限。** 旧システムはメニューのリンクを隠すだけで、評価期間が終わっても制限が解除されませんでした。新システムはサーバーで制限し、期間が終了すると制限を解除します。
- **設問の管理。** 旧システムは毎学期 SQL で設問を登録していました。新システムでは評価票と設問を画面で管理します。
- すべて 1 またはすべて 5 の回答を拒否する規則は設定になりました(既定はオフ)。

## 学期の準備

1. **評価票**: **評価票** で評価票を選びます。韓国の大学プロファイルでは `STANDARD` 評価票があらかじめ登録されます(授業準備、授業方法、授業内容、成績評価、施設・設備について各 3 問を 5 段階尺度で、さらに自由記述 1 問)。
2. **学期を設定**: 学期、評価票、最低回答数、最低回答率(%)。既定値は **設定 > 授業評価** から取られます(5 件、25%)。結果を表示するには両方の基準を満たす必要があります。回答数は匿名性を守るためのものです(回答が少ないと学生が推測できてしまいます)。回答率は結果の代表性を確保するためのものです。
3. **評価期間**: 学期編集画面の **業務期間** に、授業期間ごとの **授業評価** の期間を追加します([第 10 章](10-terms.md))。対象条件で学年ごとの期間も設定できます。
4. 期間中は、`uv run manage.py evaluation_remind {term}` で未完了の学生に催促メールを送ります(`--dry-run` は人数を数えるだけです)。回答率は **開講科目別回答** で確認します。
5. 成績処理が終わったら **結果を公開** します(または `uv run manage.py evaluation_publish_results {term}`)。コマンドの説明は [コマンド](../operations/commands.md) にあります。

## 評価票と設問

| 項目 | 説明 |
|---|---|
| コード、名称、説明 | 説明は学生の評価画面の上部に表示されます |
| 尺度の段階数 | 2〜10、通常は 5 |
| 1 のラベル、最高段階のラベル | 例: まったくそう思わない、とてもそう思う |

**設問** タブ: 領域(同じ領域の設問はまとめて表示されます)、設問、形式(尺度、自由記述)、必須、**逆転項目**(否定的な表現の設問。平均の計算では回答が反転されます。例: 「授業の進度についていくのが難しかった」への 5 は 1 として数えます)、順序。

回答が 1 件でもある評価票は、設問や尺度を変更できなくなります(結果が、尋ねていない設問への回答にならないようにするためです)。変更するには **評価票をコピー** で新しい評価票を作り、次の学期から使います。

## 評価の対象

- 学期の授業評価が設定された学期に、履修登録または修了した科目。履修中止と削除した科目は除外されます。
- **授業評価** の設定がオフの科目は除外されます(実習、インターンシップなど。[第 17 章](17-courses-and-curriculum.md))。
- 科目を評価できるのは、その授業期間の授業評価の期間が学生に対して開いている間だけです。

## 学生の画面

ポータルの **授業評価**: 評価対象の科目の一覧で **評価する** をクリックし、設問に回答して提出します。必須の設問にはすべて回答する必要があり、提出後は変更できません。各科目の評価は 1 回だけです。

**成績閲覧の制限**(設定。既定はオン): 期間中、その学期に未評価の科目がある学生には、ポータルの成績画面と成績表でその学期の成績が表示されず、案内が表示されます。評価を終えるか期間が終了すると成績が表示されます。他の学期の成績は引き続き表示されます。

## 結果

- 教員: ポータルの **担当授業** にある **授業評価結果**。学期の結果が公開された後にのみ開けます。
- 職員: **授業評価 > 開講科目別回答** に開講科目ごとの回答数と回答率が表示され、**結果** で結果画面が開きます。詳細な結果は職員にも公開後にのみ表示されます(期間中は、結果の変化と完了時刻を照らし合わせると学生を特定できるおそれがあるためです)。
- 結果画面: 回答数/対象者数(回答率)、設問ごとの平均と段階ごとの回答数(逆転項目は反転)、全体の平均、コメント(ランダムな順序)。
- 回答数が最低回答数に満たないか、回答率が最低回答率を下回る開講科目では、回答数だけが表示され、結果とコメントは表示されません。

## 設定

**設定 > 授業評価**: 授業評価が完了するまで学期の成績を非表示にする(既定はオン)、すべての設問に同じ回答をした場合は受け付けない(既定はオフ)、新しい学期の授業評価の最低回答数(既定 5)と最低回答率(既定 25%。旧システムの教務課画面の基準)。

## このインストールでの画面

画面と機能は元のシステム(Filament、Livewire)と同じですが、操作方法が少し異なります。

- **学期の授業評価** 一覧の上にある **学期を設定** で入力画面(学期、評価票、最低回答数、最低回答率)が開きます。基準を空欄にすると、新しい学期では設定の既定値が使われ、既存の学期では現在の値が維持されます。行メニューの **変更** で同じ画面が開きます(学期は変更できません)。回答がある学期は評価票を変更できません。行メニューの **結果を公開** で確認画面が開きます。行メニューは公開済みの学期にも表示され、その場合は結果がすでに公開されている旨のメッセージが表示されます。
- **評価票** の編集画面では、**設問** タブで設問を追加、変更、削除します。回答がある評価票は設問が読み取り専用で表示され、尺度の段階数の欄がロックされます。上部の **評価票をコピー** で新しいコードの入力画面が開き、コピー後は新しい評価票の編集画面が開きます。
- **開講科目別回答** のフィルター: 学期(既定: 授業評価がある最新の学期。すべての学期は **全体**)、開講単位。検索は科目コードの前方一致です。行メニューの **結果** で、ポータルの結果画面(`/portal/sections/{section id}/evaluation/`)が同じウィンドウで開きます。
- ポータルの **担当授業** の表の **授業評価結果** 列: 学期の結果が公開されると **結果** リンク、それ以外は **未公開** と表示されます。
- 学生ポータルの **授業評価**: **提出** はブラウザでもう一度確認します(JavaScript が無効な場合はそのまま提出されます)。必須の設問が未回答の場合は、入力した回答がエラーとともに再表示されます。成績画面の案内は **授業評価** にリンクします。
- 回答の保存: 回答 ID はランダムな UUID です。回答、回答内容、完了記録は、学生の履修、期間、重複を確認した後、システムコンテキストで 1 つのトランザクションとして書き込まれ、データ変更履歴(監査)には書き込まれません。評価票がロックされているか(回答があるか)は、画面を開いた人の閲覧範囲に関係なく判定されます。
