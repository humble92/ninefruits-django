# 15. ログイン方法

メニュー: **設定 > ログイン方法**(`ログイン方法と SSO の管理` 権限)

## ログイン ID

アカウントのメールアドレスが既定のログイン ID です。学籍番号ログインを有効にすると、ログイン画面の入力欄は「メールアドレスまたは学籍番号」になります。

| 学籍番号でのログイン | 動作 |
|---|---|
| 許可しない | メールアドレスのみ |
| 在籍中の学生のみ | 在学・休学中の学籍の学籍番号でログインできる |
| 在籍中の学生と卒業生 | 終了した学籍(卒業、退学など)の学籍番号でもログインできる |

複数の学籍を持つ人物は、どの学籍番号を使っても同じアカウントにログインします。

## アカウントロック

| 設定 | 説明 |
|---|---|
| ロックまでの失敗回数 | 誤ったパスワードがこの回数連続で入力されるとアカウントがロックされます。0 にするとロックは無効になります |
| ロック時間(分) | この時間が経過するとロックは自動的に解除されます |

メールアドレスによる試行と学籍番号による試行は、同じアカウントの失敗として数えられます。ロックされたアカウントには誤ったパスワードと同じメッセージが表示されるため、アカウントが存在するかどうかは分かりません。ロックはセキュリティイベント(**ログインロック**)として記録されます。

ロックを早めに解除するには、**ユーザー** の詳細画面で **ログインロックを解除** を使います(理由の入力が必要、`ユーザーの編集` 権限)。管理画面が使えないときは、IT 運用者が `uv run manage.py security_unlock_user` を使います。

## 学内アカウントログイン(SSO)

学校の OpenID Connect ログイン(例: Microsoft Entra ID、Google Workspace、Keycloak)を登録すると、ログイン画面に「… でログイン」ボタンが追加されます。

| 項目 | 説明 |
|---|---|
| キー | 小文字の識別子。例: `school`。変更すると既存の連携が切れます |
| ボタンのラベル | ログイン画面に表示される名前 |
| Issuer URL | プロバイダーの issuer。このアドレスの下で `/.well-known/openid-configuration` が取得できる必要があります |
| クライアント ID、クライアントシークレット | プロバイダーにアプリケーションを登録したときに受け取る値。シークレットは暗号化して保存されます |
| スコープ | 既定は `openid email profile` |
| 二要素認証として扱う | 学内アカウントログイン自体が二要素認証を必須としている場合にのみ有効にします。有効にすると、このログインではここで改めて二要素認証を求めません |
| プロバイダーに登録するリダイレクト URI | 画面に表示されるアドレス(`https://<server>/auth/sso/<key>/callback/`)を、そのままプロバイダーのアプリケーション設定に登録します |

### アカウント連携

| 方式 | 動作 |
|---|---|
| ユーザーが自分でアカウントを連携する | ユーザーがパスワードでログインし、ポータルの **セキュリティ > 学内アカウントログイン** で **連携** を押します(パスワードの再確認が必要) |
| 確認済みの学内メールで自動連携する | プロバイダーが確認したメールアドレスが学籍の学内メールアドレスと一致する場合、初回ログイン時にアカウントが自動的に連携されます |

- 連携されていない学内アカウントでログインすると、パスワードでログインしてから連携するよう案内が表示されます。学内アカウントだけで新しいアカウントが作成されることはありません。
- 連携と連携解除はセキュリティログに記録されます。

### パスワードログインの許可

**学内アカウント連携ユーザーにパスワードを許可** をオフにすると、連携済みのユーザーは学内アカウントログインしか使えなくなります。学内アカウントは卒業後に削除されることが多いため、この設定はオンのままにし、卒業予定の学生には個人のメールアドレスとパスワードを準備してもらうことをお勧めします。卒業生は、アカウントのログイン用メールアドレス(個人メール)とパスワードで引き続きログインします。
