# 24. 試験

メニュー: **試験 > 試験実施回**、**試験結果**、**結果訂正**、**試験種別**。学生はポータルの **試験** で申込を行い、結果を確認します。

| 権限 | できること |
|---|---|
| `学生の申込登録、結果の入力・公開、外部試験の結果の記録` | 学生の申込登録・取消・欠席処理、結果の入力、CSV 取り込み、結果の公開、訂正の申請、外部試験の結果の記録・削除、結果台帳の閲覧(学籍閲覧の範囲内) |
| `試験種別・領域・実施回の管理` | 種別、領域、実施回の作成と編集、実施回の合格点の変更、訂正申請の承認と却下 |

ロールの既定: 学籍担当と教務担当が両方を持ちます。種別と実施回の画面には `基準データの閲覧` も必要です(ロールの既定に含まれます)。結果は学籍閲覧の範囲内でのみ表示されるため、`学籍の閲覧`(または管理)も付与してください。

## 旧システムとの違い

- **種別ごとの固定列がない。** 旧システム(YUSTIC)は、`CET` に文法・作文・聴解・読解の 4 列を固定で持ち、総合試験(`SSCORE_ADD`)では科目ごとに P/N の 1 文字、コンピューター試験(`COMEXAM`)ではさらに別のテーブルを使っていました。新システムでは **試験種別** に領域と評価方法を定義し、すべての試験を同じ実施回・申込・結果の構造で扱います。
- **合否判定。** 旧システムでは 4 領域の合計が合格ラインに達すれば合格で、領域ごとの最低点はありませんでした。新システムは種別(または実施回)の合格点と **領域ごとの最低基準点** で判定し、判定結果を結果に保存します。合否型の種別は職員が判定します。
- **申込期間と定員。** 旧システムにはありませんでした。実施回には申込の開始・締切日時と定員があります。
- **結果の公開。** 旧システムでは入力した時点で学生に結果が見え、しかも最新の実施回だけでした。新システムでは実施回の **結果を公開** の後に学生が結果を確認でき、すべての実施回の結果が保存されます。結果がある実施回は削除できません。
- **外部試験の結果。** 旧システムには TOEFL や TOPIK などの外部試験を記録する場所がありませんでした(卒業判定表の HSK 欄は中身のないラベルでした)。外部試験の結果は証拠書類のファイルとともに記録します。
- **卒業要件との連携。** 旧システムでは担当者が卒業判定表を読んで判断していました。要件の種類 **試験合格** によって、これが教育課程に組み込まれます([第 17 章](17-courses-and-curriculum.md))。

## 試験種別と試験領域

**試験種別**: コード、名称(言語ごと)、区分(語学、総合、論文、外部試験)、評価方法、満点、合格点、外部試験の結果、有効、順序。

| 評価方法 | 入力 | 判定 |
|---|---|---|
| 点数 | 領域ごとの点数(領域がなければ合計) | 合計 ≥ 合格点 かつ すべての領域 ≥ その最低基準点。合格点がなければ職員が選択 |
| 合否 | 合格かどうか | 職員が選択 |

**試験領域**(種別編集画面の **試験領域** タブ): コード(CSV の列名。英字、数字、`-`、`_`)、名称、満点、最低基準点(任意)、順序。領域がある場合、合計は各領域の点数の和になります。領域の最低基準点と同じ点数であればその領域は合格で、1 点でも下回ると合計にかかわらず不合格になります。

韓国の大学プロファイル(`setup_install --profile=korean-university`)で登録される種別:

| コード | 種別 | 判定 | 備考 |
|---|---|---|---|
| `ENG_COMP` | 英語総合試験 | 点数、60 点で合格 | 聴解、読解、作文、文法、各 25 点 |
| `COMP_EXAM` | コンピューター総合試験 | 合否 | |
| `THESIS` | 卒業論文 | 合否 | |
| `TOPIK` | 韓国語能力試験 | 合否、外部 | 級と証明書番号を記録 |

プロファイルを再度実行しても、管理者が変更した値は保持され、削除した領域が復活することもありません。

## 実施回

**試験実施回**: 種別、実施日(種別ごとに一意)、会場、定員、申込開始と申込締切、合格点(空欄: 種別の値)。実施回画面の **申込者** タブに申込の一覧が表示されます。

- **学生を申込登録**(学籍番号を入力): 職員は申込期間にかかわらず、試験日まで学生を申込登録できます。定員は適用されます。実施日を過ぎた実施回には誰も申込登録できません。結果は申込済みの学生にのみ入力でき、未申込の学生の CSV の行はエラーとして報告され、スキップされます。
- 学生は申込期間中にポータルで申込と取消を行います。申込できるのは在学・休学中の学生だけです。取消後に再度申込すると、同じ申込が再び有効になります。
- **結果を入力**: 領域ごとの点数(または合計)、必要に応じて合格かどうか、備考。公開前は、再度入力すると上書きされます(監査イベント `assessment.result_recorded`)。**公開後はロックされます**(後述の訂正申請を参照)。
- **欠席**: 申込したが受験しなかった場合。結果を入力すると、申込は申込済みに戻ります。
- **申込を取消**: 結果がある申込は取り消せません。理由は任意です。
- **結果を公開**: 以後、学生はこの実施回の結果を確認できます。公開後は結果を直接編集・削除できず、**訂正申請** によって変更します(2026-10-23 の決定)。コマンド `assessment_publish_results` と同じです。
- 実施回の **合格点**(種別の値を上書き): 試験が難しかったため会議で合格ラインを下げる場合などに使います。**公開前** に限り変更でき、保存すると、その実施回にすでに入力されているすべての結果が、保存された点数から **再判定** されます(合計は新しい基準で、領域の最低基準点は種別の設定どおり)。**合格点を変更する理由** を入力すると、監査イベント `assessment.pass_score_changed` に、変更前後の基準と判定が変わった学生の学籍番号が記録されます。保存後、画面に再判定された結果の件数が表示されます。**公開後** は読み取り専用です(訂正申請のみ)。領域ごとの最低基準点は実施回では変更できません(種別の設定)。
- **結果を取り込み(CSV)**: 形式は以下のとおりです。未申込の学生の行はエラーとしてスキップされます。コマンド `assessment_import_results` と同じです。

CSV の形式(ヘッダー行あり、UTF-8、最大 5 MB):

| 列 | 内容 |
|---|---|
| `student_number` | 学籍番号(必須) |
| 領域コード(`LISTENING` など) | 領域の点数。大文字と小文字は区別しません |
| `total` | 領域のない種別の合計 |
| `passed` | `Y`/`N`。合否型の種別、または合格点のない種別では必須 |
| `absent` | `Y` で欠席として処理 |
| `note` | 備考 |

エラーの行はスキップされ、結果メッセージ(画面。最初の 10 件)または出力(コマンド)に行番号付きで報告されます。エラーの文言は、コマンドの出力と同じく英語です。

## 結果訂正

公開済みの実施回の結果を変更する手続きです。成績訂正と同じように動作します。

1. 実施回の **申込者** タブで **訂正を申請**: 新しい点数(または合格かどうか)と理由。1 つの結果につき承認待ちの申請は 1 件までです。監査イベント `assessment.correction_requested`。
2. **試験 > 結果訂正** で、`試験種別・領域・実施回の管理` 権限の保有者が **承認**(メモは任意)または **却下**(メモが必要)をクリックします。**自分の申請は誰も判断できません。**
3. 承認されると、結果はすぐに新しい値に変わり(新しい点数から改めて判定されます)、学生にも表示されます。監査イベント `assessment.correction_approved`、`assessment.result_corrected`。申請者は判断が下るまで申請を取り消せます。

一覧には既定で承認待ちの申請が表示され(すべての申請は状態フィルターの **全体**)、現在の値と訂正後の値が並べて表示されます。メニューには承認待ちの申請の件数が表示されます。

## 結果台帳

**試験結果**: すべての結果(実施回と外部試験)。種別、出所、合格で絞り込み、学籍番号または氏名で検索できます。閲覧範囲は学籍と同じです。

- **外部試験の結果を記録**(一覧の上): 学籍番号、種別(外部試験の結果を受け付ける種別のみ)、受験日(未来の日付は不可)、合計、級・レベル、合格かどうか、証明書番号、証拠書類のファイル(PDF、JPG、PNG、5 MB)、備考。監査イベント `assessment.external_recorded`。
- **証拠書類**: ファイルを開きます。学生は自分のものを開けます。
- **削除**(行): 理由が必要で、監査イベントは `assessment.result_removed`。誤って入力した外部試験の結果や、公開前の結果を削除して記録し直すためのものです。証拠書類のファイルも削除されます。公開済みの実施回の結果は削除できません(訂正申請)。

## 卒業要件

**教育課程・開講科目 > 卒業要件** で、要件の種類 **試験合格** を選び、**試験種別** を選択します。学生は、その種別の合格結果(実施回または外部試験)が 1 件以上あれば要件を満たします。ポータルの **試験** ページの上部には、学生の教育課程で求められる種別と、合格しているかどうかが表示されます。卒業判定([第 26 章](26-graduation.md))はこの要件を読み取ります。要件で使われている種別は削除できません(代わりに無効にします)。

## 学生ポータル

**試験**: 教育課程の要件と合格状況、申込受付中の実施回(申込、取消)、自分の申込、自分の結果(公開済みの実施回と外部試験の結果、領域ごとの点数、証拠書類)。

## このインストールの画面

画面と機能は元のシステム(Filament、Livewire)と同じですが、操作方法が少し異なります。

- **試験実施回** 一覧の行メニュー: **結果を公開**(確認ページ)、**結果を取り込み(CSV)**(ファイルのページ)。実施回画面の上部のボタン: **学生を申込登録**(試験日まで)、**結果を取り込み(CSV)**、**結果を公開**。フィルター: 種別、結果の公開。
- 実施回画面の **申込者** タブは、状態(全体、申込済み、取消、欠席)をクリックして絞り込みます。行のリンク **結果を入力**、**訂正を申請**、**欠席**、**申込を取消** は入力ページを開きます。結果のページには種別の領域ごとに点数の欄があり、点数で判定する種別ではその規則が説明されます。
- **試験結果** 一覧の上に **外部試験の結果を記録**、行メニューに **削除** があります。証拠書類の列のリンクは新しいウィンドウでファイルを開きます。
- **結果訂正** の行メニュー: **承認**、**却下**、**申請を取消**(自分の申請)。
- 証拠書類のアドレス: `/assessment-results/{結果 ID}/evidence/`(権限を確認してからダウンロード)。ポータルのアドレス: `/portal/assessments/`。
- コマンド: `uv run manage.py assessment_import_results {kind code} {date} {CSV} --actor=... [--dry-run]`、`uv run manage.py assessment_publish_results {kind code} {date} --actor=...`([運用コマンド](../operations/commands.md))。

## よくある質問

- **申込期間外に学生を申込登録する必要がある。** 職員が実施回画面の **学生を申込登録** で申込登録します。
- **この実施回だけ合格点を変えたい。** 公開前に、実施回の合格点を理由とともに入力して保存します。すでに入力された結果は、すぐに新しい基準で判定されます。
- **点数を誤って入力した。** 公開前であれば、もう一度 **結果を入力** して上書きします。公開後は **訂正申請** を出し、別の職員に承認してもらいます。
- **欠席者の統計。** **申込者** タブを状態 **欠席** で絞り込みます。
