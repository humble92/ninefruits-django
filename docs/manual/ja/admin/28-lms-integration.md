# 28. LMS 連携

メニュー: 管理画面の **LMS 連携 > LMS プラットフォーム**、**コース連携**、**同期ログ**(`LMS プラットフォーム・連携・同期の管理` 権限。既定: システム管理者、教務担当)。教員はポータルの **担当授業** と開講科目の詳細にある LMS へのリンクと、成績入力画面の **LMS から得点を読み込む** を使います。読み込みは成績入力と同じ条件に従います(割り当てられた担当教員が、成績入力期間内に行います)。

開発者向けの詳細(コネクターの作成、API)は [LMS 連携ガイド](../../../lms-integration-guide.md) にあります。

## 何をどこへ送るか

| SIS → LMS | タイミング |
|---|---|
| 開講科目(コースの作成)+ 担当教員 | 開講科目を **公開** したとき、および `lms_sync` の実行時 |
| 確定した履修 → 受講登録 | 履修登録、キャンセル待ちの繰り上げ、職員による履修登録の時点で即時 |
| 削除・履修中止 → 受講登録の解除 | 即時 |
| 全体の照合 | 毎日 02:30(`lms_reconcile`、スケジュールタスク `lms.reconcile`) |

| LMS → SIS | タイミング |
|---|---|
| 最終得点(下書き) | 教員が成績入力画面で **LMS から得点を読み込む** をクリックしたとき。保存と提出は教員が行います |

確定した成績は LMS に送りません。授業資料、課題、小テストは LMS で扱います。

## プラットフォーム

**LMS プラットフォーム**: コード、名称(言語ごと)、ドライバー、ベース URL、認証情報、有効、履修者名簿を同期、最終得点を取得。

- ドライバー **なし(記録のみ)**: 何も呼び出さず、送信される内容を記録します。連携前に流れを確認したり、デモンストレーションしたりするときに使います。デモデータの `DEMO` プラットフォームはこれを使っています。
- `Moodle`、`Open edX`: コネクターはまだありません(「未実装」と表示されます)。選択した場合、同期は失敗として記録されます。
- **有効** をオンにすると、それ以降、開講科目の公開と履修の変更が即時に送られるようになり、そのプラットフォームが毎晩の照合の対象になります。
- **認証情報** は 1 行に 1 つずつ `key=value` の形式で入力します(例: `token=...`)。暗号化して保存され、画面に再表示されることはありません。編集時に空欄のままにすると、保存済みの値が保持されます。データ変更履歴にも値は残りません。

## コース連携と同期ログ

- **コース連携**: どの開講科目がどのプラットフォームのコース(ID、URL)に連携されているか、状態(保留中/連携済み/失敗)、最終同期、エラー。プラットフォーム、状態、学期で絞り込み、科目コードで検索できます。行の操作 **再同期**(確認ページあり)で開講科目、担当教員、履修者名簿を改めて送ります。
- **同期ログ**: 手順(コース、メンバー追加、メンバー削除、得点取得、点数の送信、照合)ごとの結果とメッセージ。失敗の原因はここで確認します。行を開くと、開始・終了時刻とペイロードが表示されます。
- コマンド: `uv run manage.py lms_sync {platform} --term={term}`(全体の送信、`--dry-run`)、`uv run manage.py lms_reconcile`(照合)。[運用コマンド](../operations/commands.md#lms-連携フェーズ-12)を参照してください。

## ポータル

- プラットフォームのコースへのリンクは、学生と教員の科目詳細、および教員の **担当授業** の一覧(**LMS** 列。連携済みの開講科目のみ)に表示されます。
- 成績入力: プラットフォームで **最終得点を取得** がオンになっていて、開講科目が連携済みであれば、**LMS から得点を読み込む** ボタンが表示されます。素点の列を埋めるだけで、保存はしません。

## 連携 API

結果を後から報告するプラットフォームや、自ら点数を送信するプラットフォームのための API(`/api/v1/lms/platforms/...`)があります。`LMS プラットフォーム・連携・同期の管理` 権限だけを持つ連携用のアカウントを別に作成し、運用担当者が `uv run manage.py api_issue_token {email} --days=365` でトークンを発行して、プラットフォームの管理者に渡します。トークンは発行時に一度だけ表示されます。`api_revoke_tokens` で取り消します。発行と取り消しは監査ログに記録されます。

- 点数の送信(`.../scores/`)で受け取った点数も保存はされません。教員が **LMS から得点を読み込む** をクリックすると、最後に受け取った点数が下書きとしてフォームに入ります。
- 同期結果(`.../sync-results/`)は **同期ログ** に保存され、コースの結果は **コース連携** の状態を変更します。

## よくある質問

- **LMS に学生がいない。** 同期されるには、学生にアカウント(ユーザー)が必要です。アカウントがない場合は招待してください([第 14 章](14-merge-and-invitations.md))。次の照合で追加されます。
- **同期が失敗したままになる。** 同期ログのメッセージを確認してください。認証情報の期限切れがよくある原因です。プラットフォームの編集画面で値を変更し、**再同期** します。
- **プラットフォームを切り替えた。** 新しいプラットフォームを作成し、古いプラットフォームの有効をオフにします。連携はプラットフォームごとに別々に作成されます。

## このインストールでの画面

画面と機能は元のシステム(Filament、Livewire)と同じですが、一部の操作が異なります。

- 認証情報は、元のシステムのキーと値の表の代わりに、テキスト欄に `key=value` の行で入力します。形式が正しくない行は行番号とともに拒否されます。
- プラットフォームの **オプション**(プラットフォームごとのロール ID など)には画面上の欄がありません。コネクターが必要とする場合は開発者が設定します([連携ガイド](../../../lms-integration-guide.md) 第 3 節)。
- **再同期** は確認ページを経由します。コネクターのエラー(コネクターのないドライバー、プラットフォームの障害)は「同期に失敗しました: ...」というメッセージで表示され、コース連携は失敗になります(元のシステムはエラーページを表示していました)。
- 同期ログは読み取り専用です。行を開くとペイロードが JSON で表示されます。
- 成績入力画面の **LMS から得点を読み込む** は、表の下のボタン行にあります。すでに入力した内容は保持したまま、点数の欄だけを変更してページを再表示します。**下書き保存** するまで何も保存されません。
- 連携 API とトークンのコマンド(`api_issue_token`、`api_revoke_tokens`)は、このインストールで新しく追加されたものです(元のシステムには API がありませんでした)。
