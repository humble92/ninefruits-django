# 4. 审计查询

**审计** 菜单下的三个界面只能查看，任何人都不能修改或删除（需要 `查看审计记录`、`查看安全事件` 权限）。列表中没有添加、修改、删除按钮，打开某一行会以只读方式显示详情。

| 界面 | 查看什么 | 例 |
|---|---|---|
| 业务审计记录 | 谁、做了什么、**为什么**。原因和详情 | 角色分配（原因：学期中代班）、权限变更（新增/移除列表）、设置变更（变更前/后）、命令执行 |
| 数据变更记录 | 表中行的变更前/后值。未经程序的直接变更也会记录 | `users` UPDATE，变更字段 `locale` |
| 安全事件 | 登录、登录失败、双重身份验证、权限相关事件、密码和邮箱更改、审计记录清理（`audit_prune`） | 登录失败（登录名、IP） |

## 阅读方法

- **用户** 列：在界面上执行的操作显示为用户姓名或 `user:编号`，自动作业（Celery）显示为 `system:job:...`，命令显示为 `system:command:...`。
- 密码、双重身份验证密钥等会以 `[redacted]` 遮盖。
- **请求 ID** 相同的记录是在同一次页面请求中一起产生的。在多个界面之间用同一请求 ID 查找，可以看到一次操作的全部记录。命令执行使用以 `cmd-` 开头的执行 ID。

## 常用查询

在列表右上角的 **筛选** 中选择条件，在搜索框中输入值。

| 想知道的事 | 方法 |
|---|---|
| 某用户的权限何时变更 | 在业务审计记录中按日志 `security`、事件 `role.assigned`、`role.assignment_revoked` 查找 |
| 登录失败集中的账户 | 在安全事件中按事件 `登录失败` 筛选，查看登录名列 |
| 谁更改了安全策略 | 业务审计记录事件 `settings.updated` |
| 某一行是如何变更的 | 在数据变更记录中按表筛选并搜索记录 ID |
