# 15. 登录方式设置

菜单：**设置 > 登录方式**（`管理登录方式和 SSO` 权限）

## 登录名

登录账户的电子邮箱是默认登录名。开启学号登录后，登录页面的输入框会变为"邮箱或学号"。

| 使用学号登录 | 行为 |
|---|---|
| 不允许 | 仅邮箱 |
| 仅在读学生 | 可用在读、休学学籍的学号登录 |
| 在读学生和毕业生 | 毕业、退学等已终止学籍的学号也可以 |

有多个学籍的人无论用哪个学号登录都是同一账户。

## 账户锁定

| 设置 | 说明 |
|---|---|
| 锁定前失败次数 | 连续输错密码达到此次数时锁定。0 表示不锁定 |
| 锁定时长（分钟） | 时间过后自动解锁 |

无论用邮箱还是学号尝试，都计为同一账户的失败。被锁定的账户会收到与密码错误时相同的提示，因此无法得知账户是否存在。锁定会记录在安全事件（**登录已锁定**）中。

要提前解锁，使用 **用户** 详情中的 **解除登录锁定**（必须填写原因，`编辑用户` 权限）。无法使用管理界面时，由 IT 运维人员使用 `uv run manage.py security_unlock_user`。

## 学校统一登录（SSO）

登记学校的 OpenID Connect 登录（例：Microsoft Entra ID、Google Workspace、Keycloak）后，登录页面会出现"使用 OO 登录"按钮。

| 项目 | 说明 |
|---|---|
| 键 | 小写英文标识符。例：`school`。更改后现有关联会断开 |
| 按钮名称 | 登录页面上显示的名称 |
| 签发者（Issuer）URL | 提供方的 issuer。`/.well-known/openid-configuration` 必须位于此地址之下 |
| 客户端 ID、密钥 | 在提供方注册应用后获得的值。密钥加密保存 |
| 范围（scope） | 默认 `openid email profile` |
| 视为双重验证 | 仅当学校登录本身要求双重验证时开启。开启后，此登录方式不再要求本系统的双重身份验证 |
| 需在提供方登记的重定向 URI | 将界面上显示的地址（`https://<服务器地址>/auth/sso/<键>/callback/`）原样登记到提供方的应用设置中 |

### 账户关联方式

| 方式 | 行为 |
|---|---|
| 用户自行关联 | 用户用密码登录后，在门户 **安全 > 学校统一登录** 中点击 **关联**（需要再次确认密码） |
| 按已验证的学校邮箱自动关联 | 提供方验证过的邮箱与学籍的学校邮箱一致时，首次登录即自动关联 |

- 用未关联的学校账户登录时，会提示先用密码登录后再关联。不会仅凭学校账户创建新账户。
- 关联和取消关联都会记录在安全日志中。

### 允许密码登录

关闭 **允许已关联学校账户的用户使用密码登录** 后，已关联的用户只能使用学校登录。考虑到毕业后学校账户会被注销的情况，建议保持开启，并让即将毕业的学生准备好个人邮箱和密码。毕业生继续用账户的登录邮箱（个人邮箱）和密码登录。
