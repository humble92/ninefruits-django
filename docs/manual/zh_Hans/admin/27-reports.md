# 27. 报表与 reporting 视图

菜单：**报表 > 报表**（`查看和下载标准报表`权限）。角色默认值：学籍管理员、教务管理员、院系助理（范围内）。

## 标准报表

选择报表并输入条件后，屏幕上最多显示 500 行，通过**下载 CSV** 获取全部（UTF-8 BOM，可在 Excel 中直接打开）。下载记入审计 `reports.exported` 和安全日志 `data.exported`（报表、条件、行数）。以 `=`、`+`、`-`、`@`（以及制表符、换行）开头的值会在前面加上单引号（`'`）导出，以免在 Excel 中被当作公式执行。

| 报表 | 条件 | 内容 |
|---|---|---|
| 学生名单 | 组织单位（含下级）、状态、年级 | 学号、姓名、专业、院系、年级、状态、入学日期、毕业日期、学位编号 |
| 按院系、专业、年级、状态的人数 | 组织单位、状态 | 人数 |
| 学期成绩汇总 | 学期、学业状态 | 学期和累计学分与绩点、学业警告次数、成绩优秀名次（[第 21 章](21-grades.md)） |
| 预计毕业生 | 是否满足 | 按学生、专业的最新毕业资格审核（[第 26 章](26-graduation.md)） |
| 学籍异动 | 学期、期间 | 异动类型、异动前后状态、生效日期、处理状态 |
| 各教学班选课人数 | 学期、组织单位 | 班级、任课教师、容量、已选、候补 |
| 学期未选课学生 | 学期、组织单位 | 该学期没有选课的在读学生 |

可见范围与查看者的权限范围相同（学籍查看范围等）。旧系统（YUSTIC）的手续费、学费报表（欠缴学费等）不在范围内，因此没有。

## reporting 视图

报表读取数据库 `reporting` 模式中的视图。BI 工具或 SQL 用户通过只读角色 `app_reporting` 查询相同的视图。

| 视图 | 内容 |
|---|---|
| `reporting.students` | 学籍 + 人员姓名 + 专业、组织单位名称 |
| `reporting.headcount` | 按组织单位、专业、年级、状态的人数 |
| `reporting.term_records` | 按学期的成绩汇总 |
| `reporting.course_grades` | 按课程的成绩（是否确定、等级、合格、重修） |
| `reporting.section_enrollments` | 各班级的选课、候补人数，任课教师 |
| `reporting.section_meetings` | 上课时间和教室 |
| `reporting.status_changes` | 学籍异动 |
| `reporting.degree_audits` | 按学生、修读类型的最新毕业资格审核 |

- 翻译列（`program_name` 等）遵循会话区域设置：`SET app.locale = 'ko';`。也有原始 jsonb 列（`program_name_i18n` 等）。
- 视图为 `security_invoker`，查询者的行级安全照常适用。用学生账户读取时只显示自己的行。
- 视图定义位于 `db/sql/views/reporting.sql`（与原版 `database/sql/views/reporting.sql` 相同），修改后在 `core` 迁移中重新应用。应用程序通过非托管模型（`ninefruits.reporting.models`，如 `ReportStudent`）读取。

旧系统的 `AV_*` 视图（90 余个）未被使用，因此没有迁移。

## 本安装的界面

- **报表 > 报表**（`/admin/reports/`）：选择报表后点击**查看**，会显示该报表的条件（原版在选择后立即切换）。填写条件后再次点击**查看**。带学期条件的报表在选择学期之前没有数据行。
- CSV 地址为 `/reports/{报表}.csv?条件=值`（例如 `/reports/students.csv?status=enrolled`）。只接受规定的报表名称和条件名称，列和排序由报表定义固定。
- CSV 中的时间（审核时间、决定时间）与原版一样，写为 PostgreSQL 格式的 UTC（`2026-10-24 07:26:59+00`），日期为 `YYYY-MM-DD`，真/假为 `Y`/`N`。
- 各教学班选课人数的单位条件按单位代码筛选（视图中没有单位 ID）。原版选择此条件时会出错。
- 教学班和上课时间没有行级安全，因此显示所有教学班行。选课和候补人数只统计查询者可见的选课和候补记录。
