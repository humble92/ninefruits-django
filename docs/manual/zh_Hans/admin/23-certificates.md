# 23. 证明

菜单：**证明 > 开具台账**、**证明 > 证明种类**、**设置 > 证明设置**。开具通过学籍界面（**学生与教职工 > 学籍**，打开一条学籍）的**开具证明**按钮进行。学生在门户的**证明**中下载自己的证明 PDF。任何人都可以在 `/verify/{代码}/` 页面验证真伪。

| 权限 | 可以做的事 |
|---|---|
| `开具、重新生成和撤销证明书` | 开具、重新生成、作废、查看开具台账（在学籍查看范围内） |
| `管理证明书种类、模板和设置` | 种类和各语言模板、编号格式、签发人 |

角色默认值：证明书管理员拥有开具，学籍管理员拥有两项，教务管理员拥有种类和模板管理。开具权限请以**全局范围**授予（数据库策略只接受全局授予）；可为哪些学生开具由学籍查看范围决定。例如，给某学院的证明书管理员全局授予 `开具、重新生成和撤销证明书`，并在该学院范围内授予 `查看学籍`。

## 与旧系统的不同之处

- **开具台账。** 旧系统（YUSTIC）在界面上直接打印（`aca3/cti_*`），台账（`SRCERT`）只用于生成编号，无法得知谁开具的、是否已作废。新系统为每次开具记录编号、验证码、经办人、用途、份数、PDF 文件和校验和，作废也不删除行。
- **真伪验证。** 旧系统没有。所有证明上都印有验证码和二维码，公开页面显示开具事实、种类、开具日期和脱敏的持有人（姓名的首字和末字，学号前 4 位）。
- **模板。** 旧系统每个种类和语言各有一个 PDF 生成脚本。新系统为每个种类在界面上修改各语言的模板（标题、正文、页脚、签发人）。
- **开具限制。** 旧系统不考虑选课拒绝名单照常开具。新系统不为设有证明限制的学生开具（[第 20 章](20-registration.md)）。
- 不记录开具手续费（旧系统也只记了金额）。
- 没有学生在线申请（计划书 17.5 节）。由教职员开具。

## 种类与模板

**证明种类**：代码（用于编号）、名称（各语言）、对象（所有学籍 / 在校生（未毕业） / 毕业生）、包含成绩、包含照片、是否启用、顺序。韩国大学配置文件（`setup_install --profile=korean-university`）预置三个种类以及 4 种语言（韩语、英语、简体中文、老挝语）的模板。只要已有任一种类就不再添加，因此修改的内容会保留。

| 代码 | 种类 | 对象 | 备注 |
|---|---|---|---|
| `ENR` | 在学证明书 | 在校生（未毕业） | |
| `GRD` | 毕业证明书 | 毕业生 | 毕业日期、学位编号 |
| `TRN` | 成绩证明书 | 所有学籍 | 按学期的已确定成绩表、累计绩点和获得学分 |

**模板**（种类编辑界面下方的**模板**栏）：每种语言一个。语言、标题、正文（用空行分段）、页脚、签发人。正文中使用花括号替换项。

| 项目 | 值 |
|---|---|
| `{institution}` | 机构名称（该语言） |
| `{student_name}`、`{student_number}` | 姓名（该语言的写法，没有则为罗马字）、学号 |
| `{program}`、`{org_unit}` | 专业、所属组织单位 |
| `{admission_date}`、`{graduation_date}`、`{degree_number}` | 入学日期、毕业日期、学位编号 |
| `{status}`、`{year_level}` | 学籍状态、年级 |
| `{birth_date}`、`{gender}`、`{nationality}` | 出生日期、性别、国籍 |
| `{issue_date}`、`{serial_number}`、`{purpose}`、`{copies}` | 开具日期、编号、用途、份数 |

日期按该语言的格式打印（例：`2026年10月24日`、`October 24, 2026`）。没有值时（例：毕业日期）留空；不在列表中的项目按原样保留。正文上方会自动插入个人信息表（姓名、学号、出生日期、性别、国籍、专业、入学日期，毕业生另有毕业日期，否则为学籍状态和年级）。整份证明（表格标题、日期、学籍状态等）都以模板的语言打印。

## 设置

**设置 > 证明设置**（`管理证明书种类、模板和设置`权限）

- **编号格式**：默认 `{TYPE}-{YYYY}-{SEQ:6}` → `ENR-2026-000001`。项目为 `{TYPE}`（种类代码）、`{YYYY}` 和 `{YY}`（开具年份，按机构时区）、`{SEQ:n}`（n 位流水号）。`{SEQ:n}` 必须有且只有一个，其后只能是普通文字。前缀不同时流水号分别计数：`{TYPE}-{SEQ:6}` 为按种类累计，`{YYYY}{SEQ:5}` 为按年份累计。同时开具编号也不会重复（数据库原子递增）。
- **验证有效期（天）**：0 表示始终有效。超过期限后验证页面显示"已过期"。开具事实本身仍留在台账中。
- **各语言签发人**：印在印章上方的名称（"九果大学校长"），机构支持的每种语言各一栏。模板中有签发人时以模板为准。

## 开具

学籍界面的**开具证明**：种类（启用中的）、语言（机构支持的语言）、用途、份数（1~20）。点击**开具证明**后生成并保存 PDF，返回学籍界面，通知中显示编号和 **PDF** 链接。

拒绝开具的情况（界面上会显示原因）：

- 种类的对象不符（为毕业生开在学证明书、为在校生开毕业证明书）
- 已停用的种类
- 没有该语言的模板
- 学生有生效中的**限制开具证明**（选课限制，[第 20 章](20-registration.md)）。解除后再开具。即使经办人看不到该限制也会拒绝。
- 学籍在查看范围之外，或没有开具权限
- PDF 服务（Gotenberg）没有响应：什么都不会开具，并显示"无法生成 PDF"。请稍后再开具。

开具记入业务审计（`certificate.issued`：学号、种类、语言、编号、份数；用途记为理由）。

## 开具台账

**证明 > 开具台账**：开具日期、编号、种类和语言、学号、姓名、用途、份数、状态、经办人，以及 **PDF**、**验证页面**链接（新标签页）。按种类和状态筛选，按编号、学号、姓名搜索。查看范围与学籍查看范围相同。

- **PDF**：打开保存的文件。不重新生成，因此与开具当时完全一致。
- **验证页面**：打开公开页面。
- **重新生成**（行菜单）：修改模板等之后，用当前数据重新生成 PDF 并替换。编号和验证码不变，校验和改变。审计 `certificate.rerendered`。与命令 `certificate_render` 相同。已作废的证明不重新生成。
- **作废**（行菜单）：必须填写理由。行和文件保留，状态变为已作废，验证页面显示"本证明已作废"。审计 `certificate.revoked`。已作废的证明不会恢复，需要重新开具。

台账行不能在界面上修改或删除（点击行可查看只读详情和校验和）。

## 真伪验证

- 证明底部印有验证 URL（`{机构地址}/verify/{代码}/`）和二维码。代码为 20 位随机字符串（大写字母和数字），不区分大小写。地址由环境变量 `APP_URL` 生成。
- 页面无需登录即可打开，每个地址（IP）每分钟限 30 次（超出时 HTTP 429），不被搜索引擎收录（`noindex`）。显示是否开具、种类、编号、开具日期、脱敏的姓名和学号。已作废、已过期、不存在的代码各有不同的回应。也可以在页面的代码输入框中验证（`/verify/?code=...`）。
- 要核对收到的 PDF 文件本身，将台账详情中的校验和（SHA-256）与文件的哈希值比较。也可以用命令 `uv run manage.py certificate_verify {代码}` 验证（[运维命令](../operations/commands.md)）。
- 供外部系统使用的真伪验证 JSON API 将在 Phase 12 加入（相同的标准和项目）。

## 学生门户

**证明**（学生、校友菜单）：为自己学籍开具的证明列表（开具日期、种类和语言、编号、状态）和 PDF。已作废的也连同状态一起显示，但没有 PDF 链接，学生不能下载已作废证明的 PDF（开具经办人可以打开以核对记录）。不能打开其他学生的文件（应用程序和数据库两端）。PDF 地址为 `/certificates/{开具 ID}/download/`。

## 常见问题

- **姓名写法有误。** 修改人员的姓名变体（该语言）后**重新生成**。如果证明已经提交，则作废后重新开具。
- **修改了模板，已开具的证明会怎样？** 不会改变。需要时**重新生成**（多件时用命令 `certificate_render`）。
- **编号跳号了。** 开具过程中出错（PDF 服务中断等）时，编号已被消耗且不会留下台账行。编号只保证唯一性，不保证连续性。
- **二维码指向 `localhost`。** 在正式服务器上把 `APP_URL` 设为机构地址，然后对相关证明**重新生成**。

## 本系统的界面

界面和功能与原系统（Filament、Livewire）相同，操作方式略有不同。

- **开具证明**打开的是填写界面而不是对话框。原系统开具后在新标签页打开 PDF；本系统返回学籍界面，通过通知中的 **PDF** 链接打开。
- 开具台账中的 **PDF** 和**验证页面**是行末的链接，**重新生成**（确认界面）和**作废**（填写理由的界面）在行菜单中。重新生成只适用于未作废的证明。
- 模板在种类编辑界面下方修改。同一语言不能有两个模板。只有 `查看基础数据` 权限时只能查看种类和模板。
- 开具时 PDF 服务出错，则什么都不会开具（原系统可能留下没有 PDF 的台账行）。
- 开具权限只承认全局授予（原系统在界面上放行有范围的授予，随后数据库拒绝该行而出错）。
- 演示数据（`setup_demo`）中，用 `certificate-officer@demo.test` 查看开具台账，用 `student@demo.test` 查看门户的**证明**。
