# 25. 教师课堂与考勤

菜单：教师使用门户的**我的授课 > 名单与考勤**（`/portal/sections/{开课 ID}/attendance/`），学生使用门户的**考勤**（`/portal/attendance/`）。教职员使用管理界面**培养方案与开课 > 开课 > 修改**界面的**课次**标签页。

| 谁 | 可以做的事 |
|---|---|
| 任课教师 | 学生名单（含照片）和 CSV、考勤表 PDF、生成课次、添加课次、停课、录入考勤 |
| `编排开课`教职员（范围内） | 与教师相同 + 管理界面的课次 |
| `查看开课`教职员（范围内） | 查看名单、考勤表、考勤 |
| 学生 | 自己的考勤 |

公告、作业、资料等课堂功能交给 LMS（移植计划第 12 节）。

## 与旧系统的不同之处

- **旧系统（YUSTIC）不记录考勤。** "考勤表"只是在学生名单旁画上空格（27~34 格，每个副本不同）打印的 PDF，没有日期也没有汇总。新系统根据上课时间生成**课次**，每个课次记录出勤、迟到、缺勤、请假，考勤表 PDF 上打印记录和合计。
- **名单。** 旧系统的教授界面只显示学号和姓名（弹窗中甚至暴露身份证号和地址），没有 Excel 下载。新系统只显示学号、姓名、照片、专业、年级、联系邮箱，并可下载 CSV。下载记入审计。
- **教师查看学生的权限。** 行级安全策略（`student_records_instructor_select`，函数 `util.taught_student_record_ids()`）允许教师查看所授班级学生的学籍和人员信息，应用程序的可见范围与之一致（原系统此前只能看到指导学生，导致成绩录入界面中姓名为空的缺陷）。

## 课次

- **生成**：按上课时间（星期、时间、期间）的每个星期各生成一个课次。教师使用**按上课时间生成**按钮，教职员使用管理界面**课次**标签页上方的**生成课次**按钮（确认页面）或命令 `uv run manage.py attendance_generate_sessions {学期}`（整个学期）。已有的课次和考勤保持不变，因此修改上课时间后可以再次执行。已停开的开课会被跳过。
- **添加课次**：补课等上课时间以外的课（日期、开始、结束）。只能是时段期间内的日期，同一日期和开始时间只能有一个课次。
- **停课**：填写原因后停课处理。课次保留，但不计入汇总。可用**恢复**还原。
- 没有节假日日历。节假日的课次按停课处理（以后引入学期日历后，生成时可自动排除）。

## 录入考勤

在课次的**录入考勤**中为每位学生选择出勤/迟到/缺勤/请假并填写备注（200 字），然后点击**保存考勤**。先**全部出勤**（不保存，全部标为出勤）再只改例外的方式最快。

- 从上课当天起可以录入（将来的课次和已停课的课次不行）。
- 再次保存时只记录有变化的学生，审计记录（`attendance.recorded`）中按学生保留原值和新值。
- 状态清空后恢复为"未录入"。
- 只能为在读和已修完的学生录入（退选、撤课的学生不在名单中）。

## 汇总

| 项目 | 定义 |
|---|---|
| 已上课次 | 未停课且在今天之前（含当天）的课次 |
| 出勤率 | （出勤 + 迟到 + 请假）÷ 已上课次 × 100，保留一位小数（四舍五入） |
| 未录入 | 已上课次中没有记录的数量 |

没有设置将若干次迟到折算为缺勤，或缺勤超过 1/3 记 F 之类的规则。各校不同，由教师在成绩中体现。汇总规则集中在一个服务（`AttendanceSummary`）中，因此名单、考勤表和学生界面显示相同的数值。

## 考勤表 PDF 与名单 CSV

两者的下载都记入审计（`attendance.sheet_exported`、`attendance.roster_exported`）。CSV 中以 `=`、`+`、`-`、`@`（以及制表符、换行）开头的值会加上单引号导出，以免被当作公式执行。

- **考勤表（PDF）**（`/sections/{开课 ID}/attendance-sheet`）：横向 A4。学生为纵向，课次为横向（不含停课），O/△/X/假标记和各学生的合计。尚未到来的课次为空白，也可用于手工记录。PDF 服务器（Gotenberg）无响应时显示"无法生成 PDF"。
- **名单（CSV）**（`/sections/{开课 ID}/roster.csv`）：学号、姓名、专业、年级、联系邮箱、选课状态。UTF-8（BOM），可在 Excel 中直接打开。

## 学生门户

**考勤**：按学期（默认为已开始的最近学期）显示所修课程的出勤、迟到、缺勤、请假次数和出勤率，展开后显示各已上课次的记录（仅教师已录入的，否则为"未录入"）。

## 运维流程

1. 学期开始前确定开课班级的上课时间（[第 18 章](18-sections-and-timetables.md)）。
2. 用 `uv run manage.py attendance_generate_sessions {学期} --actor=...` 生成课次（教师也可以在界面上直接生成）。只处理一个开课用 `--section=CSE2010-01`，只看开课数量用 `--dry-run`（[运维命令](../operations/commands.md)）。
3. 上课时间变更后再次执行。已取消时间的课次不会自动删除，按停课处理。

## 本系统的界面

界面和功能与原系统（Filament、Livewire）相同，部分操作方式略有不同。

- 管理界面开课修改界面的**课次**标签页：日期、时间、教室、状态、录入数、原因。行中的**停课**打开填写原因的页面，**恢复**打开确认页面。**生成课次**是界面上方的操作按钮。只有`查看开课`权限的教职员能看到标签页，但没有按钮。
- 教师门户中的**停课**会在课次行中展开原因输入框，填写后再次点击**停课**（代替原系统的浏览器输入框）。
- **录入考勤**页面的地址以 `?meeting={课次 ID}` 结尾，可以加入书签。**返回**回到名单和课次列表。
- 在行级安全下，只有能看到选课记录和学籍的人才能看到名单内容。默认角色（教务管理员、院系助理）同时拥有`查看选课情况和课程名单`和`查看学籍`权限。只授予`编排开课`的角色看到的名单和考勤表为空（与原系统相同）。
