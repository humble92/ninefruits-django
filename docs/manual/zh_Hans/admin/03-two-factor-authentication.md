# 3. 双重身份验证

## 用户的注册方法

在门户的 **安全** 界面（`/portal/security/`，管理界面用户菜单中的 **双重身份验证**）进行。注册、停用前需再次确认密码。

### 身份验证器应用（推荐）

1. 点击 **启用双重身份验证**。
2. 用 Google Authenticator、Microsoft Authenticator 等身份验证器应用扫描二维码。
3. 输入应用中显示的 6 位验证码，点击 **确认**。
4. 将界面上显示的 **恢复码** 保存在安全的地方。手机丢失时，每个恢复码可使用一次。

### 邮件验证码

仅在系统管理员允许时显示。这是为无法使用身份验证器应用的用户提供的方式，安全性低于身份验证器应用。

1. 在 **邮件验证码** 区域点击 **发送设置验证码**。
2. 输入发送到账户邮箱的 6 位验证码，点击 **确认**。
3. 之后每次登录都会通过邮件收到验证码。验证码在 10 分钟内只能使用一次，输错 5 次后需要重新获取。验证码每分钟最多发送 1 次，每小时最多 5 次。

两种方式可以同时注册。策略为"必须使用"时，不能停用最后剩余的一种方式。

## 策略设置（系统管理员）

在管理界面的 **设置 > 安全** 中设定。保存后，从下一次页面跳转起即对所有用户生效。

| 项目 | 说明 |
|---|---|
| 策略 | **不使用** / **建议（可选）**：仅向未注册用户显示提示 / **指定角色必须使用**：拥有所选角色的用户必须使用 / **所有人必须使用** |
| 必须使用双重验证的角色 | 策略为"指定角色必须使用"时选择 |
| 宽限期（天） | 必须使用策略首次适用于用户后，可在未注册的情况下继续使用的天数。此期间门户和管理界面上方会显示截止日期提示。到期后，除安全界面外无法使用其他功能。0 表示立即生效 |
| 记住设备（天） | 勾选 **记住此设备** 的设备可免输验证码的天数。0 表示不使用 |
| 允许邮件验证码 | 关闭后，邮件验证码不再视为双重身份验证。仅注册了邮件验证码的用户将按策略被要求注册身份验证器应用 |

推荐运营方式：教职工角色（学籍管理员、教务管理员、系统管理员等）设为 **指定角色必须使用**，学生设为建议。

## 重置（手机丢失等）

1. 在 **用户与权限 > 用户** 中打开用户。
2. 点击界面上方的 **重置双重身份验证** 并填写原因（需要 `重置双重身份验证` 权限）。
3. 该用户的身份验证器应用、恢复码、邮件验证码和已记住的设备全部解除。宽限期重新开始。

不能重置本人账户。重置会连同原因一起记录在安全事件和业务审计中。

如果唯一的管理员丢失手机而无法进入管理界面，由 IT 运维人员使用 `uv run manage.py security_reset_mfa` 重置（Docker：`docker compose exec app uv run manage.py security_reset_mfa`，[命令参考](../operations/commands.md)）。
