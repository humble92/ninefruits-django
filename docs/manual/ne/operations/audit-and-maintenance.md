# अडिट अखण्डता र नियमित मर्मतसम्भार

- लक्षित पाठक: IT सञ्चालकहरू, सुरक्षा अधिकृतहरू
- सम्बन्धित: [प्रशासक पुस्तिका अध्याय 4, अडिट](../admin/04-audit.md), [कमान्ड सन्दर्भ](commands.md), [ब्याकअप र पुनर्स्थापना](backup-restore.md)

## अडिट ह्यास चेन

अडिट तालिकाहरू (डेटा परिवर्तनका लागि `audit.record_changes`, व्यावसायिक गतिविधिका लागि `audit.activity_log`, सुरक्षा घटनाका लागि `audit.security_events`) थप्न मात्र मिल्ने (append-only) हुन् (trigger ले लागू गर्छ)। त्यसमाथि छेडछाडलाई **उजागर गर्ने** संयन्त्र पनि छ।

- हरेक पङ्क्तिले थपिँदा आफ्नो सामग्रीको SHA-256 (`row_hash`) पाउँछ।
- `audit_seal` (निर्धारित कार्य `audit.seal`, हरेक दिन 03:30 मा) ले नयाँ पङ्क्तिहरूलाई ID क्रममा चेनमा जोड्छ: `chain_hash = SHA-256(previous chain_hash || row_hash)`। यसले स्किमा मालिकको जडान (`migrator`) बाट DB फङ्सन `audit.seal()` बोलाउँछ।
- `audit_verify_chain` ले हरेक पङ्क्तिको सामग्री ह्यास र चेन फेरि गणना गर्छ। प्रति तालिका जाँचिएका पङ्क्ति, सिल गरिएका पङ्क्ति, बेमेल र पहिलो बेमेल id देखाउँछ; सामग्री बदलिएको पङ्क्ति "row mismatch", हराएको वा क्रम बदलिएको पङ्क्ति "chain mismatch" का रूपमा जनाइन्छ, र कमान्डले निकास कोड 2 फर्काउँछ।

```bash
uv run manage.py audit_seal
uv run manage.py audit_verify_chain
uv run manage.py audit_verify_chain --table=security_events
```

ध्यान दिनुपर्ने कुराहरू

- सिल हुनुअघि (उही दिनभित्र) बदलिएको पङ्क्ति चेनले समात्न सक्दैन। त्यसैले सिल हरेक दिन चल्छ र प्रमाणीकरण ब्याकअपअघि र सुरक्षा समीक्षाका बेला चल्छ।
- छँटाइ (`audit_prune`) ले सबैभन्दा पुराना पङ्क्तिहरू हटाउँदा बाँकी रहेको पहिलो पङ्क्तिको लिङ्क जाँचिँदैन (छाँटिएको दायरा छँटाइ कमान्डको अडिट अभिलेखमा राखिन्छ)।
- DB प्रशासक (स्किमा मालिक `app_migrator`) ले मात्र `app.audit_maintenance = on` सेट गर्न सक्छ। एप्लिकेसन भूमिका (`app_runtime`) सँग अडिट तालिकामा UPDATE वा DELETE अधिकार छैन।

## अवधारण र छँटाइ

1. अवधारण अवधि तय गर्नुहोस् (उदाहरणका लागि डेटा परिवर्तन 3 वर्ष, व्यावसायिक गतिविधि 5 वर्ष, सुरक्षा घटना 1 वर्ष)।
2. छँटाइअघि ब्याकअप लिनुहोस् ([ब्याकअप र पुनर्स्थापना](backup-restore.md)) र `audit_verify_chain` बाट चेन अक्षुण्ण छ भनी पुष्टि गर्नुहोस्।
3. `uv run manage.py audit_prune --before=YYYY-MM-DD --table=record_changes --dry-run` बाट सङ्ख्या जाँच्नुहोस्, त्यसपछि `--dry-run` बिना चलाउनुहोस् (`--actor=` बाट सञ्चालकको खाता अभिलेख गर्नुहोस्)। सिल नगरिएका पङ्क्तिहरू कहिल्यै मेटिँदैनन्, त्यसैले पहिले `audit_seal` चलाउनुहोस्।
4. छँटाइपछि फेरि `audit_verify_chain` चलाउनुहोस्।

छँटाइ आफैँ पनि अभिलेख हुन्छ: हरेक रनले गतिविधि लग (लग `command`) मा कटअफ मिति, विकल्प, कर्ता र OS प्रयोगकर्ता, साथै प्रति तालिका **मेटाइएका पङ्क्तिको सङ्ख्या, मेटाइएका ID को दायरा र सीमाको chain_hash** लेख्छ; वास्तविक मेटाइ सुरक्षा घटना `audit.pruned` (**अडिट > सुरक्षा घटनाहरू**) का रूपमा पनि अभिलेख हुन्छ। यो अभिलेख पङ्क्ति आफैँ अर्को सिलमा चेनमा जोडिन्छ। `audit_verify_chain` ले बाँकी रहेको पहिलो पङ्क्तिको लिङ्क नजाँच्नुको कारण ठ्याक्कै यही सीमा हो; सीमाको ह्यासलाई छँटाइ अभिलेखसँग दाँजेर मेटाइएको दायरा अभिलेख गरिएको छँटाइसँग मेल खान्छ भनी पुष्टि गर्न सकिन्छ।

## फाइल सफाइ

`uv run manage.py media_prune_orphans --dry-run` ले मालिक अब नरहेका मिडिया पङ्क्ति र पङ्क्ति नभएका डाइरेक्टरी (`PRIVATE_MEDIA_ROOT/<media id>/`) सूचीबद्ध गर्छ; `--dry-run` बिना तिनलाई मेटाउँछ। यसले व्यक्तिका फोटो, आवेदनका कागजात, प्रमाणपत्र PDF र परीक्षाका प्रमाण समेट्छ। मासिक वा ठूलो मेटाइपछि चलाउनुहोस्।

## स्वास्थ्य जाँच

| जाँच | तरिका | असफल हुँदा |
|---|---|---|
| सेवाको स्थिति | `GET /api/v1/health/` (साइन इन नचाहिने, लोड ब्यालेन्सर र मनिटरिङका लागि) | DB वा क्यासले जवाफ नदिँदा `unavailable` (503), अनुसूचकको heartbeat 5 मिनेटभन्दा पुरानो हुँदा `degraded` (200), नत्र `ok`। `प्रशासन प्यानल खोल्ने` अनुमतिसहित साइन इन गर्दा प्रत्येक जाँच (`database`, `cache`, `scheduler`) पनि देखाउँछ |
| पूर्ण जाँच | `uv run manage.py system_health_check [--json]` | 12 जाँच: कुञ्जी, DB भूमिका, RLS, migration, अनुमति क्याटलग, Redis, Celery worker, Gotenberg, भण्डारण, beat heartbeat। कुनै असफल भएमा निकास कोड 2 |
| उत्पादन सेटिङ | `uv run manage.py check --deploy` | `DEBUG`, HTTPS redirect, HSTS, सुरक्षित cookie, गोप्य कुञ्जीबारे चेतावनी |
| Migration | `uv run manage.py migrate --check` | लागू नभएका migration भएमा निकास कोड 1 |
| अनुमति क्याटलग | `uv run manage.py security_sync_permissions` | कोडको अनुमति सूची DB मा ल्याउँछ (फेरि चलाउन सुरक्षित) |
| PDF सेवा | `uv run manage.py pdf_sample` | Gotenberg जडान, फन्ट |
| अनुवाद | `uv run manage.py i18n_missing --strict` | अनुवाद छुटेमा निकास कोड 2 |
| अडिट चेन | `uv run manage.py audit_verify_chain` | बेमेल भएमा निकास कोड 2 |
| क्यु | Flower, `uv run celery -A config inspect ping` | worker ले जवाफ दिँदैन |

मनिटरिङलाई `/api/v1/health/` को HTTP स्थिति र `status` मानसँग जोड्नुहोस्; अरू डिप्लोयका बेला र [नियमित जाँच](deployment-checklist.md#नियमित-जाँच) मा चलाउनुहोस्।
