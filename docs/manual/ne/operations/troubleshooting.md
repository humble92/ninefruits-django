# समस्या समाधान

- लक्षित पाठक: IT सञ्चालकहरू
- सम्बन्धित: [डिप्लोय जाँचसूची](deployment-checklist.md), [निर्धारित कार्यहरू](scheduled-jobs.md), [कमान्ड सन्दर्भ](commands.md)

| लक्षण | के जाँच्ने |
|---|---|
| साइन इन गर्नेबित्तिकै सुरक्षा पृष्ठमा पठाइन्छ | दुई-चरण नीति "अनिवार्य" छ र छुट अवधि नाघिसकेको छ। प्रयोगकर्ताले दर्ता गरेपछि समाधान हुन्छ। नीति **सेटिङ > सुरक्षा** मा छ |
| प्रशासन प्यानलमा 403 | प्रयोगकर्तासँग `admin_panel.access` अनुमति (`प्रशासन प्यानल खोल्ने`) भएको मान्य भूमिका तोकाइ छैन। **प्रयोगकर्ता र पहुँच > प्रयोगकर्ताहरू** मा प्रयोगकर्ता खोलेर **भूमिका तोकाइ** सूची (अवधि, दायरा) जाँच्नुहोस् |
| कुनै मेनु वस्तु देखिँदैन | भूमिकासँग त्यस स्क्रिनको अनुमति (उदाहरणका लागि `roles.view`) छैन |
| इमेल कोड आइपुग्दैन | मेल सेटिङ (`MAIL_*`, `DEFAULT_FROM_EMAIL`), **अडिट > सुरक्षा घटनाहरू** मा `इमेल कोड पठाइयो` प्रविष्टि, पठाउने सीमा (प्रति प्रयोगकर्ता प्रति मिनेट एक पटक, प्रति घण्टा पाँच पटक) |
| साइन इन पृष्ठले `429 Too Many Requests` जवाफ दिन्छ | एउटा ठेगानाले प्रति मिनेट `LOGIN_RATE_LIMIT_PER_IP` (पूर्वनिर्धारित 30) प्रयास नाघ्यो। धेरै प्रयोगकर्ता एकैपटक रोकिएमा `TRUSTED_PROXY_COUNT` वास्तविक प्रोक्सी सङ्ख्यासँग मेल खान्छ कि जाँच्नुहोस् (सबै Nginx को ठेगानाका रूपमा देखिन्छन्); क्याम्पस NAT पछाडि मान बढाउनुहोस् ([डिप्लोय जाँचसूची](deployment-checklist.md#प्रोक्सी-र-क्लाइन्टको-ठेगाना)) |
| सही पासवर्डले पनि साइन इन असफल | साइन इन लक भएको छ (**सुरक्षा घटनाहरू** मा `साइन इन लक भयो`) वा खाता निष्क्रिय छ। लक `uv run manage.py security_unlock_user <email> --reason="..."` बाट हटाउनुहोस् |
| स्क्रिनले अरूको डेटाका 0 पङ्क्ति देखाउँछ | सामान्य हुन सक्छ (पङ्क्ति स्तरको सुरक्षा)। **अडिट > डेटा परिवर्तनहरू** को प्रयोगकर्ता स्तम्भ हेरेर DB सत्रको कर्ता सेट भएको पुष्टि गर्नुहोस् |
| `400 Bad Request` | अनुरोध गरिएको होस्ट नाम `DJANGO_ALLOWED_HOSTS` मा छैन |
| `403 CSRF verification failed` | `DJANGO_CSRF_TRUSTED_ORIGINS` मा `https://` ठेगाना छैन, वा Nginx ले `X-Forwarded-Proto` पठाउँदैन |
| अनन्त HTTPS redirect | Nginx ले `X-Forwarded-Proto $scheme` पठाउँदैन, त्यसैले Django ले HTTP अनुरोध देख्छ (`SECURE_PROXY_SSL_HEADER`) |
| शैली वा स्क्रिप्टबिनाका स्क्रिन, `manifest.json` त्रुटि | `npm ci && npm run build` (`static/dist/`), `collectstatic`, Nginx को `/static/` location। उत्पादनले `VITE_DEV_MODE=false` प्रयोग गर्छ |
| स्क्रिनका केही भाग अङ्ग्रेजीमा देखिन्छन् | `compilemessages --ignore=.venv` चलाइएको छैन (`.mo` फाइल छैनन्)। नयाँ स्ट्रिङका लागि `uv run manage.py i18n_missing <locale>` |
| `permission denied for schema public` | एप्लिकेसनले `app_runtime` का रूपमा DDL प्रयास गर्‍यो। migration `uv run manage.py migrate` वा `setup_install` बाट मात्र चलाउनुहोस् (दुवैले स्वतः `app_migrator` प्रयोग गर्छन्) |
| `Audit records are append-only` | अडिट तालिका अद्यावधिक वा मेटाउने प्रयास। यो रोक जानाजानी गरिएको हो |
| PDF बनाउन असफल | `uv run manage.py pdf_sample`, Gotenberg को स्थिति, `GOTENBERG_URL`, `GOTENBERG_TIMEOUT` |
| क्यु कार्यहरू अड्किएका छन् | Flower मा worker जडान र असफल कार्यहरू, `uv run celery -A config inspect active`, Redis जडान (`REDIS_URL`) जाँच्नुहोस् |
| निर्धारित कार्यहरू चल्दैनन्, `/api/v1/health/` ले `degraded` जवाफ दिन्छ | beat रोकिएको छ (5 मिनेटभन्दा बढी अनुसूचकको heartbeat छैन)। beat प्रक्रिया र त्यसको लग जाँच्नुहोस्। beat एउटा मात्र |
| worker लगमा `Received unregistered task` | worker ले अझै अघिल्लो कोड चलाउँदैछ। डिप्लोयपछि worker पुनः सुरु गर्नुहोस् |
| सेमेस्टर बन्द पूरा हुँदैन | Flower मा असफल `grading.close_term_records` कार्यहरू। कारण सच्याएर सेमेस्टर बन्द फेरि सुरु गर्नुहोस् (प्रति विद्यार्थी गणनाले फेरि चलाउँदा उही नतिजा दिन्छ) |

प्रति-अनुरोध ट्रेसिङ: `X-Request-Id` response हेडरको मानबाट लग (JSON मा `request_id`), गतिविधि लग, डेटा परिवर्तन र सुरक्षा घटनाहरू सँगै खोज्न सकिन्छ। Nginx ले `X-Request-Id $request_id` पठाउँदा Nginx को access log पनि जोडिन्छ। कमान्ड रनले `cmd-` बाट सुरु हुने रन ID प्रयोग गर्छन्।
