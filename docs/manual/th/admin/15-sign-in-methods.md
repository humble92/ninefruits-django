# 15. วิธีเข้าสู่ระบบ

เมนู: **การตั้งค่า > วิธีเข้าสู่ระบบ** (สิทธิ์ `จัดการวิธีเข้าสู่ระบบและ SSO`)

## ชื่อสำหรับเข้าสู่ระบบ

อีเมลของบัญชีเป็นชื่อสำหรับเข้าสู่ระบบโดยค่าเริ่มต้น เมื่อเปิดการเข้าสู่ระบบด้วยรหัสนักศึกษา ช่องกรอกบนหน้าจอเข้าสู่ระบบจะเปลี่ยนเป็น "อีเมลหรือรหัสนักศึกษา"

| เข้าสู่ระบบด้วยรหัสนักศึกษา | การทำงาน |
|---|---|
| ไม่อนุญาต | ใช้อีเมลเท่านั้น |
| เฉพาะนักศึกษาปัจจุบัน | เข้าสู่ระบบได้ด้วยรหัสนักศึกษาของระเบียนที่กำลังศึกษาหรือลาพักการศึกษา |
| นักศึกษาปัจจุบันและผู้สำเร็จการศึกษา | เข้าสู่ระบบได้ด้วยรหัสนักศึกษาของระเบียนที่สิ้นสุดแล้ว (สำเร็จการศึกษา ลาออก ฯลฯ) ด้วย |

บุคคลที่มีระเบียนนักศึกษาหลายระเบียนจะเข้าสู่บัญชีเดียวกันไม่ว่าจะใช้รหัสนักศึกษาใด

## การล็อกบัญชี

| การตั้งค่า | คำอธิบาย |
|---|---|
| ล็อกหลังพยายามไม่สำเร็จ (ครั้ง) | บัญชีจะถูกล็อกเมื่อกรอกรหัสผ่านผิดติดต่อกันครบจำนวนครั้งนี้ ค่า 0 คือปิดการล็อก |
| ระยะเวลาล็อก (นาที) | การล็อกจะถูกปลดโดยอัตโนมัติเมื่อครบเวลานี้ |

การพยายามเข้าสู่ระบบด้วยอีเมลและด้วยรหัสนักศึกษานับเป็นความล้มเหลวของบัญชีเดียวกัน บัญชีที่ถูกล็อกจะได้รับข้อความเดียวกับกรณีรหัสผ่านผิด จึงไม่เปิดเผยว่าบัญชีนั้นมีอยู่หรือไม่ การล็อกจะถูกบันทึกเป็นเหตุการณ์ด้านความปลอดภัย (**ล็อกการเข้าสู่ระบบ**)

หากต้องการปลดล็อกก่อนกำหนด ให้ใช้ **ปลดล็อกการเข้าสู่ระบบ** ในหน้ารายละเอียดของ **ผู้ใช้** (ต้องระบุเหตุผล สิทธิ์ `แก้ไขผู้ใช้`) เมื่อไม่สามารถใช้แผงผู้ดูแลระบบได้ ผู้ปฏิบัติงานฝ่ายไอทีจะใช้ `uv run manage.py security_unlock_user`

## เข้าสู่ระบบด้วยบัญชีสถาบัน (SSO)

เมื่อลงทะเบียนการเข้าสู่ระบบแบบ OpenID Connect ของสถาบัน (เช่น Microsoft Entra ID, Google Workspace, Keycloak) หน้าจอเข้าสู่ระบบจะมีปุ่ม "เข้าสู่ระบบด้วย ..." เพิ่มขึ้น

| ช่อง | คำอธิบาย |
|---|---|
| คีย์ | ตัวระบุเป็นตัวพิมพ์เล็ก เช่น `school` การเปลี่ยนคีย์จะทำให้การเชื่อมโยงที่มีอยู่ใช้ไม่ได้ |
| ข้อความบนปุ่ม | ชื่อที่แสดงบนหน้าจอเข้าสู่ระบบ |
| URL ของผู้ออก (Issuer) | Issuer ของผู้ให้บริการ ต้องเข้าถึง `/.well-known/openid-configuration` ได้ภายใต้ที่อยู่นี้ |
| Client ID, Client secret | ค่าที่ได้รับเมื่อลงทะเบียนแอปพลิเคชันกับผู้ให้บริการ Secret จะถูกจัดเก็บแบบเข้ารหัส |
| Scopes | ค่าเริ่มต้น `openid email profile` |
| นับเป็นการยืนยันตัวตนแบบสองขั้นตอน | เปิดเฉพาะเมื่อการเข้าสู่ระบบด้วยบัญชีสถาบันบังคับใช้การยืนยันตัวตนแบบสองขั้นตอนอยู่แล้ว เมื่อเปิด ระบบนี้จะไม่ขอการยืนยันตัวตนแบบสองขั้นตอนซ้ำสำหรับการเข้าสู่ระบบด้วยวิธีนี้ |
| Redirect URI ที่ต้องลงทะเบียนกับผู้ให้บริการ | ลงทะเบียนที่อยู่ที่แสดงบนหน้าจอ (`https://<server>/auth/sso/<key>/callback/`) ในการตั้งค่าแอปพลิเคชันของผู้ให้บริการให้ตรงทุกตัวอักษร |

### การเชื่อมโยงบัญชี

| โหมด | การทำงาน |
|---|---|
| ผู้ใช้เชื่อมโยงบัญชีเอง | ผู้ใช้เข้าสู่ระบบด้วยรหัสผ่าน แล้วกด **เชื่อมโยง** ที่ **ความปลอดภัย > เข้าสู่ระบบด้วยบัญชีสถาบัน** ในพอร์ทัล (ต้องยืนยันรหัสผ่าน) |
| เชื่อมโยงอัตโนมัติด้วยอีเมลสถาบันที่ยืนยันแล้ว | เมื่ออีเมลที่ผู้ให้บริการยืนยันแล้วตรงกับอีเมลสถาบันในระเบียนนักศึกษา บัญชีจะถูกเชื่อมโยงโดยอัตโนมัติในการเข้าสู่ระบบครั้งแรก |

- การเข้าสู่ระบบด้วยบัญชีสถาบันที่ยังไม่ได้เชื่อมโยงจะแสดงข้อความแนะนำให้เข้าสู่ระบบด้วยรหัสผ่านแล้วเชื่อมโยงบัญชี บัญชีสถาบันเพียงอย่างเดียวจะไม่สร้างบัญชีใหม่
- การเชื่อมโยงและการยกเลิกการเชื่อมโยงจะถูกบันทึกในบันทึกด้านความปลอดภัย

### การอนุญาตให้เข้าสู่ระบบด้วยรหัสผ่าน

หากปิด **อนุญาตรหัสผ่านสำหรับผู้ใช้ที่เข้าสู่ระบบด้วยบัญชีสถาบัน** ผู้ใช้ที่เชื่อมโยงแล้วจะเข้าสู่ระบบได้ด้วยบัญชีสถาบันเท่านั้น เนื่องจากบัญชีสถาบันมักถูกลบหลังสำเร็จการศึกษา จึงแนะนำให้เปิดไว้ และขอให้นักศึกษาที่ใกล้สำเร็จการศึกษาเตรียมอีเมลส่วนตัวและรหัสผ่านไว้ ผู้สำเร็จการศึกษาจะเข้าสู่ระบบต่อไปด้วยอีเมลสำหรับเข้าสู่ระบบของบัญชี (อีเมลส่วนตัว) และรหัสผ่าน
