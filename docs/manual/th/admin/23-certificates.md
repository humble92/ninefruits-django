# 23. หนังสือรับรอง

เมนู: **หนังสือรับรอง > หนังสือรับรองที่ออกแล้ว**, **หนังสือรับรอง > ประเภทหนังสือรับรอง**, **การตั้งค่า > การตั้งค่าหนังสือรับรอง** หนังสือรับรองออกด้วยปุ่ม **ออกหนังสือรับรอง** ในหน้าจอระเบียนนักศึกษา (**นักศึกษาและบุคลากร > ระเบียนนักศึกษา** แล้วเปิดระเบียน) นักศึกษาดาวน์โหลด PDF หนังสือรับรองของตนเองได้ในพอร์ทัลที่ **หนังสือรับรอง** ทุกคนสามารถตรวจสอบหนังสือรับรองได้ที่หน้า `/verify/{code}/`

| สิทธิ์ | สิ่งที่ทำได้ |
|---|---|
| `ออก สร้างใหม่ และเพิกถอนหนังสือรับรอง` | ออก สร้างใหม่ เพิกถอน ดูหนังสือรับรองที่ออกแล้ว (ภายในขอบเขตการดูระเบียนนักศึกษา) |
| `จัดการประเภท แม่แบบ และการตั้งค่าหนังสือรับรอง` | ประเภทและแม่แบบของแต่ละภาษา รูปแบบเลขที่เอกสาร ผู้ลงนาม |

ค่าเริ่มต้นของบทบาท: เจ้าหน้าที่ออกหนังสือรับรองเป็นผู้ออก เจ้าหน้าที่ทะเบียนมีทั้งสองสิทธิ์ เจ้าหน้าที่ฝ่ายวิชาการจัดการประเภทและแม่แบบ ให้กำหนดสิทธิ์การออกด้วย **ขอบเขตทั้งหมด** (นโยบายของฐานข้อมูลยอมรับเฉพาะการกำหนดแบบทั้งหมด) นักศึกษาที่เจ้าหน้าที่ออกหนังสือรับรองให้ได้จะเป็นไปตามขอบเขตการดูระเบียนนักศึกษาของเจ้าหน้าที่ผู้นั้น ตัวอย่างเช่น ให้เจ้าหน้าที่ออกหนังสือรับรองของคณะหนึ่งมีสิทธิ์ `ออก สร้างใหม่ และเพิกถอนหนังสือรับรอง` แบบทั้งหมด และ `ดูระเบียนนักศึกษา` สำหรับคณะนั้น

## ความแตกต่างจากระบบเดิม

- **ทะเบียนหนังสือรับรองที่ออก** ระบบเดิม (YUSTIC) พิมพ์โดยตรงจากหน้าจอ (`aca3/cti_*`) และทะเบียน (`SRCERT`) มีไว้เพียงเพื่อสร้างเลขที่ จึงไม่แสดงว่าใครเป็นผู้ออกหรือถูกเพิกถอนหรือไม่ ระบบใหม่บันทึกเลขที่เอกสาร รหัสตรวจสอบ เจ้าหน้าที่ วัตถุประสงค์ จำนวนฉบับ ไฟล์ PDF และค่า checksum ทุกครั้งที่ออก และหนังสือรับรองที่ถูกเพิกถอนยังคงมีแถวของตนอยู่
- **การตรวจสอบ** ระบบเดิมไม่มี หนังสือรับรองทุกฉบับมีรหัสตรวจสอบและ QR code และหน้าสาธารณะจะแสดงว่าออกแล้ว ประเภท วันที่ออก และผู้ถือแบบปิดบังบางส่วน (อักขระแรกและอักขระสุดท้ายของชื่อ อักขระ 4 ตัวแรกของรหัสนักศึกษา)
- **แม่แบบ** ระบบเดิมมีสคริปต์ PDF แยกตามประเภทและภาษา ระบบใหม่แก้ไขแม่แบบของแต่ละภาษา (หัวเรื่อง เนื้อความ ท้ายเอกสาร ผู้ลงนาม) สำหรับแต่ละประเภทบนหน้าจอ
- **การระงับ** ระบบเดิมออกหนังสือรับรองโดยไม่คำนึงถึงรายชื่อห้ามลงทะเบียน ระบบใหม่ไม่ออกหนังสือรับรองให้นักศึกษาที่ถูกระงับการออกหนังสือรับรอง ([บทที่ 20](20-registration.md))
- ไม่มีการบันทึกค่าธรรมเนียม (ระบบเดิมบันทึกเพียงจำนวนเงิน)
- ไม่มีการยื่นคำขอออนไลน์โดยนักศึกษา (แผนการย้ายระบบ 17.5) เจ้าหน้าที่เป็นผู้ออกหนังสือรับรอง

## ประเภทและแม่แบบ

**ประเภทหนังสือรับรอง**: รหัส (ใช้ในเลขที่เอกสาร) ชื่อ (ตามภาษา) กลุ่มเป้าหมาย (ระเบียนนักศึกษาทุกรายการ / นักศึกษา (ยังไม่สำเร็จการศึกษา) / ผู้สำเร็จการศึกษา) มีผลการเรียน มีรูปถ่าย ใช้งาน ลำดับ โปรไฟล์มหาวิทยาลัยเกาหลี (`setup_install --profile=korean-university`) สร้างไว้ให้สามประเภทพร้อมแม่แบบสี่ภาษา (เกาหลี อังกฤษ จีนตัวย่อ ลาว) เมื่อมีประเภทใดอยู่แล้ว โปรไฟล์จะไม่เพิ่มอะไรอีก การแก้ไขของท่านจึงคงอยู่

| รหัส | ประเภท | กลุ่มเป้าหมาย | หมายเหตุ |
|---|---|---|---|
| `ENR` | หนังสือรับรองการเป็นนักศึกษา | นักศึกษา (ยังไม่สำเร็จการศึกษา) | |
| `GRD` | หนังสือรับรองการสำเร็จการศึกษา | ผู้สำเร็จการศึกษา | วันที่สำเร็จการศึกษา เลขที่ปริญญาบัตร |
| `TRN` | ใบแสดงผลการเรียน | ระเบียนนักศึกษาทุกรายการ | ตารางเกรดที่ยืนยันแล้วแยกตามภาคการศึกษา เกรดเฉลี่ยสะสม และหน่วยกิตที่ได้ |

**แม่แบบ** (ส่วน **แม่แบบ** ด้านล่างของหน้าจอแก้ไขประเภท): หนึ่งแม่แบบต่อภาษา ภาษา หัวเรื่อง เนื้อความ (แยกย่อหน้าด้วยบรรทัดว่าง) ท้ายเอกสาร ผู้ลงนาม เนื้อความใช้ตัวแทนข้อมูลในวงเล็บปีกกา

| ตัวแทนข้อมูล | ค่า |
|---|---|
| `{institution}` | ชื่อสถาบัน (ในภาษานั้น) |
| `{student_name}`, `{student_number}` | ชื่อ (ในรูปแบบของภาษานั้น หากไม่มีจะใช้การสะกดแบบละติน) รหัสนักศึกษา |
| `{program}`, `{org_unit}` | หลักสูตร หน่วยงาน |
| `{admission_date}`, `{graduation_date}`, `{degree_number}` | วันที่เข้าศึกษา วันที่สำเร็จการศึกษา เลขที่ปริญญาบัตร |
| `{status}`, `{year_level}` | สถานภาพนักศึกษา ชั้นปี |
| `{birth_date}`, `{gender}`, `{nationality}` | วันเกิด เพศ สัญชาติ |
| `{issue_date}`, `{serial_number}`, `{purpose}`, `{copies}` | วันที่ออก เลขที่เอกสาร วัตถุประสงค์ จำนวนฉบับ |

วันที่จะพิมพ์ตามรูปแบบของภาษานั้น (เช่น `October 24, 2026`, `2026년 10월 24일`) ค่าที่ไม่มี (เช่น วันที่สำเร็จการศึกษา) จะพิมพ์เป็นช่องว่าง ตัวแทนข้อมูลที่ไม่อยู่ในรายการจะคงไว้ตามที่เขียน ตารางข้อมูลส่วนบุคคล (ชื่อ รหัสนักศึกษา วันเกิด เพศ สัญชาติ หลักสูตร วันที่เข้าศึกษา ตามด้วยวันที่สำเร็จการศึกษาสำหรับผู้สำเร็จการศึกษา หรือสถานภาพและชั้นปีสำหรับกรณีอื่น) จะถูกเพิ่มโดยอัตโนมัติด้านบนเนื้อความ หนังสือรับรองทั้งฉบับ (ป้ายในตาราง วันที่ สถานภาพ) จะพิมพ์ในภาษาของแม่แบบ

## การตั้งค่า

**การตั้งค่า > การตั้งค่าหนังสือรับรอง** (`จัดการประเภท แม่แบบ และการตั้งค่าหนังสือรับรอง`)

- **รูปแบบเลขที่เอกสาร**: ค่าเริ่มต้น `{TYPE}-{YYYY}-{SEQ:6}` → `ENR-2026-000001` โทเค็นได้แก่ `{TYPE}` (รหัสประเภท) `{YYYY}` และ `{YY}` (ปีที่ออก ตามเขตเวลาของสถาบัน) และ `{SEQ:n}` (ลำดับเลข n หลัก) ต้องมี `{SEQ:n}` หนึ่งตัวพอดี และตามหลังได้เฉพาะข้อความธรรมดาเท่านั้น ลำดับจะนับแยกกันสำหรับแต่ละคำนำหน้าที่ต่างกัน: `{TYPE}-{SEQ:6}` นับต่อประเภทข้ามปี `{YYYY}{SEQ:5}` นับต่อปีข้ามประเภท การออกพร้อมกันจะไม่ชนกัน (ตัวนับเพิ่มค่าแบบ atomic ในฐานข้อมูล)
- **ตรวจสอบได้เป็นเวลา (วัน)**: 0 หมายถึงตลอดไป หลังพ้นระยะเวลา หน้าตรวจสอบจะตอบว่า "หมดอายุ" ส่วนรายการที่ออกยังคงอยู่ในทะเบียน
- **ผู้ลงนามตามภาษา**: ชื่อที่พิมพ์เหนือตราประทับ ("อธิการบดี มหาวิทยาลัย Ninefruits") หนึ่งช่องต่อภาษาที่สถาบันรองรับ ผู้ลงนามในแม่แบบมีลำดับความสำคัญสูงกว่า

## การออกหนังสือรับรอง

**ออกหนังสือรับรอง** ในหน้าจอระเบียนนักศึกษา: ประเภท (ที่ใช้งานอยู่) ภาษา (ภาษาของสถาบัน) วัตถุประสงค์ จำนวนฉบับ (1 ถึง 20) **ออกหนังสือรับรอง** จะสร้างและจัดเก็บ PDF แล้วกลับไปยังระเบียนนักศึกษา ข้อความแจ้งจะแสดงเลขที่เอกสารพร้อมลิงก์ **PDF**

ระบบจะปฏิเสธการออก (หน้าจอจะแจ้งเหตุผล) เมื่อ:

- กลุ่มเป้าหมายของประเภทไม่ตรงกัน (หนังสือรับรองการเป็นนักศึกษาสำหรับผู้สำเร็จการศึกษา หนังสือรับรองการสำเร็จการศึกษาสำหรับนักศึกษาปัจจุบัน)
- ประเภทนั้นไม่ได้ใช้งาน
- ไม่มีแม่แบบสำหรับภาษานั้น
- นักศึกษามี **การระงับการออกหนังสือรับรอง** ที่มีผลอยู่ (การระงับ [บทที่ 20](20-registration.md)) ให้ยกเลิกการระงับก่อน การระงับมีผลแม้เจ้าหน้าที่จะมองไม่เห็นการระงับนั้น
- ระเบียนนักศึกษาอยู่นอกขอบเขตการดู หรือเจ้าหน้าที่ไม่มีสิทธิ์ออก
- บริการ PDF (Gotenberg) ไม่ตอบสนอง: จะไม่มีการออกใด ๆ และแสดงข้อความ "ไม่สามารถสร้าง PDF ได้" ให้ออกใหม่ภายหลัง

การออกหนังสือรับรองจะถูกบันทึกในบันทึกการดำเนินงาน (`certificate.issued`: รหัสนักศึกษา ประเภท ภาษา เลขที่เอกสาร จำนวนฉบับ โดยวัตถุประสงค์บันทึกเป็นเหตุผล)

## หนังสือรับรองที่ออกแล้ว

**หนังสือรับรอง > หนังสือรับรองที่ออกแล้ว**: วันที่ออก เลขที่เอกสาร ประเภทและภาษา รหัสนักศึกษา ชื่อ วัตถุประสงค์ จำนวนฉบับ สถานะ เจ้าหน้าที่ และลิงก์ **PDF** และ **หน้าตรวจสอบ** (แท็บใหม่) กรองตามประเภทและสถานะ ค้นหาด้วยเลขที่เอกสาร รหัสนักศึกษา หรือชื่อ ขอบเขตการดูเหมือนกับของระเบียนนักศึกษา

- **PDF**: เปิดไฟล์ที่จัดเก็บไว้ ไม่มีการสร้างใหม่ จึงตรงกับฉบับที่ออกทุกประการ
- **หน้าตรวจสอบ**: เปิดหน้าสาธารณะ
- **สร้างใหม่** (เมนูแถว): สร้าง PDF ใหม่จากข้อมูลปัจจุบัน เช่น หลังแก้ไขแม่แบบ และแทนที่ไฟล์เดิม เลขที่เอกสารและรหัสตรวจสอบคงเดิม ค่า checksum จะเปลี่ยน เหตุการณ์ตรวจสอบ `certificate.rerendered` เหมือนกับคำสั่ง `certificate_render` หนังสือรับรองที่ถูกเพิกถอนจะไม่ถูกสร้างใหม่
- **เพิกถอน** (เมนูแถว): ต้องระบุเหตุผล แถวและไฟล์ยังคงอยู่ สถานะเปลี่ยนเป็นเพิกถอนแล้ว และหน้าตรวจสอบจะตอบว่า "เพิกถอนแล้ว" เหตุการณ์ตรวจสอบ `certificate.revoked` หนังสือรับรองที่ถูกเพิกถอนจะไม่ถูกคืนสถานะ ให้ออกฉบับใหม่แทน

แถวในทะเบียนแก้ไขหรือลบบนหน้าจอไม่ได้ (การเปิดแถวจะแสดงรายละเอียดแบบอ่านอย่างเดียวพร้อมค่า checksum)

## การตรวจสอบ

- URL ตรวจสอบ (`{institution address}/verify/{code}/`) และ QR code จะพิมพ์ไว้ด้านล่างของหนังสือรับรอง รหัสเป็นสตริงสุ่มยาว 20 ตัวอักษร (อักษรตัวพิมพ์ใหญ่และตัวเลข) ไม่แยกตัวพิมพ์ใหญ่เล็ก ที่อยู่มาจากตัวแปรสภาพแวดล้อม `APP_URL`
- หน้านี้เปิดได้โดยไม่ต้องเข้าสู่ระบบ และจำกัดไว้ที่ 30 คำขอต่อนาทีต่อที่อยู่ (IP เกินกว่านั้นได้ HTTP 429) เครื่องมือค้นหาจะถูกขอไม่ให้จัดทำดัชนี (`noindex`) แสดงว่าหนังสือรับรองออกแล้วหรือไม่ ประเภท เลขที่เอกสาร วันที่ออก และชื่อและรหัสนักศึกษาแบบปิดบังบางส่วน รหัสที่ถูกเพิกถอน หมดอายุ และไม่รู้จัก จะได้รับคำตอบที่ต่างกัน ช่องรหัสในหน้านี้ก็ใช้ตรวจสอบรหัสได้เช่นกัน (`/verify/?code=...`)
- หากต้องการตรวจสอบไฟล์ PDF ที่ได้รับมาโดยตรง ให้เปรียบเทียบค่า checksum (SHA-256) ในรายละเอียดของทะเบียนกับค่าแฮชของไฟล์ คำสั่ง `uv run manage.py certificate_verify {code}` ก็ตรวจสอบรหัสได้เช่นกัน ([คำสั่ง](../operations/commands.md))
- ระบบอื่นตรวจสอบแบบเดียวกันและได้รายละเอียดเดียวกันเป็น JSON: `GET /api/v1/certificates/verify/<verification code>/` (ไม่ต้องเข้าสู่ระบบ 30 คำขอต่อนาทีต่อที่อยู่ [คู่มือการเชื่อมต่อ LMS](../../../lms-integration-guide.md))

## พอร์ทัลนักศึกษา

**หนังสือรับรอง** (เมนูของนักศึกษาและศิษย์เก่า): หนังสือรับรองที่ออกในระเบียนของนักศึกษาเอง (วันที่ออก ประเภทและภาษา เลขที่เอกสาร สถานะ) พร้อม PDF หนังสือรับรองที่ถูกเพิกถอนจะแสดงในรายการพร้อมสถานะแต่ไม่มีลิงก์ PDF และนักศึกษาจะดาวน์โหลด PDF ของหนังสือรับรองที่ถูกเพิกถอนไม่ได้ (เจ้าหน้าที่ผู้ออกสามารถเปิดเพื่อตรวจสอบบันทึกได้) ไฟล์ของนักศึกษาคนอื่นเปิดไม่ได้ (บังคับใช้ทั้งในแอปพลิเคชันและฐานข้อมูล) ที่อยู่ของ PDF คือ `/certificates/{issue id}/download/`

## คำถามที่พบบ่อย

- **ชื่อสะกดผิด** แก้ไขรูปแบบชื่อของบุคคล (ในภาษานั้น) แล้ว **สร้างใหม่** หากส่งหนังสือรับรองไปแล้ว ให้เพิกถอนและออกฉบับใหม่
- **แก้ไขแม่แบบแล้ว หนังสือรับรองที่ออกไปแล้วจะเป็นอย่างไร** หนังสือรับรองเหล่านั้นไม่เปลี่ยนแปลง ให้ **สร้างใหม่** หากจำเป็น (ครั้งละหลายฉบับด้วยคำสั่ง `certificate_render`)
- **เลขที่เอกสารถูกข้ามไป** เมื่อเกิดข้อผิดพลาดระหว่างการออก (เช่น บริการ PDF ไม่ทำงาน) เลขที่จะถูกใช้ไปแล้วและไม่มีแถวในทะเบียนเหลืออยู่ ระบบรับประกันว่าเลขที่ไม่ซ้ำกัน แต่ไม่รับประกันว่าต่อเนื่องกัน
- **QR code ชี้ไปที่ `localhost`** ตั้งค่า `APP_URL` บนเซิร์ฟเวอร์ใช้งานจริงเป็นที่อยู่ของสถาบัน แล้ว **สร้างใหม่** หนังสือรับรองที่ได้รับผลกระทบ

## หน้าจอในการติดตั้งนี้

หน้าจอและฟังก์ชันเป็นแบบเดียวกับต้นฉบับ (Filament, Livewire) แต่วิธีใช้งานต่างกันเล็กน้อย

- **ออกหนังสือรับรอง** จะเปิดหน้าแบบฟอร์มแทนหน้าต่างโต้ตอบ ต้นฉบับเปิด PDF ในแท็บใหม่หลังออก ในที่นี้ระบบจะกลับไปยังหน้าจอระเบียนนักศึกษา และลิงก์ **PDF** ในข้อความแจ้งจะเปิดไฟล์
- ในทะเบียน **PDF** และ **หน้าตรวจสอบ** เป็นลิงก์ที่ท้ายแถว **สร้างใหม่** (หน้ายืนยัน) และ **เพิกถอน** (หน้ากรอกเหตุผล) อยู่ในเมนูแถว สร้างใหม่ใช้ได้เฉพาะกับหนังสือรับรองที่ยังไม่ถูกเพิกถอน
- แม่แบบแก้ไขได้ที่ด้านล่างของหน้าจอแก้ไขประเภท ระบบจะไม่รับแม่แบบสองรายการของภาษาเดียวกัน ผู้ที่มีเพียงสิทธิ์ `ดูข้อมูลอ้างอิง` จะเห็นประเภทและแม่แบบแบบอ่านอย่างเดียว
- เมื่อบริการ PDF ล้มเหลวระหว่างการออก จะไม่มีการออกใด ๆ (ในต้นฉบับอาจมีแถวในทะเบียนเหลืออยู่โดยไม่มี PDF)
- สิทธิ์การออกจะนับเฉพาะเมื่อกำหนดแบบทั้งหมด (ต้นฉบับยอมให้การกำหนดแบบมีขอบเขตผ่านบนหน้าจอ แล้วฐานข้อมูลจึงปฏิเสธแถวพร้อมข้อผิดพลาด)
- ในข้อมูลสาธิต (`setup_demo`) `certificate-officer@demo.test` จะเห็นทะเบียน และ `student@demo.test` จะเห็น **หนังสือรับรอง** ในพอร์ทัล
