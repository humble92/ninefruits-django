# 4. การตรวจสอบ

หน้าจอทั้งสามในเมนู **การตรวจสอบ** เป็นแบบอ่านอย่างเดียว ไม่มีผู้ใดแก้ไขหรือลบได้ (ต้องมีสิทธิ์ `ดูบันทึกการตรวจสอบ` และ `ดูเหตุการณ์ด้านความปลอดภัย`) รายการเหล่านี้ไม่มีปุ่มเพิ่ม แก้ไข หรือลบ การเปิดแถวจะแสดงรายละเอียดแบบอ่านอย่างเดียว

| หน้าจอ | สิ่งที่แสดง | ตัวอย่าง |
|---|---|---|
| บันทึกการดำเนินงาน | ใครทำอะไร และ **เพราะเหตุใด** เหตุผลและรายละเอียด | การกำหนดบทบาท (เหตุผล: ปฏิบัติหน้าที่แทนระหว่างภาคการศึกษา) การเปลี่ยนสิทธิ์ (รายการที่เพิ่ม/นำออก) การเปลี่ยนการตั้งค่า (ก่อน/หลัง) การรันคำสั่ง |
| การเปลี่ยนแปลงข้อมูล | ค่าก่อนและหลังของแถวในตาราง รวมถึงการเปลี่ยนแปลงโดยตรงที่ไม่ผ่านแอปพลิเคชัน | `users` UPDATE คอลัมน์ที่เปลี่ยนแปลง `locale` |
| เหตุการณ์ด้านความปลอดภัย | การเข้าสู่ระบบ การเข้าสู่ระบบไม่สำเร็จ การยืนยันตัวตนแบบสองขั้นตอน เหตุการณ์เกี่ยวกับสิทธิ์ การเปลี่ยนรหัสผ่านและอีเมล การลบบันทึกการตรวจสอบเก่า (`audit_prune`) | เข้าสู่ระบบไม่สำเร็จ (ชื่อที่ใช้เข้าสู่ระบบ, IP) |

## วิธีอ่าน

- คอลัมน์ **ผู้ใช้**: การดำเนินการบนหน้าจอจะแสดงชื่อผู้ใช้หรือ `user:หมายเลข` งานอัตโนมัติ (Celery) แสดงเป็น `system:task:...` และคำสั่งแสดงเป็น `system:command:...`
- รหัสผ่าน ข้อมูลลับของการยืนยันตัวตนแบบสองขั้นตอน และค่าที่คล้ายกันจะถูกปิดบังเป็น `[redacted]`
- รายการที่มี **รหัสคำขอ** เดียวกันเกิดจากคำขอหน้าจอครั้งเดียวกัน การค้นหารหัสคำขอเดียวกันในทุกหน้าจอจะเห็นร่องรอยทั้งหมดของการดำเนินการหนึ่งครั้ง การรันคำสั่งจะใช้รหัสการรันที่ขึ้นต้นด้วย `cmd-`

## การค้นหาที่ใช้บ่อย

เลือกเงื่อนไขที่ **ตัวกรอง** มุมขวาบนของรายการ และพิมพ์ค่าในช่องค้นหา

| สิ่งที่ต้องการทราบ | วิธี |
|---|---|
| สิทธิ์ของผู้ใช้เปลี่ยนเมื่อใด | ในบันทึกการดำเนินงาน เลือกบันทึก `security` เหตุการณ์ `role.assigned`, `role.assignment_revoked` |
| บัญชีที่เข้าสู่ระบบไม่สำเร็จหลายครั้ง | ในเหตุการณ์ด้านความปลอดภัย กรองเหตุการณ์ `เข้าสู่ระบบไม่สำเร็จ` แล้วดูคอลัมน์ชื่อที่ใช้เข้าสู่ระบบ |
| ใครเปลี่ยนนโยบายความปลอดภัย | เหตุการณ์ `settings.updated` ในบันทึกการดำเนินงาน |
| แถวหนึ่งเปลี่ยนแปลงอย่างไร | ในการเปลี่ยนแปลงข้อมูล กรองตามตารางแล้วค้นหาด้วยรหัสรายการ |
