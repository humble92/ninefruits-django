# Резервное копирование и восстановление

- Для кого: ИТ-специалисты по эксплуатации
- Связанные документы: [установка](installation.md), [управление ключами](security-keys.md), [целостность аудита](audit-and-maintenance.md)

## Что копировать

| Объект | Способ | Периодичность (рекомендуемая) |
|---|---|---|
| PostgreSQL | `pg_dump -Fc` или PITR (архивирование WAL) | Ежедневная полная копия + непрерывный WAL |
| Закрытое файловое хранилище (`PRIVATE_MEDIA_ROOT`, по умолчанию `storage/private`) | Снимок или бакет с версиями | Так же, как БД |
| Конфигурация окружения и ключи (`DJANGO_SECRET_KEY`, `PII_*`, пароли БД) | Хранилище секретов | При каждом изменении |

БД и файловое хранилище должны восстанавливаться на один и тот же момент времени (метаданные фотографий, документов заявлений, PDF справок и подтверждающих документов экзаменов хранятся в таблице БД `media`). Redis не копируется: в нём хранятся только кеш, блокировки и очередь, а сессии также хранятся в БД (`django_session`). Список заданий по расписанию (django-celery-beat) тоже находится в БД, и beat при запуске заново согласует его с `config/celery.py`.

`staticfiles/` и `static/dist/` — результат сборки, их резервные копии не делаются (`npm run build` и `collectstatic` создают их заново).

## Пример резервного копирования БД

```bash
pg_dump -h db.internal -U app_migrator -d ninefruits -Fc -f ninefruits-$(date +%F).dump
```

`app_migrator` владеет всеми схемами (`public`, `audit`, `reporting`, `util`), поэтому делайте резервную копию под этой учётной записью. Роли (`app_*`) — объекты кластера и в дамп не входят. На сервере восстановления сначала создайте роли, как описано в разделе 2 документа [Установка](installation.md).

Если выполнить `uv run manage.py audit_verify_chain` перед резервным копированием, та же команда на восстановленной БД позволит сравнить цепочки аудита.

## Пример восстановления

```bash
createdb -U postgres ninefruits_restore
psql -U postgres -d ninefruits_restore -v ON_ERROR_STOP=1 -f db/sql/roles/prepare_database.sql
pg_restore -U app_migrator -d ninefruits_restore --no-owner --role=app_migrator ninefruits-2026-10-22.dump
```

Чтобы запустить приложение на восстановленной БД, задайте `DB_DATABASE=ninefruits_restore` и **ключи на момент резервного копирования** (`DJANGO_SECRET_KEY`, `PII_ENCRYPTION_KEY`, `PII_HASH_KEY`, а также `PII_PREVIOUS_KEYS`, если с тех пор выполнялась ротация ключа). Затем проверьте состояние:

```bash
DB_DATABASE=ninefruits_restore uv run manage.py migrate --check   # code and schema versions match
DB_DATABASE=ninefruits_restore uv run manage.py audit_verify_chain
```

Если `migrate --check` сообщает о миграциях, которые нужно применить, резервная копия старше текущего кода. Восстанавливайте с кодом той же версии или обновите командой `setup_install --force`.

## Учебные восстановления

Каждый квартал восстанавливайте данные на отдельный сервер и проверяйте: вход, расшифровку персональных данных (**Показать номер удостоверения личности** у лица в панели администрирования; ключи совпадают), просмотр записей аудита и `audit_verify_chain`, открытие файлов (фотографии, PDF справок), страницу проверки справок. Записывайте результат (затраченное время, проблемы).
