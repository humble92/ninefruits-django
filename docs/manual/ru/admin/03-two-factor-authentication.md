# 3. Двухфакторная аутентификация

## Как пользователи её подключают

Пользователи подключают её на странице **Безопасность** портала (`/portal/security/`, в панели администрирования — пункт **Двухфакторная аутентификация** в меню пользователя). Перед подключением или отключением пароль запрашивается ещё раз.

### Приложение-аутентификатор (рекомендуется)

1. Нажмите **Включить двухфакторную аутентификацию**.
2. Отсканируйте QR-код приложением-аутентификатором, например Google Authenticator или Microsoft Authenticator.
3. Введите 6-значный код, показанный в приложении, и нажмите **Подтвердить**.
4. Сохраните в надёжном месте **коды восстановления**, показанные на экране. Каждый из них можно использовать один раз, если телефон утерян.

### Код из письма

Отображается, только если это разрешил системный администратор. Предназначен для пользователей, которые не могут пользоваться приложением-аутентификатором, и менее безопасен, чем приложение.

1. В области **Код из письма** нажмите **Отправить код для настройки**.
2. Введите 6-значный код, отправленный на адрес электронной почты учётной записи, и нажмите **Подтвердить**.
3. С этого момента при каждом входе код приходит по электронной почте. Код можно использовать один раз в течение 10 минут; после 5 неверных попыток нужен новый код. Коды можно отправлять не чаще одного раза в минуту и не более 5 раз в час.

Можно подключить оба способа. Если политика требует двухфакторной аутентификации, последний оставшийся способ отключить нельзя.

## Настройки политики (системный администратор)

Задаются в разделе **Настройки > Безопасность** в панели администрирования. После сохранения действуют для всех пользователей начиная со следующей загрузки страницы.

| Параметр | Описание |
|---|---|
| Политика | **Не используется** / **Рекомендуется (необязательно)**: пользователи без подключения видят только уведомление / **Обязательно для выбранных ролей**: пользователи с выбранными ролями обязаны подключить её / **Обязательно для всех** |
| Роли, обязанные использовать двухфакторную аутентификацию | Выбираются, если политика — «Обязательно для выбранных ролей» |
| Льготный период (дней) | Сколько пользователь может работать без подключения после того, как требование впервые стало к нему применяться. В этот период в верхней части портала и панели администрирования показывается уведомление о сроке. По его истечении доступна только страница безопасности. 0 — сразу |
| Запоминать устройства (дней) | Сколько код не запрашивается на устройстве, где было выбрано **Запомнить это устройство**. 0 отключает эту возможность |
| Разрешить коды по эл. почте | Если выключено, коды из письма не считаются двухфакторной аутентификацией. Пользователям, подключившим только код из письма, в соответствии с политикой предлагается подключить приложение-аутентификатор |

Рекомендуемый режим: **Обязательно для выбранных ролей** для ролей сотрудников (учебный отдел, учебное управление, системный администратор и т. п.), «рекомендуется» — для студентов.

## Сброс (утерян телефон и т. п.)

1. Откройте пользователя в разделе **Пользователи и доступ > Пользователи**.
2. Нажмите **Сбросить двухфакторную аутентификацию** в верхней части страницы и укажите причину (требуется разрешение `Сбрасывать двухфакторную аутентификацию`).
3. Приложение-аутентификатор, коды восстановления, код из письма и запомненные устройства пользователя удаляются. Льготный период начинается заново.

Собственную учётную запись сбросить нельзя. Сброс вместе с причиной записывается как событие безопасности и в журнал действий.

Если единственный администратор потерял телефон и не может открыть панель администрирования, ИТ-оператор выполняет сброс командой `uv run manage.py security_reset_mfa` (Docker: `docker compose exec app uv run manage.py security_reset_mfa`, [справочник команд](../operations/commands.md)).
