# 28. Интеграция с LMS

Меню: панель администрирования **Интеграция с LMS > Платформы LMS**, **Связи с курсами**, **Журналы синхронизации** (разрешение `Управлять платформами LMS, связями и синхронизацией`; по умолчанию: системный администратор, сотрудник учебного управления (Academic Affairs)). Преподаватели используют ссылки на LMS в разделе **Мои дисциплины** портала и в сведениях о группе, а также кнопку **Загрузить баллы из LMS** на экране ввода оценок. Загрузка подчиняется тем же условиям, что и ввод оценок (назначенный преподаватель, в период ввода оценок).

Подробности для разработчиков (написание коннектора, API) — в [руководстве по интеграции с LMS](../../../lms-integration-guide.md).

## Что и куда передаётся

| SIS → LMS | Когда |
|---|---|
| Группа (создание курса) + преподаватели | При **публикации** группы, а также командой `lms_sync` |
| Подтверждённая запись на дисциплину → зачисление на курс | Сразу при записи, переводе из листа ожидания или записи сотрудником |
| Отмена записи или выход из дисциплины → отчисление с курса | Сразу |
| Полная сверка | Ежедневно в 02:30 (`lms_reconcile`, задача по расписанию `lms.reconcile`) |

| LMS → SIS | Когда |
|---|---|
| Итоговые баллы (черновик) | Когда преподаватель нажимает **Загрузить баллы из LMS** на экране ввода оценок. Сохранение и отправку выполняет преподаватель |

Итоговые оценки в LMS не передаются. Учебные материалы, задания и тесты находятся в LMS.

## Платформы

**Платформы LMS**: код, название (на каждом языке), драйвер, базовый URL, учётные данные, активен, синхронизировать списки групп, загружать итоговые баллы.

- Драйвер **Нет (только запись)**: ничего не вызывает и записывает то, что было бы отправлено. Используйте его для проверки процесса или демонстраций до интеграции. Его использует платформа `DEMO` в демонстрационных данных.
- `Moodle`, `Open edX`: коннектора пока нет (помечены как «пока не реализован»). Если выбрать их, синхронизации записываются как неудачные.
- **Учётные данные** записываются по одной паре `key=value` в строке (например, `token=...`). Они хранятся в зашифрованном виде и никогда не показываются обратно. Если при редактировании оставить поле пустым, сохранённые значения остаются. История изменений данных также не содержит эти значения.
- Включение параметра **Активен** означает, что публикации групп и изменения записей с этого момента сразу передаются, а платформа включается в ночную сверку.

## Связи с курсами и журналы синхронизации

- **Связи с курсами**: какая группа связана с каким курсом платформы (ID, URL), статус (Ожидает/Связано/Ошибка), последняя синхронизация и ошибка. Фильтры по платформе, статусу и семестру; поиск по коду дисциплины. Действие строки **Синхронизировать снова** (со страницей подтверждения) заново передаёт группу, преподавателей и список группы.
- **Журналы синхронизации**: результат и сообщение по каждому шагу (курс, добавление и удаление участника, загрузка баллов, доставка баллов, сверка). Здесь ищите причину сбоя. При открытии строки показываются время начала и окончания и содержимое (payload).
- Команды: `uv run manage.py lms_sync {platform} --term={term}` (полная передача, `--dry-run`), `uv run manage.py lms_reconcile` (сверка). См. [команды эксплуатации](../operations/commands.md#интеграция-с-lms-этап-12).

## Портал

- Ссылка на курс платформы показывается в сведениях о дисциплине для студентов и преподавателей, а также в списке **Мои дисциплины** преподавателя (столбец **LMS**; только для связанных групп).
- Ввод оценок: если для платформы включено **Загружать итоговые баллы** и группа связана, появляется кнопка **Загрузить баллы из LMS**. Она только заполняет столбец баллов и не сохраняет их.

## API интеграции

API (`/api/v1/lms/platforms/...`) обслуживает платформы, которые сообщают результаты позже или сами присылают баллы. Создайте отдельную учётную запись интеграции только с разрешением `Управлять платформами LMS, связями и синхронизацией`; оператор выпускает для неё токен командой `uv run manage.py api_issue_token {email} --days=365` и передаёт его администратору платформы. Токен показывается только один раз, при выпуске. `api_revoke_tokens` отзывает его. Выпуск и отзыв записываются в журнал аудита.

- Баллы, полученные через доставку баллов (`.../scores/`), тоже не сохраняются. Когда преподаватель нажимает **Загрузить баллы из LMS**, последние полученные баллы заполняют форму как черновик.
- Результаты синхронизации (`.../sync-results/`) сохраняются в **Журналы синхронизации**, а результаты по курсам меняют статус в **Связи с курсами**.

## Частые вопросы

- **Студента нет в LMS.** Для синхронизации у студента должна быть учётная запись (пользователь). Если её нет, пригласите его ([глава 14](14-merge-and-invitations.md)); следующая сверка добавит его.
- **Синхронизация остаётся неудачной.** Прочитайте сообщение в журнале синхронизации. Часто причина — истёкшие учётные данные. Измените значения на экране редактирования платформы и нажмите **Синхронизировать снова**.
- **Мы перешли на другую платформу.** Создайте новую платформу и выключите у старой параметр «Активен». Связи создаются отдельно для каждой платформы.

## Экраны в этой установке

Экраны и функции те же, что и в исходной системе (Filament, Livewire); некоторые действия отличаются.

- Учётные данные вводятся строками `key=value` в текстовом поле вместо таблицы ключ/значение исходной системы. Строки неверного формата отклоняются с указанием номера строки.
- Для **параметров** платформы (ID ролей на платформе и т. п.) на экране нет поля. Разработчики задают их, когда они нужны коннектору ([руководство по интеграции](../../../lms-integration-guide.md), раздел 3).
- **Синхронизировать снова** проходит через страницу подтверждения. Ошибки коннектора (драйвер без коннектора, сбой платформы) показываются сообщением «Ошибка синхронизации: ...», а связь с курсом получает статус «Ошибка» (исходная система показывала страницу ошибки).
- Журналы синхронизации доступны только для чтения. При открытии строки содержимое показывается в виде JSON.
- **Загрузить баллы из LMS** на экране ввода оценок находится в ряду кнопок под таблицей. Кнопка снова показывает страницу, меняя только поля баллов и сохраняя уже введённое. Ничего не сохраняется до **Сохранить черновик**.
- API интеграции и команды токенов (`api_issue_token`, `api_revoke_tokens`) — новинка этой установки (в исходной системе API не было).
