# 26. Проверка требований к выпуску и выпуск

Меню: **Выпуск > Проверки требований к выпуску**, кнопка **Проверка требований** на экране просмотра личного дела студента, **Настройки > Настройки выпуска** (шаблон номера диплома, минимальный накопленный средний балл; разрешение `Оформлять выпуск`). Студенты видят свой прогресс на портале в разделе **Требования к выпуску**.

| Разрешение | Что позволяет |
|---|---|
| `Выполнять и просматривать проверки требований к выпуску` | Выполнение проверок (по одному студенту и массово) и просмотр сохранённых проверок |
| `Оформлять выпуск, предоставлять освобождения от требований` | Оформление выпуска (массово), освобождения от требований |

Роли по умолчанию: у сотрудника учебного отдела (Registrar) есть оба разрешения, у сотрудника учебного управления (Academic Affairs) — проверки.

## Отличия от прежней системы

- **Требования проверяются.** Лист проверки выпуска прежней системы (YUSTIC) лишь печатал кредиты и средний балл по категориям дисциплин и ни с чем их не сравнивал (поле результата проверки было пустым). Новая система сравнивает их с **требованиями к выпуску** для года учебного плана ([глава 17](17-courses-and-curriculum.md)) и сообщает, выполнено ли каждое требование.
- **Перед выпуском обязательна проверка.** В прежней системе достаточно было ввести код изменения статуса Z. Новая система оформляет выпуск только тогда, когда последняя сохранённая проверка выполнена.
- **Номер диплома присваивает система.** Прежняя система не использовала поле номера диплома, и номер диплома вписывался вручную.
- Выпускники не переносятся в другую таблицу. Меняется только статус студента на `Выпускник`, а учётная запись сохраняет доступ выпускника ([глава 13](13-status-changes-and-advisors.md)).

## Правила проверки

Находится набор требований для **основной программы × года учебного плана** студента, и проверяется каждое требование.

| Вид требования | Проверка |
|---|---|
| Кредиты в категории | Сумма кредитов сданных дисциплин, категория которых — эта категория **или подчинённая ей** ≥ минимума кредитов |
| Обязательные дисциплины | Сданы все дисциплины из списка. Засчитываются **эквивалентные дисциплины**, действовавшие на момент записи |
| Выбор из дисциплин | Кредиты или число сданных дисциплин из списка (включая эквивалентные) не ниже порога |
| Сданный экзамен | Есть положительный результат этого вида экзамена ([глава 24](24-assessments.md)) |

- «Сдана» означает запись на дисциплину, итоговая оценка по которой положительная (`is_passed`). Засчитываются и дисциплины, сданные в других личных делах того же лица (до восстановления).
- Проверяются также **всего кредитов** набора требований и **минимальный накопленный средний балл** из **Настройки > Настройки выпуска** (по умолчанию 2.0; пусто: не применяется).
- Вторые специальности и minor проверяются отдельно по их собственным наборам требований и показываются вместе. Условие выпуска — выполнение требований основной программы.
- Если набора требований для года учебного плана нет, проверка не выполнена (набор необходимо создать).

## Проверки

- **Проверить сейчас**: кнопка **Проверка требований** на экране просмотра личного дела студента. Она сразу проверяет текущие данные и показывает сданные и недостающие дисциплины по каждому требованию. **Сохранить эту проверку** сохраняет её.
- **Массовые проверки**: **Проверки требований к выпуску > Выполнить проверки** (семестр, начиная с курса) или команда `uv run manage.py degree_audit_run --term={term} --min-year-level=4 --actor=...` ([команды эксплуатации](../operations/commands.md)). Проверка сохраняется для каждого обучающегося студента.
- Сохранённая проверка — это **снимок**. Последующие изменения оценок его не меняют; повторная проверка добавляет новый снимок. Список показывает только **последнюю** проверку по каждому студенту и роли программы, и при оформлении выпуска тоже учитывается последняя проверка.

## Освобождения от требований

Отдельное требование может быть снято с учётом индивидуальных обстоятельств, например смены специальности, поступления в порядке перевода или обмена. Участвуют два человека (решение от 2026-10-23).

1. **Запрос**: в разделе **Освободить от требования** на экране просмотра личного дела студента выберите требование и укажите причину (разрешение `Оформлять выпуск, предоставлять освобождения от требований`). Событие аудита `graduation.waiver_requested`.
2. **Одобрение или отклонение**: в разделе **Выпуск > Освобождения от требований** **другой сотрудник** с тем же разрешением одобряет (комментарий необязателен) или отклоняет (комментарий обязателен). Никто не может принимать решение по собственному запросу. События аудита `graduation.waiver_approved`/`waiver_rejected`.
3. В проверке выполненными считаются только одобренные освобождения. На одно требование — одно ожидающее или одобренное освобождение.
4. **Отмена**: **Отменить освобождение** у одобренного освобождения (требуется причина) прекращает его действие и сохраняет историю (статус `Отменено`, событие аудита `graduation.waiver_lifted`). Выпуск уже оформленного студента не отменяется.

Каждый шаг также отражается в истории изменений данных.

## Оформление выпуска

В списке **Проверки требований к выпуску** выберите студентов и нажмите **Выпустить** (дата выпуска, причина). Для каждого студента:

1. Проверяется, что студент обучается и последняя проверка по основной программе выполнена. Иначе этот студент пропускается, а причина сообщается.
2. Записывается изменение статуса `Выпуск` (статус `Выпускник`, дата выпуска). Оно появляется в истории изменений статуса из [главы 13](13-status-changes-and-advisors.md).
3. Присваивается номер диплома. Шаблон — `{PROGRAM}-{YYYY}-{SEQ:5}` из **Настройки > Настройки выпуска** (по умолчанию, например `CS-2026-00001`; токены `{PROGRAM}` — код программы, `{YYYY}`, `{YY}` — год выпуска, `{SEQ:n}` — порядковый номер для каждого префикса). Одновременная обработка никогда не приводит к конфликтам.
4. Событие аудита `graduation.processed` (студенческий номер, дата выпуска, номер диплома, проверка, на основании которой оформлен выпуск).

Выпускники продолжают видеть свои оценки и справки на портале, а в справке об окончании печатаются дата выпуска и номер диплома ([глава 23](23-certificates.md)). Ошибочный выпуск исправляется изменением статуса (восстановление и т. п.). Функции отмены выпуска нет.

## Частые вопросы

- **Проверка сообщает «нет набора требований».** У программы нет набора требований к выпуску, охватывающего год учебного плана студента. Создайте его, как описано в [главе 17](17-courses-and-curriculum.md).
- **Эквивалентная дисциплина не засчитывается.** Срок действия эквивалентности должен включать дату начала семестра, в котором изучалась дисциплина.
- **Что произойдёт при изменении шаблона номера диплома?** Он применяется начиная со следующего присвоения. Если меняется префикс, нумерация снова начинается с 1.

## Экраны этой установки

Экраны и функции те же, что и в исходной системе (Filament, Livewire); некоторые элементы управления работают немного иначе.

- Список **Выпуск > Проверки требований к выпуску** (`/admin/graduation/degreeaudit/`): фильтры по умолчанию — роль программы **Основная программа** и статус студента **Обучается**. **Открыть** в строке показывает сохранённую проверку; **Проверить снова** открывает страницу подтверждения. **Выполнить проверки** — кнопка действия над списком (семестр, начиная с курса, по умолчанию 4).
- Чтобы выполнить **Выпустить**, отметьте строки, выберите **Выпустить** в списке действий и выполните: страница запрашивает дату выпуска и причину. Студенты, которых не удалось обработать, перечисляются со студенческим номером и причиной в виде предупреждений (до 10).
- **Проверка требований** в личном деле студента показывает проверку, выполненную сейчас, на отдельной странице; **Сохранить эту проверку** ниже сохраняет её. **Освободить от требования** открывает страницу для выбора требования и указания причины.
- **Выпуск > Освобождения от требований** (`/admin/graduation/degreerequirementwaiver/`): фильтр статуса по умолчанию — **Ожидает**, а в меню показывается число ожидающих. **Одобрить**, **Отказать** и **Отменить освобождение** в строке открывают страницу для комментария (причины). Если открыть их для собственного запроса или для уже решённого освобождения, возвращается 403.
- **Настройки > Настройки выпуска** (`/admin/settings/graduation/`): шаблон номера диплома сохраняется только с ровно одним `{SEQ:n}`. Минимальный накопленный средний балл — от 0 до 5; пусто — не применяется.
- **Требования к выпуску** на портале (`/portal/graduation/`): в меню студентов и выпускников. При нескольких личных делах (восстановление) используется личное дело, выбранное на портале.
- Выпуск записывает изменение статуса и номер диплома в системном контексте после проверки разрешений (обработка выпуска, область действия личного дела, область одобрения изменений статуса), поэтому сотрудникам, занимающимся выпуском, не нужно дополнительно `Создавать и редактировать личные дела студентов`. Журнал изменений данных всё равно указывает пользователя, выполнившего обработку.
