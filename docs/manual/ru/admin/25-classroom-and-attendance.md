# 25. Работа преподавателя с группой и посещаемость

Меню: преподаватели используют на портале **Мои дисциплины > Список группы и посещаемость** (`/portal/sections/{section ID}/attendance/`), студенты — **Посещаемость** на портале (`/portal/attendance/`). Сотрудники используют вкладку **Занятия** экрана **Учебные планы и группы > Группы > Изменить** в панели администрирования.

| Кто | Что может делать |
|---|---|
| Назначенные преподаватели | Список группы (с фотографиями) и CSV, журнал посещаемости в PDF, создание, добавление и отмена занятий, ввод посещаемости |
| Сотрудники с `Планировать группы` (в пределах области действия) | То же, что преподаватели, + занятия в панели администрирования |
| Сотрудники с `Просматривать группы` (в пределах области действия) | Список группы, журнал посещаемости, просмотр посещаемости |
| Студенты | Своя посещаемость |

Функции учебной среды, такие как объявления, задания и материалы, оставлены LMS (раздел 12 плана переноса).

## Отличия от прежней системы

- **Прежняя система (YUSTIC) не вела учёт посещаемости.** Её «журнал посещаемости» был PDF-файлом, в котором рядом со списком группы печатались пустые клетки (от 27 до 34, в зависимости от экземпляра), без дат и итогов. Новая система создаёт **занятия** по расписанию занятий, записывает для каждого занятия «присутствовал», «опоздал», «отсутствовал» или «уважительная причина» и печатает записи и итоги в журнале посещаемости в PDF.
- **Список группы.** Экран преподавателя в прежней системе показывал только студенческие номера и ФИО (а во всплывающем окне раскрывал номер регистрации резидента и адрес) и не позволял скачать Excel. Новая система показывает только студенческий номер, ФИО, фотографию, программу, курс и контактную эл. почту и позволяет скачать CSV. Скачивания записываются в журнал аудита.
- **Доступ преподавателей к своим студентам.** Политика защиты на уровне строк (`student_records_instructor_select`, функция `util.taught_student_record_ids()`) позволяет преподавателям видеть личные дела студентов и сведения о лицах-студентах своих групп, а правила видимости приложения ей соответствуют (раньше исходная система показывала только их подопечных студентов, из-за чего ФИО оставались пустыми даже на экране ввода оценок).

## Занятия

- **Создание**: одно занятие на каждое повторение недельного расписания занятий (день, время, пара). Преподаватели используют кнопку **Создать по расписанию**; сотрудники — кнопку **Создать занятия** над вкладкой **Занятия** (со страницей подтверждения) или команду `uv run manage.py attendance_generate_sessions {term}` (весь семестр). Существующие занятия и посещаемость не затрагиваются, поэтому создание можно запускать повторно после изменения расписания занятий. Отменённые группы пропускаются.
- **Добавить занятие**: занятие вне расписания, например отработка (дата, начало, окончание). Только даты в пределах учебного периода и только одно занятие на дату и время начала.
- **Отменить**: отмена занятия с указанием причины. Занятие сохраняется, но не учитывается в итогах. **Восстановить** возвращает его.
- Календаря праздников нет. Отменяйте занятия в государственные праздники (когда будет добавлен календарь семестра, генератор сможет их пропускать).

## Ввод посещаемости

В разделе **Посещаемость** занятия выберите для каждого студента «присутствовал», «опоздал», «отсутствовал» или «уважительная причина» при необходимости добавьте примечание (200 символов) и нажмите **Сохранить посещаемость**. Быстрее всего нажать **Все присутствуют** (отмечает всех присутствующими без сохранения), а затем изменить исключения.

- Посещаемость можно вводить начиная с дня занятия (для будущих и отменённых занятий — нельзя).
- При повторном сохранении записываются только изменившиеся студенты, а событие аудита (`attendance.recorded`) сохраняет старое и новое значение по каждому студенту.
- Если очистить статус, студент возвращается в состояние «не отмечено».
- Отмечать можно только записанных студентов и студентов, завершивших дисциплину (студенты, отменившие запись или вышедшие из дисциплины, в списке группы отсутствуют).

## Итоги

| Элемент | Определение |
|---|---|
| Проведённые занятия | Неотменённые занятия, дата которых — сегодня или раньше |
| Процент посещаемости | (присутствовал + опоздал + уважительная причина) ÷ проведённые занятия × 100, один знак после запятой (половины округляются вверх) |
| Не отмечено | Проведённые занятия без записи |

Нет правила, превращающего определённое число опозданий в пропуск или ставящего F при пропуске более трети занятий. Это различается между вузами, поэтому преподаватели сами учитывают посещаемость в оценке. Правила подсчёта находятся в одном сервисе (`AttendanceSummary`), поэтому список группы, журнал посещаемости и страница студента показывают одни и те же числа.

## Журнал посещаемости в PDF и список группы в CSV

Оба скачивания записываются в журнал аудита (`attendance.sheet_exported`, `attendance.roster_exported`). Значения CSV, начинающиеся с `=`, `+`, `-` или `@` (или с табуляции или перевода строки), выгружаются с ведущим апострофом, чтобы они не выполнялись как формулы.

- **Журнал посещаемости (PDF)** (`/sections/{section ID}/attendance-sheet`): альбомный A4. Студенты — по строкам, занятия — по столбцам (отменённые не включаются), отметки O/△/X/E и итоги по каждому студенту. Будущие занятия остаются пустыми, поэтому журнал подходит и для ручных отметок. Если сервер PDF (Gotenberg) не отвечает, показывается «Не удалось создать PDF».
- **Список группы (CSV)** (`/sections/{section ID}/roster.csv`): студенческий номер, ФИО, программа, курс, контактная эл. почта, статус записи. UTF-8 с BOM, поэтому файл сразу открывается в Excel.

## Портал студента

**Посещаемость**: по семестрам (по умолчанию — последний начавшийся семестр) и дисциплинам — число присутствий, опозданий, пропусков и пропусков по уважительной причине и процент посещаемости; в развёрнутом виде — запись по каждому проведённому занятию (только то, что ввёл преподаватель, иначе «Не отмечено»).

## Порядок работы

1. До начала семестра окончательно утвердите расписание занятий групп ([глава 18](18-sections-and-timetables.md)).
2. Создайте занятия командой `uv run manage.py attendance_generate_sessions {term} --actor=...` (преподаватели также могут создать их на экране). Только одна группа: `--section=CSE2010-01`; только число групп: `--dry-run` ([команды эксплуатации](../operations/commands.md)).
3. При изменении расписания занятий запустите команду снова. Занятия удалённого времени автоматически не удаляются; отмените их.

## Экраны в этой установке

Экраны и функции те же, что и в исходной системе (Filament, Livewire); некоторые элементы управления работают немного иначе.

- Вкладка **Занятия** экрана изменения группы в панели администрирования: дата, время, аудитория, статус, введённые записи, причина. **Отменить** в строке открывает страницу для причины, **Восстановить** — страницу подтверждения. **Создать занятия** — кнопка действия в верхней части экрана. Сотрудники только с разрешением `Просматривать группы` видят вкладку без кнопок.
- На портале преподавателя **Отменить** открывает поле причины в строке занятия; введите причину и снова нажмите **Отменить** (вместо запроса браузера в исходной системе).
- Адрес страницы ввода **Посещаемость** заканчивается на `?meeting={meeting ID}`, поэтому её можно добавить в закладки. **Назад** возвращает к списку группы и списку занятий.
- При защите на уровне строк список группы заполняется только для тех, кто может видеть записи на дисциплины и личные дела студентов. Роли по умолчанию (Academic Affairs, методист кафедры) имеют также `Просматривать записи на дисциплины и списки групп` и `Просматривать личные дела студентов`. Роль, которой назначено только `Планировать группы`, видит пустой список группы и журнал (как в исходной системе).
