# 23. Справки

Меню: **Справки > Выданные справки**, **Справки > Виды справок**, **Настройки > Настройки справок**. Справки выдаются кнопкой **Выдать справку** на экране личного дела студента (**Студенты и сотрудники > Личные дела студентов**, откройте личное дело). Студенты скачивают PDF-файлы своих справок на портале в разделе **Справки**. Любой может проверить справку на странице `/verify/{code}/`.

| Разрешение | Что позволяет |
|---|---|
| `Выдавать, формировать заново и аннулировать справки` | Выдача, повторное формирование, аннулирование, просмотр выданных справок (в пределах области действия просмотра личных дел студентов) |
| `Управлять видами справок, шаблонами и настройками` | Виды справок и их шаблоны для каждого языка, шаблон регистрационного номера, подписанты |

Роли по умолчанию: ответственный за справки выдаёт справки, у сотрудника учебного отдела (Registrar) есть оба разрешения, сотрудник учебного управления (Academic Affairs) управляет видами и шаблонами. Разрешение на выдачу назначайте с **глобальной областью действия** (политика базы данных принимает только глобальное назначение); для каких студентов сотрудник может выдавать справки, определяется его областью просмотра личных дел студентов. Например, ответственному за справки института назначьте `Выдавать, формировать заново и аннулировать справки` глобально и `Просматривать личные дела студентов` для этого института.

## Отличия от прежней системы

- **Журнал выданных справок.** Прежняя система (YUSTIC) печатала прямо с экрана (`aca3/cti_*`), а её журнал (`SRCERT`) существовал только для генерации номеров, поэтому по нему нельзя было узнать, кто выдал справку и не была ли она аннулирована. Новая система при каждой выдаче записывает регистрационный номер, код проверки, сотрудника, цель, число экземпляров, PDF-файл и контрольную сумму, а аннулированная справка сохраняет свою строку.
- **Проверка.** В прежней системе её не было. Каждая справка содержит код проверки и QR-код, а общедоступная страница показывает факт выдачи, вид справки, дату выдачи и замаскированные данные владельца (первый и последний символы имени, первые 4 символа студенческого номера).
- **Шаблоны.** В прежней системе для каждого вида и языка был отдельный PDF-скрипт. Новая система позволяет редактировать на экране шаблон для каждого языка (заголовок, текст, нижний колонтитул, подписант) у каждого вида справки.
- **Запреты.** Прежняя система выдавала справки независимо от списка запретов на запись. Новая система не выдаёт справки студенту с запретом выдачи справок ([глава 20](20-registration.md)).
- Оплата не учитывается (прежняя система записывала только сумму).
- Онлайн-заказа справок студентами нет (план переноса 17.5). Справки выдают сотрудники.

## Виды и шаблоны

**Виды справок**: код (используется в регистрационном номере), название (на каждом языке), для кого (любое личное дело / студенты (не выпускники) / выпускники), с оценками, с фотографией, активен, порядок. Профиль корейского университета (`setup_install --profile=korean-university`) создаёт три вида с шаблонами на четырёх языках (корейский, английский, упрощённый китайский, лаосский). Если хотя бы один вид уже существует, он ничего не добавляет, поэтому ваши изменения сохраняются.

| Код | Вид | Для кого | Примечание |
|---|---|---|---|
| `ENR` | Справка об обучении | Студенты (не выпускники) | |
| `GRD` | Справка об окончании | Выпускники | Дата выпуска, номер диплома |
| `TRN` | Академическая справка | Любое личное дело | Таблица итоговых оценок по семестрам, накопленный средний балл и полученные кредиты |

**Шаблоны** (раздел **Шаблоны** внизу экрана редактирования вида): по одному на язык. Язык, заголовок, текст (абзацы разделяются пустой строкой), нижний колонтитул, подписант. В тексте используются подстановки в фигурных скобках.

| Подстановка | Значение |
|---|---|
| `{institution}` | Название учебного заведения (на этом языке) |
| `{student_name}`, `{student_number}` | ФИО (в форме для этого языка, иначе латиницей), студенческий номер |
| `{program}`, `{org_unit}` | Программа, подразделение |
| `{admission_date}`, `{graduation_date}`, `{degree_number}` | Дата зачисления, дата выпуска, номер диплома |
| `{status}`, `{year_level}` | Статус студента, курс |
| `{birth_date}`, `{gender}`, `{nationality}` | Дата рождения, пол, гражданство |
| `{issue_date}`, `{serial_number}`, `{purpose}`, `{copies}` | Дата выдачи, регистрационный номер, цель, число экземпляров |

Даты печатаются в формате этого языка (например, `October 24, 2026`, `2026년 10월 24일`). Отсутствующее значение (например, дата выпуска) печатается пустым; подстановка, которой нет в списке, остаётся как написана. Над текстом автоматически добавляется таблица личных данных (ФИО, студенческий номер, дата рождения, пол, гражданство, программа, дата зачисления, затем дата выпуска для выпускников или статус и курс для остальных). Вся справка (подписи таблицы, даты, статус) печатается на языке шаблона.

## Настройки

**Настройки > Настройки справок** (`Управлять видами справок, шаблонами и настройками`)

- **Шаблон регистрационного номера**: по умолчанию `{TYPE}-{YYYY}-{SEQ:6}` → `ENR-2026-000001`. Токены: `{TYPE}` (код вида), `{YYYY}` и `{YY}` (год выдачи в часовом поясе учебного заведения) и `{SEQ:n}` (n-значный порядковый номер). Обязателен ровно один `{SEQ:n}`, и после него может идти только обычный текст. Нумерация ведётся отдельно для каждого отличающегося префикса: `{TYPE}-{SEQ:6}` нумерует по видам сквозь годы, `{YYYY}{SEQ:5}` — по годам для всех видов. Одновременные выдачи никогда не конфликтуют (счётчик атомарно увеличивается в базе данных).
- **Срок проверки (дней)**: 0 — без ограничения. По истечении срока страница проверки отвечает «срок истёк». Сама выдача остаётся в журнале.
- **Подписант по языкам**: имя, печатаемое над печатью («Ректор Университета Ninefruits»), по одному полю на каждый язык учебного заведения. Подписант, указанный в шаблоне, имеет приоритет.

## Выдача

**Выдать справку** на экране личного дела студента: вид (активные), язык (языки учебного заведения), цель, число экземпляров (от 1 до 20). **Выдать справку** формирует и сохраняет PDF и возвращает к личному делу студента; уведомление показывает регистрационный номер со ссылкой **PDF**.

В выдаче отказывается (экран сообщает причину), если:

- вид справки не подходит по адресату (справка об обучении для выпускника, справка об окончании для обучающегося студента)
- вид справки неактивен
- для этого языка нет шаблона
- для студента действует **запрет выдачи справок** (ограничение, [глава 20](20-registration.md)); сначала снимите его. Запрет действует, даже если сотрудник не видит это ограничение.
- личное дело студента вне области действия просмотра или сотрудник не имеет права выдачи
- сервис PDF (Gotenberg) не отвечает: ничего не выдаётся и показывается «Не удалось создать PDF». Выдайте справку позже.

Выдача записывается в журнал действий (`certificate.issued`: студенческий номер, вид, язык, регистрационный номер, число экземпляров; цель — как причина).

## Выданные справки

**Справки > Выданные справки**: дата выдачи, регистрационный номер, вид и язык, студенческий номер, ФИО, цель, число экземпляров, статус, сотрудник, а также ссылки **PDF** и **Страница проверки** (новая вкладка). Фильтр по виду и статусу; поиск по регистрационному номеру, студенческому номеру или ФИО. Область действия просмотра такая же, как для личных дел студентов.

- **PDF**: открывает сохранённый файл. Он не формируется заново, поэтому в точности соответствует выданному.
- **Страница проверки**: открывает общедоступную страницу.
- **Сформировать заново** (меню строки): формирует новый PDF по текущим данным, например после исправления шаблона, и заменяет файл. Регистрационный номер и код проверки сохраняются; контрольная сумма меняется. Событие аудита `certificate.rerendered`. То же, что команда `certificate_render`. Аннулированные справки заново не формируются.
- **Аннулировать** (меню строки): требуется причина. Строка и файл сохраняются, статус становится «аннулирована», а страница проверки отвечает «аннулирована». Событие аудита `certificate.revoked`. Аннулированная справка не восстанавливается; выдаётся новая.

Строки журнала нельзя редактировать или удалять на экране (строка открывает подробности только для чтения с контрольной суммой).

## Проверка

- URL проверки (`{адрес учебного заведения}/verify/{code}/`) и QR-код печатаются внизу справки. Код — случайная строка из 20 символов (заглавные буквы и цифры); регистр не важен. Адрес берётся из переменной окружения `APP_URL`.
- Страница открывается без входа и ограничена 30 запросами в минуту с одного адреса (IP; сверх этого — HTTP 429). Поисковым системам предлагается её не индексировать (`noindex`). Она показывает, выдавалась ли справка, её вид, регистрационный номер, дату выдачи, а также замаскированные ФИО и студенческий номер. Для аннулированных, просроченных и неизвестных кодов выводятся разные ответы. Поле кода на странице также проверяет код (`/verify/?code=...`).
- Чтобы проверить сам представленный PDF-файл, сравните контрольную сумму (SHA-256) в подробностях журнала с хешем файла. Код также проверяет команда `uv run manage.py certificate_verify {code}` ([команды](../operations/commands.md)).
- Другие системы получают ту же проверку с теми же сведениями в виде JSON: `GET /api/v1/certificates/verify/<verification code>/` (без входа, 30 запросов в минуту с одного адреса, [руководство по интеграции с LMS](../../../lms-integration-guide.md)).

## Портал студента

**Справки** (меню студентов и выпускников): справки, выданные по собственному личному делу студента (дата выдачи, вид и язык, регистрационный номер, статус), с PDF-файлами. Аннулированные справки показываются в списке со своим статусом, но без ссылки на PDF, и скачать PDF аннулированной справки студент не может (выдавший сотрудник может открыть его для проверки записи). Файлы других студентов открыть нельзя (это обеспечивают приложение и база данных). Адрес PDF — `/certificates/{issue id}/download/`.

## Частые вопросы

- **Имя написано неправильно.** Исправьте вариант имени лица (на этом языке) и нажмите **Сформировать заново**. Если справка уже передана, аннулируйте её и выдайте новую.
- **Я изменил шаблон; что будет с уже выданными справками?** Они не меняются. При необходимости используйте **Сформировать заново** (для многих сразу — команда `certificate_render`).
- **Регистрационный номер пропущен.** Если при выдаче происходит ошибка (например, недоступен сервис PDF), номер расходуется, а строка журнала не остаётся. Гарантируется уникальность номеров, но не их непрерывность.
- **QR-код указывает на `localhost`.** Задайте на рабочем сервере в `APP_URL` адрес учебного заведения, затем выполните **Сформировать заново** для затронутых справок.

## Экраны этой установки

Экраны и функции те же, что и в исходной системе (Filament, Livewire); порядок работы с ними немного отличается.

- **Выдать справку** открывает страницу с формой вместо диалога. Исходная система после выдачи открывала PDF в новой вкладке; здесь происходит возврат на экран личного дела студента, а PDF открывается по ссылке **PDF** в уведомлении.
- В журнале **PDF** и **Страница проверки** — ссылки в конце строки; **Сформировать заново** (страница подтверждения) и **Аннулировать** (страница для причины) находятся в меню строки. Повторное формирование работает только для неаннулированных справок.
- Шаблоны редактируются внизу экрана редактирования вида. Два шаблона для одного языка не принимаются. Только с разрешением `Просматривать справочные данные` виды и шаблоны доступны только для чтения.
- Если при выдаче сервис PDF не отвечает, ничего не выдаётся (в исходной системе могла остаться строка журнала без PDF).
- Разрешение на выдачу учитывается, только если оно назначено глобально (исходная система пропускала назначение с областью действия на экране, а затем база данных отклоняла строку с ошибкой).
- В демонстрационных данных (`setup_demo`) `certificate-officer@demo.test` показывает журнал, а `student@demo.test` — раздел **Справки** на портале.
