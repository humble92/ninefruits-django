# 15. Способы входа

Меню: **Настройки > Способы входа** (разрешение `Управлять способами входа и SSO`)

## Имя для входа

По умолчанию именем для входа служит адрес эл. почты учётной записи. Если включён вход по студенческому номеру, поле на экране входа называется «Эл. почта или студенческий номер».

| Вход по студенческому номеру | Поведение |
|---|---|
| Не разрешено | Только эл. почта |
| Только обучающиеся студенты | Можно войти по студенческому номеру личных дел со статусом «обучается» или «в академическом отпуске» |
| Обучающиеся студенты и выпускники | Можно войти также по студенческим номерам завершённых личных дел (выпуск, отчисление и т. п.) |

Лицо, у которого несколько личных дел студента, попадает в одну и ту же учётную запись, какой бы студенческий номер оно ни использовало.

## Блокировка учётной записи

| Параметр | Описание |
|---|---|
| Блокировать после неудачных попыток | Учётная запись блокируется после указанного числа неверных паролей подряд. 0 отключает блокировку |
| Длительность блокировки (минут) | По истечении этого времени блокировка снимается автоматически |

Попытки по эл. почте и по студенческому номеру считаются неудачами одной и той же учётной записи. Для заблокированной учётной записи выводится то же сообщение, что и при неверном пароле, поэтому по нему нельзя понять, существует ли учётная запись. Блокировки записываются как событие безопасности (**Вход заблокирован**).

Чтобы снять блокировку досрочно, используйте **Разблокировать вход** на странице сведений в разделе **Пользователи** (требуется причина, разрешение `Редактировать пользователей`). Если панель администрирования недоступна, ИТ-оператор выполняет `uv run manage.py security_unlock_user`.

## Вход через вуз (SSO)

После регистрации входа вуза по OpenID Connect (например, Microsoft Entra ID, Google Workspace, Keycloak) на экране входа появляется кнопка «Войти через ...».

| Поле | Описание |
|---|---|
| Ключ | Идентификатор строчными буквами, например `school`. Его изменение разрывает существующие связи |
| Надпись на кнопке | Название, отображаемое на экране входа |
| URL издателя (issuer) | Issuer провайдера. По этому адресу должен быть доступен `/.well-known/openid-configuration` |
| Client ID, Client secret | Значения, полученные при регистрации приложения у провайдера. Секрет хранится в зашифрованном виде |
| Области доступа (scopes) | По умолчанию `openid email profile` |
| Считается двухфакторной аутентификацией | Включайте, только если сам вход через вуз требует двухфакторной аутентификации. Если параметр включён, при этом способе входа двухфакторная аутентификация здесь повторно не запрашивается |
| Redirect URI для регистрации у провайдера | Зарегистрируйте показанный на экране адрес (`https://<server>/auth/sso/<key>/callback/`) в настройках приложения у провайдера в точности как есть |

### Связывание учётных записей

| Режим | Поведение |
|---|---|
| Пользователи связывают учётные записи сами | Пользователь входит по паролю и нажимает **Связать** в разделе **Безопасность > Вход через вуз** на портале (требуется подтверждение пароля) |
| Автоматически по подтверждённой эл. почте вуза | Если подтверждённый провайдером адрес эл. почты совпадает с вузовской эл. почтой в личном деле студента, учётная запись связывается автоматически при первом входе |

- При входе с несвязанной вузовской учётной записью выводится уведомление о том, что нужно войти по паролю и связать её. Одна лишь вузовская учётная запись никогда не создаёт новую учётную запись.
- Связывание и отмена связи записываются в журнал безопасности.

### Разрешение входа по паролю

Если отключить **Разрешить пароли пользователям со входом через вуз**, связанные пользователи смогут входить только через вуз. Поскольку вузовские учётные записи часто удаляются после выпуска, рекомендуем оставить параметр включённым и просить студентов, которые скоро выпускаются, заранее подготовить личную эл. почту и пароль. Выпускники продолжают входить по эл. почте для входа учётной записи (личной эл. почте) и паролю.
