# 27. Отчёты и представления reporting

Меню: **Отчёты > Отчёты** (разрешение `Просматривать и скачивать стандартные отчёты`). Роли по умолчанию: сотрудник учебного отдела (Registrar), сотрудник учебного управления (Academic Affairs), методист кафедры (в пределах области действия).

## Стандартные отчёты

Выберите отчёт и его фильтры: на экране показывается до 500 строк, а **Скачать CSV** выгружает их все (UTF-8 с BOM, файл сразу открывается в Excel). Скачивания записываются в событие аудита `reports.exported` и в событие журнала безопасности `data.exported` (отчёт, фильтры, число строк). Значения, начинающиеся с `=`, `+`, `-`, `@` (или с табуляции или перевода строки), выгружаются с ведущим апострофом (`'`), чтобы Excel не выполнял их как формулы.

| Отчёт | Фильтры | Содержание |
|---|---|---|
| Список студентов | Подразделение (включая подчинённые), статус, курс | Студенческий номер, ФИО, программа, подразделение, курс, статус, дата зачисления, дата выпуска, номер диплома |
| Контингент по подразделениям, программам, курсам и статусам | Подразделение, статус | Число студентов |
| Сводка оценок за семестр | Семестр, академический статус | Кредиты и средний балл за семестр и накопленные, число академических предупреждений, место среди отличников ([глава 21](21-grades.md)) |
| Кандидаты на выпуск | Выполнено или нет | Последняя проверка требований к выпуску по каждому студенту и программе ([глава 26](26-graduation.md)) |
| Изменения статуса | Семестр, период | Вид изменения, статусы до и после, дата вступления в силу, статус заявки |
| Записавшиеся по группам | Семестр, подразделение | Группа, преподаватели, число мест, записано, в ожидании |
| Студенты, не записавшиеся на дисциплины в семестре | Семестр, подразделение | Обучающиеся студенты без записи на дисциплины в этом семестре |

Видимые данные определяются областью действия разрешений пользователя (область действия просмотра личных дел студентов и т. п.). Отчёты прежней системы (YUSTIC) по сборам и оплате обучения (неоплата обучения и т. п.) не входят в охват и отсутствуют.

## Представления reporting

Отчёты читают представления схемы `reporting` в базе данных. BI-инструменты и пользователи SQL обращаются к тем же представлениям через роль только для чтения `app_reporting`.

| Представление | Содержание |
|---|---|
| `reporting.students` | Личное дело студента + имя лица + названия программы и подразделения |
| `reporting.headcount` | Контингент по подразделениям, программам, курсам и статусам |
| `reporting.term_records` | Сводка оценок по семестрам |
| `reporting.course_grades` | Оценки по дисциплинам (итоговая или нет, оценка, сдано, повторное изучение) |
| `reporting.section_enrollments` | Записанные и ожидающие по группам, преподаватели |
| `reporting.section_meetings` | Время занятий и аудитории |
| `reporting.status_changes` | Изменения статуса |
| `reporting.degree_audits` | Последняя проверка требований к выпуску по каждому студенту и роли программы |

- Переведённые столбцы (`program_name` и т. п.) следуют локали сеанса: `SET app.locale = 'ko';`. Доступны и исходные столбцы jsonb (`program_name_i18n` и т. п.).
- Представления имеют атрибут `security_invoker`, поэтому к пользователю без изменений применяется защита на уровне строк. При чтении под учётной записью студента они возвращают только строки этого студента.
- Определения представлений находятся в `db/sql/views/reporting.sql` (исходный `database/sql/views/reporting.sql` без изменений); после изменения они применяются повторно из миграции `core`. Приложение читает их через неуправляемые модели (`ninefruits.reporting.models`, например `ReportStudent`).

Прежние представления `AV_*` (около 90) не использовались и не переносились.

## Экраны этой установки

- **Отчёты > Отчёты** (`/admin/reports/`): выберите отчёт и нажмите **Показать**, чтобы вывести его фильтры (исходная система меняла их сразу при выборе отчёта). Заполните фильтры и снова нажмите **Показать**. В отчёте с фильтром семестра нет строк, пока семестр не выбран.
- Адрес CSV — `/reports/{report}.csv?filter=value` (например, `/reports/students.csv?status=enrolled`). Принимаются только перечисленные названия отчётов и фильтров, а столбцы и порядок сортировки зафиксированы определением отчёта.
- Время в CSV (аудит, решение) записывается, как в исходной системе, текстом PostgreSQL в UTC (`2026-10-24 07:26:59+00`); даты — `YYYY-MM-DD`, истина/ложь — `Y`/`N`.
- Фильтр подразделения в отчёте «Записавшиеся по группам» фильтрует по коду подразделения (в представлении нет ID подразделения). В исходной системе выбор этого фильтра приводил к ошибке.
- У групп и времени занятий нет защиты на уровне строк, поэтому показываются все строки групп. Число записавшихся и ожидающих учитывает только записи и места в листе ожидания, которые может видеть читатель.
