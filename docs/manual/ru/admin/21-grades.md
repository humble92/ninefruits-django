# 21. Оценки

Меню: **Оценки > Ход выставления оценок**, **Запросы на смену способа оценивания**, **Изменения оценок**, **Итоги семестров**, **Настройки > Правила оценивания**. Преподаватели используют на портале **Мои дисциплины > Ввести оценки**.

| Разрешение | Что позволяет |
|---|---|
| `Просматривать оценки, ход выставления оценок и итоги семестров` | Просмотр хода выставления оценок, итогов семестров и ведомостей оценок студентов |
| `Утверждать и возвращать оценки, вводить оценки за преподавателей, закрывать семестры` | Утверждение или возврат оценок группы, ввод оценок за преподавателей (независимо от периода), отправка оценок с превышением квот в порядке исключения, закрытие семестров, пересчёт. При назначении с областью действия «подразделение» — только группы, открываемые этим подразделением |
| `Получать уведомления, когда сотрудники отправляют оценки с превышением квот` | Получение уведомлений об отправке в порядке исключения. Назначается с областью действия «подразделение» заведующим кафедрами и руководителю учебного управления |
| `Запрашивать изменение итоговой оценки` | Запрос изменений для групп, которые сотрудник не ведёт (например, аннулирование оценки за нарушение академической честности) |
| `Одобрять или отклонять изменения оценок (кроме собственных запросов)` | Принятие решений по запросам на изменение оценок |
| `Управлять правилами среднего балла, повторного изучения, академического статуса и отличия` | Настройки правил оценивания |

Преподаватели вводят оценки и запрашивают изменения для своих групп без каких-либо разрешений. Роли по умолчанию: у сотрудника учебного отдела (Registrar) есть просмотр, утверждение, одобрение и получение уведомлений об исключениях; у сотрудника учебного управления (Academic Affairs) — просмотр, запросы на изменение и правила; у ответственного за справки и методиста кафедры — просмотр. Решения по запросам на смену способа оценивания принимаются с разрешением `Планировать группы`.

## Отличия от прежней системы

- В прежней системе (YUSTIC) оценка, сохранённая преподавателем, сразу становилась окончательной, а учебное управление правило её прямо на экране. Не было ни причины, ни шага одобрения, а правки некоторых учётных записей даже не попадали в резервные записи. В новой системе есть этапы **ввод → отправка → утверждение**, и итоговая оценка меняется только тогда, когда **запрос на изменение одобряет другой человек**. Это обеспечивают и приложение, и база данных (триггеры).
- В прежней системе преподаватель мог, подменив запрос, сохранить оценки для групп, которые он не ведёт. Новая система проверяет назначенных преподавателей и область действия разрешений на сервере и в базе данных.
- Средний балл, академические предупреждения и отличия не вычисляются на лету на каждом экране; они хранятся как **итоги семестра**. При закрытии семестра они становятся официальными данными этого семестра.
- При повторном изучении прежняя оценка исключается из накопленного среднего балла только **после утверждения новой оценки** (прежняя система исключала её при записи и не возвращала при отмене группы).
- Прежняя система лишь отключала меню оценок; оценки были видны по адресу. Новая система применяет запрет просмотра оценок на сервере.

## Порядок работы в семестре

1. **Периоды семестра** ([глава 10](10-terms.md)): период **Ввод оценок** для каждого учебного периода. Преподаватели вводят и отправляют оценки только в этот период.
2. Преподаватели вводят и отправляют оценки. `uv run manage.py grades_remind_missing {term}` отправляет письма-напоминания преподавателям, которые ещё не отправили оценки.
3. В разделе **Ход выставления оценок** утвердите оценки каждой группы или верните их преподавателю.
4. Когда оценки всех групп утверждены, выполните **Итоги семестров > Закрыть семестр**. Определяются итоги семестра, академический статус и отличия, и семестр переходит в статус **Оценки закрыты**.
5. Изменения оценок после этого проходят через **Изменения оценок**.

## Шкала оценок и способ оценивания

**Шкала оценок фиксируется при установке и не может быть изменена** (решение от 2026-10-23), поскольку все оценки и средние баллы опираются на эту шкалу. Задайте её командой `uv run manage.py setup_install --grade-scale=4.5|4.3`; иначе используется шкала первого профиля (корейский университет — 4.5, прежний YUST — 4.3). Отметку **По умолчанию** в разделе Справочные данные > Шкалы оценок перенести нельзя, а шкалу по умолчанию нельзя удалить. **Диапазоны баллов** (нижняя и верхняя границы в %) и баллы каждой оценки редактируются на этом экране ([глава 11](11-course-categories-and-grade-scales.md)).

У каждой группы есть **способ оценивания**. По умолчанию — **Абсолютное оценивание**.

| Способ оценивания | Что вводит преподаватель | Что хранится | Условие отправки |
|---|---|---|---|
| Абсолютное оценивание (по умолчанию) | **Балл (0–100)** для каждого студента. Оценка следует из диапазона баллов и не выбирается (напрямую выбираются только оценки без балла, например I) | Балл (исходный), оценка, баллы оценки | Оценка у каждого студента |
| Относительное оценивание | **Оценка** для каждого студента. Баллы не вводятся (при вводе — отказ) | Оценка, баллы оценки | Оценка у каждого студента + соблюдены **квоты оценок** |
| Дисциплина с зачётом/незачётом | P/NP независимо от способа оценивания | Оценка | Оценка у каждого студента |

- Преподаватель, который хочет использовать относительное оценивание, нажимает **Запросить: Относительное оценивание** (с причиной) на экране ввода оценок. Обладатель разрешения `Планировать группы` для открывающего подразделения (методист кафедры, учебное управление) одобряет или отклоняет запрос (комментарий обязателен) в разделе **Оценки > Запросы на смену способа оценивания**, и преподаватель получает уведомление по эл. почте. При одобрении черновые оценки, введённые прежним способом, удаляются. После **отправки** оценок ни запрос, ни смена невозможны. Сотрудники могут изменить способ и на экране группы, но только до ввода оценок.
- Наивысшая оценка при повторном изучении: при абсолютном оценивании балл, который дал бы оценку выше предельной, **понижается до предельной оценки** (сам балл сохраняется). При относительном оценивании оценку выше предельной выбрать нельзя.

## Квоты оценок (относительное оценивание)

**Настройки > Правила оценивания > Относительное оценивание**: квота для каждой группы оценок (по умолчанию группа A — 30 %, группа B — 40 %), допуск сверх квоты (по умолчанию 1 процентный пункт), минимальное число студентов с оценками для проверки (по умолчанию 10).

- Группы оценок формируются по букве: A+, A0 и A- составляют группу A; B+, B0 и B- — группу B. Группы без квоты (C, D, F) не ограничены.
- Знаменатель — число студентов группы с оценкой, учитываемой в среднем балле. Вышедшие из дисциплины студенты и P/NP/I не учитываются.
- Группы с числом студентов меньше минимального не проверяются (30 % A из 7 студентов выполнить невозможно).
- Преподаватели видят текущее распределение относительно квот кнопкой **Проверить квоты оценок** на экране ввода оценок и **не могут отправить** оценки с превышением квот.
- Сотрудники с разрешением на управление оценками могут отправить оценки с превышением квот, но только как **отправку в порядке исключения**: причина обязательна, распределение и причина записываются в журнал действий, обладатели разрешения `Получать уведомления, когда сотрудники отправляют оценки с превышением квот` (заведующие кафедрами, руководитель учебного управления, назначены с областью действия «подразделение») получают письмо, а группа помечается как **Отправлено как исключение**. **Ход выставления оценок** можно отфильтровать, оставив только отправки в порядке исключения.

## Ввод оценок (преподаватели)

На портале в разделе **Мои дисциплины** откройте **Ввести оценки** нужной группы. В верхней части экрана показаны способ оценивания группы, указания по вводу и запрос на смену способа оценивания.

- Абсолютное оценивание: оценка появляется сразу после ввода балла.
- Относительное оценивание: выбирается только оценка. Столбца баллов нет. Проверьте квоты кнопкой **Проверить квоты оценок** и отправьте.
- Список оценок зависит от способа оценивания дисциплины. Для дисциплин с дифференцированной оценкой показываются буквенные оценки, для дисциплин с зачётом/незачётом — P/NP ([глава 11](11-course-categories-and-grade-scales.md)).
- **Сохранить черновик** можно в любое время. Студенты черновые оценки не видят.
- Для **Отправить оценки** нужна оценка у каждого студента. После отправки преподаватель больше не может их изменить. Если оценка неверна, попросите учебное управление вернуть оценки до утверждения или запросите изменение после него.
- Вышедшие из дисциплины студенты отображаются как W и оценку не получают.

## Утверждение и возврат (учебное управление)

**Ход выставления оценок**: группы семестра с числом неотправленных, отправленных и итоговых оценок. Фильтр **Готово к утверждению** показывает только группы, где отправлены оценки всех студентов.

- **Утвердить**: утверждает отправленные оценки. Записи на дисциплины переходят в статус **Завершено**, и студенты видят свои оценки. Итоги семестра студентов пересчитываются. Можно выбрать несколько групп и утвердить их кнопкой **Утвердить выбранные**. Группы, где оценка хотя бы одного студента ещё не отправлена, пропускаются.
- **Вернуть преподавателю**: отменяет отправку с указанием причины. Оценки возвращаются в черновик, и преподаватель получает письмо.
- **Оценки**: открывает экран ввода оценок. Учебное управление может вводить и менять оценки до утверждения независимо от периода. Когда сотрудник меняет оценку, которую преподаватель уже **отправил**, старое и новое значения записываются в событие аудита `grades.submitted_changed`.

## Изменения оценок

Единственный способ изменить итоговую оценку.

1. Запрос: преподаватель нажимает **Запросить изменение** для студента на экране ввода оценок (с причиной; при абсолютном оценивании — новый балл, при относительном — новая оценка). Предельная оценка при повторном изучении действует и для изменений. Для групп, которые они не ведут, сотрудники с разрешением `Запрашивать изменение итоговой оценки` подают запрос на том же экране. На одну оценку — только один открытый запрос.
2. Решение: в разделе **Оценки > Изменения оценок** (по умолчанию — список ожидающих; в меню показывается их число) нажмите **Одобрить** или **Отказать** (комментарий обязателен). Автор запроса не может принимать решение по собственному запросу (это также обеспечивается ограничением базы данных).
3. При одобрении оценка (при абсолютном оценивании — балл и оценка) меняется сразу, а итоги семестра студента и накопленный средний балл последующих семестров пересчитываются. Академический статус и отличия сохраняют значения, определённые при закрытии семестра.

Автор может нажать **Отменить запрос**, пока запрос ожидает решения. Каждый запрос и решение записываются в журнал действий вместе с причиной.

## Расчёт среднего балла

| Элемент | Правило |
|---|---|
| Записанные кредиты | Все дисциплины с итоговой оценкой (включая F, P, NP, I) |
| Полученные кредиты | Положительные оценки (кроме F, NP, I) |
| Кредиты в среднем балле | Оценки, учитываемые в среднем балле. F учитывается с 0 баллов; P/NP/I исключаются |
| Средний балл | Сумма (баллы оценки × кредиты) ÷ кредиты в среднем балле. У семестра только с дисциплинами с зачётом/незачётом среднего балла нет |
| Знаков после запятой | Число знаков и способ округления (округление половины вверх, отбрасывание) задаются правилами. Вычисления в целых числах, поэтому на границах нет ошибок (например, 3.4375 → 3.438) |
| Средний балл за семестр | Все оценки этого семестра (прежняя оценка, заменённая повторным изучением, по-прежнему учитывается в среднем балле своего семестра) |
| Накопленный средний балл | Повторно изученная дисциплина учитывается только один раз, согласно правилам: **Последняя попытка** (по умолчанию; последняя, даже если она хуже) или **Лучшая попытка**. Заменённая оценка исключается и из накопленных кредитов и показывается на экране оценок как «заменено повторным изучением в накопленном среднем балле» |

Связь повторного изучения устанавливается при записи на дисциплины ([глава 20](20-registration.md)): повторная запись на ту же или эквивалентную дисциплину связывает её с прежней записью.

## Академический статус и отличия (закрытие семестра)

| Правило | По умолчанию | Профиль прежнего YUST |
|---|---|---|
| Порог предупреждения | Средний балл за семестр ниже 1.75 | Ниже 1.3 |
| Учитывать только основные семестры | Да | Да |
| Число предупреждений для рассмотрения отчисления | 0 (выключено) | 4 |
| Учитывать только предупреждения подряд | Нет (общее число) | Нет |
| Минимальный средний балл и минимум кредитов в среднем балле для отличия | 4.0, 15 кредитов | 0, 0 (прежняя система просто брала первых N) |
| Без отличия при несданной дисциплине | Да | Нет |
| Знаков после запятой в среднем балле | 2, округление половины вверх | 3, округление половины вверх |
| Шкала оценок (фиксируется при установке) | 4.5 (KR45) | 4.3 (YUST43) |
| Квоты оценок (относительное оценивание) | A 30 %, B 40 %, допуск 1 процентный пункт, проверка начиная с 10 студентов | То же |

- **Академическое предупреждение**: средний балл за семестр **ниже** порога. Семестр только с дисциплинами с зачётом/незачётом предупреждения не даёт.
- **Рассмотрение отчисления**: отметка ставится, когда число предупреждений достигает порога. Само отчисление оформляется как изменение статуса ([глава 13](13-status-changes-and-advisors.md)).
- Если учитываются только основные семестры, у летних и зимних семестров нет академического статуса, и они не прерывают серию предупреждений подряд.
- **Отличие**: студенты, удовлетворяющие критериям, ранжируются внутри программы по среднему баллу за семестр (при равенстве место общее; следующее место пропускается).
- **Академический статус** в личном деле студента меняется на последний результат. Критерий «академический статус» периодов семестра и условий допуска в группу использует это значение.

На экране **Итоги семестров** отфильтруйте по семестру, академическому статусу, отличию и программе, чтобы получить список студентов с академическим предупреждением и список отличников (прежние отчёты о предупреждениях и отличиях). Сначала выполните **Закрыть семестр** с параметром **Только предпросмотр** (по умолчанию), чтобы увидеть группы с неитоговыми оценками, затем выключите его и выполните снова. **Пересчитать** применяет изменённые правила к итогам прошлых семестров (требуется причина).

## Экран студента и ведомость оценок

Когда сотрудник открывает ведомость оценок студента, это записывается в событие аудита `transcript.viewed` (со студенческим номером).

- **Оценки** на портале: итоговые оценки по семестрам (выход из дисциплины — W), средний балл за семестр и полученные кредиты, накопленный средний балл, академический статус, отличие. Выпускники тоже могут их видеть. Неитоговые оценки не показываются.
- **Печать**, **PDF**: неофициальная ведомость оценок для проверки. PDF формируется сервисом Gotenberg. Официальная академическая справка выдаётся как справка ([глава 23](23-certificates.md)). Сотрудники открывают ведомость оценок студента кнопкой **Ведомость оценок** на экране личного дела студента или в разделе «Итоги семестров» (разрешение `Просматривать оценки`).
- Студент, у которого в **ограничении** включено **Запрещает просмотр оценок**, не видит экран оценок и ведомость оценок ([глава 20](20-registration.md)).
- В период анкетирования по дисциплинам у студента, не завершившего анкетирование по дисциплинам семестра, оценки этого семестра скрыты (настраивается, [глава 22](22-course-evaluation.md)).

## Правила оценивания

**Настройки > Правила оценивания** (разрешение `Управлять правилами среднего балла, повторного изучения, академического статуса и отличия`). Изменяет параметры из таблицы выше. Изменённые правила применяются начиная со следующего расчёта. Чтобы применить их к итогам прошлых семестров, используйте **Пересчитать**. Академический статус и отличия определяются при закрытии семестра, поэтому к закрытому семестру повторно не применяются.

## Экраны в этой установке

Экраны и функции те же, что и в исходной системе (Filament, Livewire); порядок работы с ними немного отличается.

- Меню строки в **Ход выставления оценок**: **Оценки** (экран ввода оценок на портале), **Утвердить** (экран подтверждения), **Вернуть преподавателю** (экран для причины). Чтобы утвердить несколько групп, выберите их в списке и выберите **Утвердить выбранные** в списке действий. Фильтры: семестр (по умолчанию — текущий семестр, **Все** — все семестры), подразделение-организатор, отправлено как исключение, готово к утверждению.
- **Одобрить** и **Отказать** в меню строки разделов **Изменения оценок** и **Запросы на смену способа оценивания** открывают экран для комментария. Список по умолчанию показывает ожидающие запросы, а в меню показывается их число.
- **Закрыть семестр** над списком **Итоги семестров**: семестр, **Только предпросмотр** (по умолчанию включено), причина. Предпросмотр показывает в сообщениях, можно ли закрыть семестр, и группы с неитоговыми оценками (до 30). Запущенное закрытие выполняется задачами в очереди (Celery) по 100 студентов; ход выполняющегося закрытия показывается над списком итогов семестров. По завершении семестр переходит в состояние **Оценки закрыты**, а сотрудник, запустивший закрытие, получает письмо. Если задача завершилась с ошибкой, закрытие не завершается и семестр остаётся как был; устраните причину и закройте снова (результат будет тем же). Из командной строки: `uv run manage.py term_close {term} --dry-run`, `uv run manage.py term_close {term} --reason=...` ([команды](../operations/commands.md)).
- В **Правила оценивания** квоты оценок записываются буквами и процентами через запятую, например `A=30, B=40`. Пусто — без квоты.
- Ввод оценок на портале: при абсолютном оценивании оценка появляется рядом с баллом вскоре после ввода. **Сохранить черновик**, **Проверить квоты оценок** и **Отправить оценки** находятся внизу экрана; если сохранение не удалось (например, балл вне допустимого диапазона), введённые значения показываются снова вместе с ошибкой. **Запросить изменение** в строке студента открывает поля запроса под таблицей.
- Адрес ведомости оценок для сотрудников: `/student-records/{student record id}/transcript/` (кнопка **Ведомость оценок** на экране личного дела студента, **Ведомость оценок** в строке итогов семестра). Добавьте `?format=pdf`, чтобы получить PDF.
- Для группы, связанной с LMS, экран ввода оценок может загрузить баллы из LMS как черновик ([глава 28](28-lms-integration.md)). Оценки семестра, в котором анкетирование по дисциплинам открыто и не завершено, скрываются с уведомлением и ссылкой на **Анкетирование по дисциплине** ([глава 22](22-course-evaluation.md)).
