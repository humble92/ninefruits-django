# 25. 교수 강의실과 출석

메뉴: 교원은 포털 **담당 강좌 > 수강생과 출석**(`/portal/sections/{개설강좌 ID}/attendance/`), 학생은 포털 **출석**(`/portal/attendance/`). 직원은 관리 화면 **교육과정과 개설 > 개설강좌 > 수정** 화면의 **수업 회차** 탭.

| 누가 | 할 수 있는 일 |
|---|---|
| 담당 교원 | 수강생 명단(사진 포함)과 CSV, 출석부 PDF, 수업 회차 생성·추가·휴강, 출석 입력 |
| `개설강좌 편성` 직원(범위 안) | 교원과 같음 + 관리 화면의 수업 회차 |
| `개설강좌 조회` 직원(범위 안) | 명단, 출석부, 출석 조회 |
| 학생 | 자기 출석 |

공지, 과제, 자료 같은 강의실 기능은 LMS로 넘긴다(이식 계획 12절).

## 레거시와 다른 점

- **레거시는 출석을 기록하지 않았다.** "출석부"는 수강생 명단 옆에 빈 칸(27~34칸, 복사본마다 다름)을 그려 인쇄하는 PDF였고, 날짜도 집계도 없었다. 신규 시스템은 **수업 회차**를 강의 시간에서 만들고 회차마다 출석·지각·결석·공결을 기록하며, 출석부 PDF에 기록과 합계를 찍는다.
- **명단.** 레거시 교수 화면은 학번·이름만 보였고(팝업에서 주민번호·주소까지 노출), 엑셀 내려받기는 없었다. 신규 시스템은 학번, 이름, 사진, 과정, 학년, 연락용 이메일만 보여 주고 CSV로 내려받는다. 내려받기는 감사에 남는다.
- **교원의 수강생 조회 권한.** 담당 강좌 수강생의 학적·인물을 교원이 볼 수 있도록 RLS 정책(`student_records_instructor_select`, 함수 `util.taught_student_record_ids()`)이 있고, 애플리케이션의 조회 범위도 같다(이전 원본에는 지도 학생만 보여 성적 입력 화면에서도 이름이 비는 결함이 있었다).

## 수업 회차

- **생성**: 강의 시간(요일·시간·기간)의 요일마다 회차를 하나씩 만든다. 교원은 **강의 시간으로 회차 생성** 버튼, 직원은 관리 화면 **수업 회차** 탭 위의 **회차 생성** 버튼(확인 화면) 또는 명령 `uv run manage.py attendance_generate_sessions {학기}`(학기 전체)로 한다. 이미 있는 회차와 출석은 그대로 두므로 강의 시간을 고친 뒤 다시 실행해도 된다. 폐강된 개설강좌는 건너뛴다.
- **추가**: 보강처럼 강의 시간 밖의 수업(**회차 추가**: 날짜, 시작, 종료). 세션 기간 안의 날짜만, 같은 날짜·시작 시간의 회차는 하나만.
- **휴강**: 사유를 적고 휴강 처리. 회차는 남고 집계에서 빠진다. **되돌리기**로 복구.
- 공휴일 달력은 없다. 공휴일 회차는 휴강 처리한다(추후 학기 달력이 들어오면 생성기에서 제외).

## 출석 입력

회차의 **출석 입력**에서 학생마다 출석/지각/결석/공결을 고르고 비고(200자)를 적은 뒤 **출석 저장**. **전원 출석**(저장하지 않고 모두 출석으로 표시) 뒤 예외만 바꾸는 방식이 빠르다.

- 수업 당일부터 입력할 수 있다(미래 회차, 휴강 회차 불가).
- 다시 저장하면 바뀐 학생만 기록되고, 감사 기록(`attendance.recorded`)에 학생별 이전 값과 새 값이 남는다.
- 상태를 비우면 "미입력"으로 돌아간다.
- 수강 중이거나 이수한 학생만 입력할 수 있다(취소·철회한 학생은 명단에 없다).

## 집계

| 항목 | 정의 |
|---|---|
| 진행 회차 | 휴강이 아닌, 오늘 이전(당일 포함)의 회차 |
| 출석률 | (출석 + 지각 + 공결) ÷ 진행 회차 × 100, 소수 첫째 자리(반올림) |
| 미입력 | 진행 회차 중 기록이 없는 수 |

지각을 몇 회 결석으로 환산하거나 결석이 1/3을 넘으면 F로 처리하는 규칙은 두지 않았다. 대학마다 달라서 교원이 성적에 반영한다. 집계 규칙은 서비스 한 곳(`AttendanceSummary`)에 있어 명단, 출석부, 학생 화면이 같은 값을 보인다.

## 출석부 PDF와 명단 CSV

둘 다 내려받기가 감사에 남는다(`attendance.sheet_exported`, `attendance.roster_exported`). CSV의 `=`, `+`, `-`, `@`(그리고 탭, 줄 바꿈)로 시작하는 값은 수식으로 실행되지 않도록 작은따옴표를 붙여 내보낸다.

- **출석부(PDF)** (`/sections/{개설강좌 ID}/attendance-sheet`): 가로 A4. 학생 세로, 회차 가로(휴강 제외), O/△/X/공 표시와 학생별 합계. 아직 오지 않은 회차는 빈칸이라 수기 기록용으로도 쓴다. PDF 서버(Gotenberg)가 응답하지 않으면 "PDF를 만들지 못했습니다"가 보인다.
- **명단(CSV)** (`/sections/{개설강좌 ID}/roster.csv`): 학번, 이름, 과정, 학년, 연락용 이메일, 수강 상태. UTF-8(BOM)이라 엑셀에서 바로 열린다.

## 학생 포털

**출석**: 학기별(기본은 시작한 가장 최근 학기) 수강 과목의 출석·지각·결석·공결 수와 출석률, 펼치면 진행 회차별 기록(교원이 입력한 것만, 없으면 "미입력").

## 운영 절차

1. 학기 시작 전 개설강좌의 강의 시간을 확정한다([18장](18-sections-and-timetables.md)).
2. `uv run manage.py attendance_generate_sessions {학기} --actor=...`로 회차를 만든다(교원이 화면에서 직접 만들어도 된다). 한 강좌만은 `--section=CSE2010-01`, 대상 강좌 수만 보려면 `--dry-run`([운영 명령](../operations/commands.md)).
3. 강의 시간이 바뀌면 다시 실행한다. 없어진 시간의 회차는 자동으로 지워지지 않으므로 휴강 처리한다.

## 이 설치본의 화면

원본(Filament, Livewire) 화면과 기능은 같고 조작 방식이 조금 다르다.

- 관리 화면 개설강좌 수정 화면의 **수업 회차** 탭: 날짜, 시간, 강의실, 상태, 입력 수, 사유. 행의 **휴강**은 사유 입력 화면을, **되돌리기**는 확인 화면을 연다. **회차 생성**은 화면 위 동작 버튼이다. `개설강좌 조회`만 있는 직원은 탭을 볼 수 있지만 버튼은 없다.
- 교원 포털의 **휴강**은 회차 행에서 펼쳐지는 사유 칸에 적고 다시 **휴강**을 누른다(원본의 브라우저 입력 창 대신).
- **출석 입력** 화면 주소는 `?meeting={회차 ID}`로 끝나 즐겨찾기할 수 있다. **뒤로**는 명단과 회차 목록으로 돌아간다.
- 행 수준 보안 아래에서 명단은 수강 행과 학적을 볼 수 있는 사람에게만 채워진다. 기본 역할(교무 담당, 학과 조교)은 `수강 현황과 수강생 명단 조회`와 `학적 조회` 권한을 함께 가진다. `개설강좌 편성`만 준 역할은 명단과 출석부가 비어 보인다(원본도 같다).
