# 3. 2단계 인증

## 사용자가 등록하는 방법

포털 **보안** 화면(`/portal/security/`, 관리 화면 사용자 메뉴 **2단계 인증**)에서 한다. 등록, 해제 전에 비밀번호를 한 번 더 확인한다.

### 인증 앱 (권장)

1. **2단계 인증 사용**을 누른다.
2. Google Authenticator, Microsoft Authenticator 등 인증 앱으로 QR 코드를 스캔한다.
3. 앱에 표시된 6자리 코드를 입력하고 **확인**을 누른다.
4. 화면에 나온 **복구 코드**를 안전한 곳에 보관한다. 휴대폰을 잃어버렸을 때 한 번씩 쓸 수 있다.

### 이메일 코드

시스템 관리자가 허용한 경우에만 보인다. 인증 앱을 쓸 수 없는 사용자를 위한 방식이며 인증 앱보다 안전성이 낮다.

1. **이메일 코드** 영역에서 **설정용 코드 보내기**를 누른다.
2. 계정 이메일로 온 6자리 코드를 입력하고 **확인**을 누른다.
3. 이후 로그인할 때마다 이메일로 코드가 온다. 코드는 10분 동안 한 번만 쓸 수 있고, 5번 틀리면 새 코드를 받아야 한다. 코드는 1분에 한 번, 1시간에 5번까지 보낼 수 있다.

두 방식을 모두 등록할 수 있다. 정책이 "필수"이면 마지막 남은 방식은 해제할 수 없다.

## 정책 설정 (시스템 관리자)

관리 화면 **설정 > 보안**에서 정한다. 저장하면 모든 사용자에게 다음 화면 이동부터 바로 적용된다.

| 항목 | 설명 |
|---|---|
| 정책 | **사용 안 함** / **권장 (선택)**: 미등록 사용자에게 안내만 / **지정 역할 필수**: 선택한 역할을 가진 사용자는 필수 / **전체 필수** |
| 2단계 인증이 필수인 역할 | "지정 역할 필수"일 때 선택 |
| 유예 기간(일) | 필수 정책이 처음 적용된 사용자가 등록 없이 쓸 수 있는 기간. 이 기간에는 포털과 관리 화면 위에 마감일 안내가 나온다. 지나면 보안 화면 외에는 쓸 수 없다. 0이면 즉시 |
| 기기 기억 기간(일) | **이 기기 기억하기**를 선택한 기기에서 코드 입력을 생략하는 기간. 0이면 사용 안 함 |
| 이메일 코드 허용 | 끄면 이메일 코드는 2단계 인증으로 인정되지 않는다. 이메일 코드만 등록한 사용자는 정책에 따라 인증 앱 등록을 요구받는다 |

권장 운영: 교직원 역할(학적 담당, 교무 담당, 시스템 관리자 등)은 **지정 역할 필수**, 학생은 권장.

## 초기화 (휴대폰 분실 등)

1. **사용자와 권한 > 사용자**에서 사용자를 연다.
2. 화면 위쪽의 **2단계 인증 초기화**를 누르고 사유를 입력한다(`2단계 인증 초기화` 권한 필요).
3. 사용자의 인증 앱, 복구 코드, 이메일 코드, 기억된 기기가 모두 해제된다. 유예 기간이 다시 시작된다.

본인 계정은 초기화할 수 없다. 초기화는 보안 이벤트와 업무 감사에 사유와 함께 남는다.

유일한 관리자가 휴대폰을 잃어버려 관리 화면에 들어올 수 없으면 IT 운영자가 `uv run manage.py security_reset_mfa`로 초기화한다(Docker: `docker compose exec app uv run manage.py security_reset_mfa`, [명령 레퍼런스](../operations/commands.md)).
