# 21. 성적

메뉴: **성적 > 성적 처리 현황**, **평가 방식 변경 요청**, **성적 정정**, **학기 기록**, **설정 > 성적 처리 정책**. 교원은 포털 **담당 강좌 > 성적 입력**을 쓴다.

| 권한 | 할 수 있는 일 |
|---|---|
| `성적, 성적 처리 현황, 학기 기록 조회` | 성적 처리 현황, 학기 기록, 학생 성적표 조회 |
| `성적 확정과 반려, 교원 대신 성적 입력, 학기 마감` | 강좌 성적 확정·반려, 교원 대신 입력(기간 무관), 등급 비율을 넘긴 예외 제출, 학기 마감, 재계산. 조직 단위 범위로 할당하면 그 조직이 개설한 강좌만 |
| `성적 예외 제출 검토` | 예외 제출 알림을 받는다. 학과장, 학사팀장에게 조직 범위로 할당한다 |
| `확정된 성적의 정정 요청` | 담당하지 않는 강좌의 정정 요청(예: 부정행위로 인한 성적 취소) |
| `성적 정정 승인·반려(본인 요청 제외)` | 정정 요청 처리 |
| `평점, 재수강, 학사경고, 성적우수 정책 관리` | 성적 처리 정책 설정 |

담당 교원은 권한 없이 자기 강좌의 성적을 입력하고 정정을 요청할 수 있다. 역할 기본값: 학적 담당은 조회·확정·승인·예외 제출 검토, 교무 담당은 조회·정정 요청·정책 관리, 증명서 담당과 학과 조교는 조회. 평가 방식 변경 요청은 `개설강좌 편성` 권한으로 처리한다.

## 레거시와 다른 점

- 레거시는 교수가 성적을 저장하면 바로 최종 성적이었고, 교무처가 화면에서 직접 고쳤다. 사유와 승인 절차가 없었고, 일부 계정의 수정은 백업 기록에도 남지 않았다. 신규 시스템은 **입력 → 제출 → 확정** 단계를 두고, 확정된 성적은 **정정 요청을 다른 사람이 승인**해야만 바뀐다. 애플리케이션과 DB(트리거)가 모두 막는다.
- 레거시는 교수가 담당하지 않는 강좌의 성적도 요청을 조작해 저장할 수 있었다. 신규 시스템은 담당 교원과 권한 범위를 서버와 DB에서 확인한다.
- 평점, 학사경고, 성적우수를 화면마다 그때그때 계산하지 않고 **학기 기록**으로 저장한다. 학기 마감 때 그 학기의 공식 기록이 된다.
- 재수강은 새 성적이 **확정된 뒤에** 이전 성적을 누적 평점에서 뺀다(레거시는 신청하는 순간 뺐고, 폐강해도 되돌리지 않았다).
- 레거시는 성적 메뉴만 비활성화하고 주소로 들어가면 성적이 보였다. 신규 시스템은 성적 조회 제한을 서버에서 적용한다.

## 학기 순서

1. **업무 기간**([10장](10-terms.md)): 세션별 **성적 입력** 기간. 교원은 이 기간에만 입력·제출한다.
2. 교원이 성적을 입력하고 제출한다. `uv run manage.py grades_remind_missing {학기}`로 미제출 교원에게 안내 메일을 보낸다.
3. **성적 처리 현황**에서 강좌별로 확정하거나 교원에게 반려한다.
4. 모든 강좌가 확정되면 **학기 기록 > 학기 마감**. 학기 기록, 학업 상태, 성적우수가 정해지고 학기가 **성적 마감** 상태가 된다.
5. 그 뒤에 바꿀 성적은 **성적 정정**으로 처리한다.

## 성적 척도와 평가 방식

**성적 척도는 설치할 때 정해지고 바꿀 수 없다**(2026-10-23 결정). 성적과 평점이 모두 그 척도에 있기 때문이다. `uv run manage.py setup_install --grade-scale=4.5|4.3`으로 정하거나, 정하지 않으면 첫 프로파일의 척도가 된다(한국 대학 4.5, 레거시 YUST 4.3). 기준정보 > 성적 척도의 **기본** 표시는 바꿀 수 없고, 기본 척도는 지울 수 없다. 등급별 **점수 대역**(하한·상한 %)과 평점은 같은 화면에서 고친다([11장](11-course-categories-and-grade-scales.md)).

강좌마다 **평가 방식**이 있다. 기본은 **절대평가**다.

| 평가 방식 | 교원 입력 | 저장 | 제출 조건 |
|---|---|---|---|
| 절대평가(기본) | 학생마다 **점수(0~100)**. 성적은 점수 대역으로 정해지며 고를 수 없다(점수 없는 성적, 예: I만 직접 고른다) | 점수(원본), 성적, 평점 | 모든 학생에게 성적 |
| 상대평가 | 학생마다 **성적**. 점수는 입력하지 않는다(입력하면 거부) | 성적, 평점 | 모든 학생에게 성적 + **등급 비율 상한** 준수 |
| P/F 과목 | 평가 방식과 관계없이 P/NP | 성적 | 모든 학생에게 성적 |

- 상대평가를 원하는 교원은 성적 입력 화면에서 **상대평가 요청**(사유)을 한다. 개설 조직의 `개설강좌 편성` 권한자(학과 조교, 교무 담당)가 **성적 > 평가 방식 변경 요청**에서 승인하거나 반려(의견 필수)하고, 결과가 교원에게 메일로 간다. 승인되면 이전 방식으로 임시 저장한 성적은 지워진다. 성적이 **제출된 뒤에는** 요청도 변경도 할 수 없다. 직원도 개설강좌 화면에서 성적이 입력되기 전까지만 바꿀 수 있다.
- 재수강 최고 성적: 절대평가에서 점수가 상한보다 높은 성적이 되면 **상한 성적으로 낮춘다**(점수는 그대로). 상대평가에서는 상한보다 높은 성적을 고를 수 없다.

## 등급 비율 상한 (상대평가)

**설정 > 성적 처리 정책 > 상대평가**: 등급군별 상한(기본 A군 30%, B군 40%), 상한 초과 허용폭(기본 1%p), 검사 최소 학생 수(기본 10명).

- 등급군은 글자 기준이다. A+·A0·A-는 A군, B+·B0·B-는 B군. 상한이 없는 등급군(C, D, F)은 제한이 없다.
- 비율의 분모는 그 강좌에서 평점에 들어가는 성적을 받은 학생 수다. 철회 학생과 P/NP/I는 빠진다.
- 최소 학생 수 미만인 강좌는 검사하지 않는다(7명 중 A 30%는 맞출 수 없으므로).
- 교원은 성적 입력 화면의 **등급 비율 검사**로 현재 분포와 상한을 보고, 상한을 넘으면 **제출할 수 없다**.
- 성적 관리 권한을 가진 직원은 상한을 넘겨도 제출할 수 있다. 다만 **예외 제출**이다. 사유를 반드시 적어야 하고, 업무 감사에 분포와 사유가 남으며, `성적 예외 제출` 검토 권한자(학과장, 학사팀장 등 조직 범위로 할당)에게 메일이 가고, 강좌에 **예외 제출** 표시가 남는다. **성적 처리 현황**에서 예외 제출 강좌만 걸러 볼 수 있다.

## 성적 입력 (교원)

포털 **담당 강좌**에서 강좌의 **성적 입력**을 연다. 화면 위에 강좌의 평가 방식, 입력 안내, 평가 방식 변경 요청이 나온다.

- 절대평가: 점수를 넣으면 성적이 바로 보인다.
- 상대평가: 성적만 고른다. 점수 칸이 없다. **등급 비율 검사**로 상한을 확인하고 제출한다.
- 성적 목록은 과목의 성적 방식을 따른다. 일반 과목은 등급, P/F 과목은 P/NP를 보여 준다([11장](11-course-categories-and-grade-scales.md)).
- **임시 저장**은 언제든 할 수 있다. 학생은 임시 저장한 성적을 보지 못한다.
- **성적 제출**은 모든 학생에게 성적이 있어야 한다. 제출하면 교원은 더 고칠 수 없다. 잘못된 성적은 확정 전이라면 학사 담당에게 반려를 요청하고, 확정 후라면 정정을 요청한다.
- 수강 철회한 학생은 W로 보이고 성적을 넣지 않는다.

## 확정과 반려 (학사 담당)

**성적 처리 현황**: 학기별 강좌 목록과 미제출·제출·확정 건수. **확정 가능** 필터는 모든 학생의 성적이 제출된 강좌만 보여 준다.

- **확정**: 제출된 성적을 확정한다. 수강이 **이수** 상태가 되고 학생에게 성적이 보인다. 학생의 학기 기록이 다시 계산된다. 여러 강좌를 골라 **선택 강좌 확정**도 할 수 있다. 미제출 학생이 있는 강좌는 건너뛴다.
- **교원에게 반려**: 사유와 함께 제출을 취소한다. 성적은 임시 저장 상태로 돌아가고 교원에게 메일이 간다.
- **성적**: 성적 입력 화면을 연다. 학사 담당은 기간과 관계없이 확정 전 성적을 입력하거나 고칠 수 있다. 교원이 **제출한** 성적을 직원이 고치면 이전 값과 새 값이 감사 `grades.submitted_changed`에 남는다.

## 성적 정정

확정된 성적을 바꾸는 유일한 방법이다.

1. 요청: 교원은 성적 입력 화면에서 해당 학생의 **정정 요청**(사유와 함께, 절대평가는 바꿀 점수, 상대평가는 바꿀 성적). 재수강 상한은 정정에도 적용된다. 담당하지 않는 강좌는 `확정된 성적의 정정 요청` 권한이 있는 직원이 같은 화면에서 요청한다. 한 성적에 진행 중인 요청은 하나뿐이다.
2. 처리: **성적 > 성적 정정**(기본은 대기 목록, 메뉴에 대기 건수 표시)에서 **승인** 또는 **반려**(의견 필수). 요청한 사람은 자기 요청을 처리할 수 없다(DB 제약으로도 막는다).
3. 승인하면 성적(절대평가는 점수와 성적)이 바로 바뀌고 학생의 학기 기록과 이후 학기의 누적 평점이 다시 계산된다. 학업 상태와 성적우수는 학기 마감 때 정한 값을 유지한다.

요청자는 대기 중인 요청을 **요청 취소**할 수 있다. 모든 요청과 처리는 사유와 함께 업무 감사에 남는다.

## 평점 계산

| 항목 | 규칙 |
|---|---|
| 신청 학점 | 확정된 모든 과목(F, P, NP, I 포함) |
| 취득 학점 | 이수 등급(F, NP, I 제외) |
| 평점 학점 | 평점 계산에 포함하는 등급. F는 0점으로 포함, P/NP/I는 제외 |
| 평점 | 합계(평점 × 학점) ÷ 평점 학점. P/F 과목만 들은 학기는 평점이 없다 |
| 자릿수 | 정책의 소수 자릿수와 처리(반올림, 버림). 정수 연산이라 경계값(예: 3.4375 → 3.438)에서 오차가 없다 |
| 학기 평점 | 그 학기의 성적을 모두 반영(재수강으로 대체된 이전 성적도 그 학기 평점에는 남는다) |
| 누적 평점 | 재수강한 과목은 정책에 따라 한 번만 반영. **최근 성적**(기본, 더 나빠도 최근 것) 또는 **최고 성적**. 대체된 성적은 누적 학점에서도 빠지고 성적 화면에 "재수강으로 누적 평점에서 제외"로 표시된다 |

재수강 관계는 수강신청 때 정해진다([20장](20-registration.md)): 같은 과목이나 대체과목을 다시 들으면 이전 수강과 연결된다.

## 학업 상태와 성적우수 (학기 마감)

| 정책 | 기본값 | 레거시 YUST 프로파일 |
|---|---|---|
| 학사경고 기준 | 학기 평점 1.75 미만 | 1.3 미만 |
| 정규 학기만 판정 | 예 | 예 |
| 제적 검토 경고 횟수 | 0(끔) | 4 |
| 연속 경고만 셈 | 아니오(전체 횟수) | 아니오 |
| 성적우수 최저 평점, 최소 평점 학점 | 4.0, 15학점 | 0, 0(레거시는 단순 상위 N명) |
| F가 있으면 성적우수 제외 | 예 | 아니오 |
| 평점 자릿수 | 2자리 반올림 | 3자리 반올림 |
| 성적 척도(설치 때 확정) | 4.5(KR45) | 4.3(YUST43) |
| 등급 비율 상한(상대평가) | A 30%, B 40%, 허용 1%p, 10명 이상 검사 | 같음 |

- **학사경고**: 학기 평점이 기준 **미만**. P/F 과목만 들은 학기는 경고하지 않는다.
- **제적 검토**: 경고 횟수가 기준에 이르면 표시한다. 제적 자체는 학적 변동([13장](13-status-changes-and-advisors.md))으로 처리한다.
- 정규 학기만 판정하면 계절학기는 학업 상태가 없고, 연속 경고를 끊지도 않는다.
- **성적우수**: 기준을 충족한 학생을 프로그램별로 학기 평점 순으로 순위를 매긴다(동점은 같은 순위, 다음 순위는 건너뜀).
- 학생 학적의 **학업 상태**가 최근 판정으로 바뀐다. 업무 기간이나 수강 대상 조건의 "학업 상태"가 이 값을 쓴다.

**학기 기록** 화면에서 학기, 학업 상태, 성적우수, 프로그램으로 걸러 학사경고자 명단과 성적우수자 명단을 본다(레거시 학사경고·성적우수 보고서). **학기 마감**은 먼저 **미리 보기만**(기본)으로 실행해 미확정 강좌를 본 뒤, 끄고 다시 실행한다. **재계산**은 정책을 바꾼 뒤 지난 학기 기록에 적용할 때 쓴다(사유 필수).

## 학생 화면과 성적표

직원이 학생의 성적표를 열어 보면 감사 `transcript.viewed`에 남는다(학번 포함).

- 포털 **성적**: 학기별 확정 성적(철회는 W), 학기 평점과 취득 학점, 누적 평점, 학업 상태, 성적우수. 졸업생도 볼 수 있다. 확정되지 않은 성적은 보이지 않는다.
- **인쇄**, **PDF**: 확인용 성적표(비공식). PDF는 Gotenberg로 만든다. 공식 성적증명서는 증명서 발급으로 만든다([23장](23-certificates.md)). 직원은 학적 화면이나 학기 기록의 **성적표**로 학생의 성적표를 연다(`성적 조회` 권한).
- **수강신청 제한**에서 **성적 조회 제한**을 켠 학생은 성적 화면과 성적표를 볼 수 없다([20장](20-registration.md)).
- 강의평가 기간 중 그 학기 강의평가를 마치지 않은 학생은 그 학기 성적이 가려진다(설정, [22장](22-course-evaluation.md)).

## 성적 처리 정책

**설정 > 성적 처리 정책**(`평점, 재수강, 학사경고, 성적우수 정책 관리` 권한). 위 표의 항목을 바꾼다. 바꾼 정책은 이후 계산부터 적용된다. 지난 학기 기록에 적용하려면 **재계산**한다. 학업 상태와 성적우수는 학기 마감 때 정해지므로, 마감한 학기에 다시 적용되지 않는다.

## 이 설치본의 화면

원본(Filament, Livewire) 화면과 기능은 같고 조작 방식이 조금 다르다.

- **성적 처리 현황**의 행 메뉴: **성적**(포털 성적 입력 화면), **확정**(확인 화면), **교원에게 반려**(사유 입력 화면). 여러 강좌 확정은 목록에서 강좌를 고른 뒤 동작 목록의 **선택 강좌 확정**. 필터: 학기(기본은 진행 중인 학기, **전체**로 모든 학기), 개설 조직, 예외 제출, 확정 가능.
- **성적 정정**, **평가 방식 변경 요청**의 행 메뉴 **승인**, **반려**는 의견 입력 화면을 연다. 기본 목록은 대기 중인 요청이고, 메뉴에 대기 건수가 보인다.
- **학기 기록** 목록 위 **학기 마감**: 학기, **미리 보기만**(기본 켜짐), 사유. 미리 보기는 마감할 수 있는지와 미확정 강좌(최대 30개)를 메시지로 보여 준다. 마감을 시작하면 학생 100명 단위의 큐 작업(Celery)으로 진행되고, 진행 중인 마감은 학기 기록 목록 위에 진행률로 보인다. 끝나면 학기 상태가 **성적 마감**으로 바뀌고 마감을 시작한 직원에게 메일이 간다. 작업 하나가 실패하면 마감은 끝나지 않고 학기는 그대로다. 원인을 해결하고 다시 마감한다(다시 해도 결과가 같다). 명령으로는 `uv run manage.py term_close {학기} --dry-run`, `uv run manage.py term_close {학기} --reason=...`([운영 명령](../operations/commands.md)).
- **성적 처리 정책**의 등급 비율 상한은 `A=30, B=40`처럼 등급 글자와 비율을 쉼표로 이어 적는다. 비우면 상한이 없다.
- 교원 포털 성적 입력: 절대평가는 점수를 넣으면 잠시 뒤 옆에 성적이 보인다. **임시 저장**, **등급 비율 검사**, **성적 제출** 버튼은 화면 아래에 있고, 저장이 안 된 경우(예: 범위 밖 점수) 입력한 값과 오류가 그대로 다시 보인다. 정정 요청은 학생 행의 **정정 요청**을 누르면 화면 아래에 입력 칸이 열린다.
- 직원용 성적표 주소: `/student-records/{학적 ID}/transcript/`(학적 화면의 **성적표** 버튼, 학기 기록 행의 **성적표**). 끝에 `?format=pdf`를 붙이면 PDF.
- LMS 연결이 있는 강좌는 성적 입력 화면에서 LMS 점수를 초안으로 불러올 수 있다([28장](28-lms-integration.md)). 강의평가 기간 중 평가를 마치지 않은 학기의 성적은 안내와 **강의평가** 링크와 함께 가려진다([22장](22-course-evaluation.md)).
