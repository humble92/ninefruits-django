# 28. LMS 연동

메뉴: 관리 화면 **LMS 연동 > LMS 플랫폼**, **강좌 연결**, **동기화 기록**(`LMS 플랫폼, 연결, 동기화 관리` 권한, 기본: 시스템 관리자, 교무 담당). 교원은 포털 **담당 강좌**와 강좌 상세의 LMS 링크, 성적 입력의 **LMS 점수 불러오기**를 쓴다. 불러오기는 성적 입력과 같은 조건이다(담당 교원이 성적 입력 기간 안에서).

개발자용 상세(커넥터 구현, API)는 [LMS 연동 가이드](../../../lms-integration-guide.md).

## 무엇이 어디로 가나

| 학사 → LMS | 시점 |
|---|---|
| 개설강좌(강좌 생성) + 담당 교원 | 강좌 **공개** 시, 그리고 `lms_sync` |
| 수강 확정 → 등록 | 수강신청·대기자 승격·직원 수강 처리 즉시 |
| 수강 취소·철회 → 등록 해제 | 즉시 |
| 전체 대조 | 매일 02:30 (`lms_reconcile`, 스케줄 작업 `lms.reconcile`) |

| LMS → 학사 | 시점 |
|---|---|
| 최종 점수(초안) | 교원이 성적 입력에서 **LMS 점수 불러오기**를 누를 때. 저장·제출은 교원이 한다 |

확정 성적은 LMS로 보내지 않는다. 강의 자료·과제·퀴즈는 LMS 안에 있다.

## 플랫폼

**LMS 플랫폼**: 코드, 이름(언어별), 드라이버, 기본 URL, 인증 정보, 사용 여부, 수강 명단 동기화, 최종 점수 가져오기.

- 드라이버 **없음(기록만)**: 아무것도 호출하지 않고 보낼 내용을 기록한다. 연동 전 흐름을 점검하거나 시연할 때 쓴다. 데모 데이터의 `DEMO` 플랫폼이 이것이다.
- `Moodle`, `Open edX`: 커넥터가 아직 없다("아직 구현되지 않음" 표시). 선택하면 동기화가 실패로 기록된다.
- **사용**을 켜면 그때부터 강좌 공개·수강 변동이 즉시 전달되고 야간 대조 대상이 된다.
- **인증 정보**는 한 줄에 `키=값` 하나씩 쓴다(예: `token=...`). 암호화해 저장하며 화면에 다시 보여 주지 않는다. 수정할 때 비워 두면 저장된 값을 그대로 둔다. 데이터 변경 기록에도 값이 남지 않는다.

## 강좌 연결과 동기화 기록

- **강좌 연결**: 어느 개설강좌가 어느 플랫폼 강좌(ID, URL)에 연결됐는지, 상태(대기/연결됨/실패), 마지막 동기화와 오류. 플랫폼·상태·학기 필터, 과목 코드 검색. 행의 **다시 동기화**(확인 화면)로 강좌·교원·수강생을 다시 밀어넣는다.
- **동기화 기록**: 단계별(강좌, 구성원 추가·제거, 점수 가져오기, 점수 전달, 대조) 결과와 메시지. 실패 원인을 여기서 본다. 행을 열면 시작·종료 시각과 내용(payload)이 보인다.
- 명령: `uv run manage.py lms_sync {플랫폼} --term={학기}`(전체 밀어넣기, `--dry-run`), `uv run manage.py lms_reconcile`(대조). [운영 명령](../operations/commands.md#lms-연동-phase-12) 참조.

## 포털

- 학생·교원의 강좌 상세와 교원의 담당 강좌 목록(**LMS** 열)에 플랫폼 강좌 링크가 보인다(연결된 강좌만).
- 성적 입력: 플랫폼에 **최종 점수 가져오기**가 켜져 있고 강좌가 연결돼 있으면 **LMS 점수 불러오기** 버튼이 나온다. 점수 칸만 채우며 저장하지 않는다.

## 외부 연동 API

플랫폼이 결과를 늦게 알려 주거나 점수를 직접 보내는 경우를 위한 API가 있다(`/api/v1/lms/platforms/...`). 연동용 계정을 따로 만들어 `LMS 플랫폼, 연결, 동기화 관리` 권한만 주고, 운영자가 `uv run manage.py api_issue_token {이메일} --days=365`로 토큰을 발급해 플랫폼 담당자에게 전달한다. 토큰은 발급할 때 한 번만 보인다. 회수는 `api_revoke_tokens`. 발급·회수는 감사 기록에 남는다.

- 점수 전달(`.../scores/`)로 받은 점수도 저장되지 않는다. 교원이 **LMS 점수 불러오기**를 누르면 가장 최근에 받은 점수가 초안으로 채워진다.
- 동기화 결과(`.../sync-results/`)는 **동기화 기록**에 남고, 강좌 결과는 **강좌 연결**의 상태를 바꾼다.

## 자주 묻는 질문

- **학생이 LMS에 없다.** 학생에게 계정(사용자)이 있어야 동기화된다. 계정이 없으면 초대 후([14장](14-merge-and-invitations.md)) 다음 대조에서 추가된다.
- **동기화가 실패로 남는다.** 기록의 메시지를 본다. 인증 정보 만료가 흔하다. 플랫폼 수정에서 값을 바꾸고 **다시 동기화**.
- **플랫폼을 바꿨다.** 새 플랫폼을 만들고 옛 플랫폼의 사용을 끈다. 연결은 플랫폼별로 따로 생긴다.

## 이 설치본의 화면

원본(Filament, Livewire) 화면과 기능은 같고 조작 방식이 조금 다르다.

- 인증 정보는 원본의 키/값 표 대신 여러 줄 입력 칸에 `키=값`으로 쓴다. 형식이 틀린 줄은 줄 번호와 함께 거부된다.
- 플랫폼의 **옵션**(플랫폼별 역할 ID 등)은 화면에 입력 칸이 없다. 커넥터가 필요로 할 때 개발자가 넣는다([연동 가이드](../../../lms-integration-guide.md) 3절).
- **다시 동기화**는 확인 화면을 거친다. 커넥터 오류(구현 없는 드라이버, 플랫폼 장애)는 화면에 "동기화 실패: ..." 메시지로 보이고 강좌 연결이 "실패"가 된다(원본은 오류 화면).
- 동기화 기록은 읽기 전용이다. 행을 열면 내용(payload)을 JSON으로 보여 준다.
- 성적 입력의 **LMS 점수 불러오기**는 표 아래 버튼 줄에 있다. 누르면 이미 입력한 값은 그대로 두고 점수 칸만 바꾼 화면을 다시 보여 준다. **임시 저장**을 눌러야 저장된다.
- 외부 연동 API와 토큰 명령(`api_issue_token`, `api_revoke_tokens`)은 이 설치본에서 새로 생겼다(원본에는 API가 없다).
