# 15. 로그인 수단 설정

메뉴: **설정 > 로그인 수단** (`로그인 수단과 SSO 관리` 권한)

## 로그인 이름

로그인 계정의 이메일이 기본 로그인 이름이다. 학번 로그인을 켜면 로그인 화면의 칸이 "이메일 또는 학번"이 된다.

| 학번으로 로그인 | 동작 |
|---|---|
| 허용 안 함 | 이메일만 |
| 재학생만 | 재학, 휴학 학적의 학번으로 로그인 가능 |
| 재학생과 졸업생 | 졸업, 자퇴 등 끝난 학적의 학번도 가능 |

학적이 여러 개인 사람은 어느 학번으로 로그인해도 같은 계정이다.

## 계정 잠금

| 설정 | 설명 |
|---|---|
| 잠금까지 실패 횟수 | 비밀번호를 연속으로 틀린 횟수가 이 값에 이르면 잠근다. 0이면 잠그지 않는다 |
| 잠금 시간(분) | 시간이 지나면 저절로 풀린다 |

이메일과 학번 어느 쪽으로 시도해도 같은 계정의 실패로 센다. 잠긴 계정에는 비밀번호가 틀렸을 때와 같은 안내가 나가서, 계정이 있는지 알 수 없다. 잠금은 보안 이벤트(**계정 잠김**)에 남는다.

시간 전에 풀려면 **사용자** 상세의 **로그인 잠금 해제**(사유 필수, `사용자 수정` 권한)를 쓴다. 관리 화면을 쓸 수 없을 때는 IT 운영자가 `uv run manage.py security_unlock_user`를 쓴다.

## 학교 통합 로그인(SSO)

학교의 OpenID Connect 로그인(예: Microsoft Entra ID, Google Workspace, Keycloak)을 등록하면 로그인 화면에 "OO로 로그인" 버튼이 생긴다.

| 항목 | 설명 |
|---|---|
| 키 | 영문 소문자 식별자. 예: `school`. 바꾸면 기존 연결이 끊긴다 |
| 버튼 이름 | 로그인 화면에 보일 이름 |
| 발급자(Issuer) URL | 제공자의 issuer. `/.well-known/openid-configuration`이 이 주소 아래에 있어야 한다 |
| 클라이언트 ID, 비밀값 | 제공자에서 앱을 등록하고 받은 값. 비밀값은 암호화해 저장한다 |
| 범위(scope) | 기본 `openid email profile` |
| 2단계 인증으로 인정 | 학교 로그인 자체가 2단계 인증을 요구할 때만 켠다. 켜면 이 로그인에는 이곳의 2단계 인증을 다시 묻지 않는다 |
| 제공자에 등록할 리디렉션 URI | 화면에 표시되는 주소(`https://<서버 주소>/auth/sso/<키>/callback/`)를 제공자 앱 설정에 그대로 등록한다 |

### 계정 연결 방식

| 방식 | 동작 |
|---|---|
| 사용자가 직접 연결 | 사용자가 비밀번호로 로그인한 뒤 포털 **보안 > 학교 통합 로그인**에서 **연결**한다(비밀번호 재확인 필요) |
| 확인된 학교 이메일로 자동 연결 | 제공자가 확인한 이메일이 학적의 학교 이메일과 같으면 처음 로그인할 때 자동으로 연결한다 |

- 연결되지 않은 학교 계정으로 로그인하면 비밀번호 로그인 후 연결하라는 안내가 나온다. 학교 계정만으로 새 계정이 만들어지지는 않는다.
- 연결과 해제는 보안 로그에 남는다.

### 비밀번호 로그인 허용

**학교 계정을 연결한 사용자의 비밀번호 로그인 허용**을 끄면 연결한 사용자는 학교 로그인만 쓸 수 있다. 졸업 후 학교 계정이 없어지는 경우를 생각해, 켜 두고 졸업 예정자에게 개인 이메일과 비밀번호를 준비하게 하는 것을 권장한다. 졸업생은 계정의 로그인 이메일(개인 이메일)과 비밀번호로 계속 로그인한다.
