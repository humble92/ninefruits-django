# 23. 증명서

메뉴: **증명서 > 발급 대장**, **증명서 > 증명서 종류**, **설정 > 증명서 설정**. 발급은 학적 화면(**학생과 교직원 > 학적** 보기)의 **증명서 발급** 버튼으로 한다. 학생은 포털 **증명서**에서 자기 증명서 PDF를 내려받는다. 누구나 `/verify/{코드}/` 페이지에서 진위를 확인할 수 있다.

| 권한 | 할 수 있는 일 |
|---|---|
| `증명서 발급, 재생성, 취소` | 발급, 다시 만들기, 취소, 발급 대장 조회(학적 조회 범위 안에서) |
| `증명서 종류, 서식, 설정 관리` | 종류와 언어별 서식, 발급번호 형식, 발급자 |

역할 기본값: 증명서 담당은 발급, 학적 담당은 둘 다, 교무 담당은 종류·서식 관리. 발급 권한은 **전체 범위**로 준다(DB 정책이 전체 범위 부여만 받는다). 어느 학생에게 발급할 수 있는지는 학적 조회 범위로 정한다. 예를 들어 단과대학 증명서 담당에게는 `증명서 발급`을 전체 범위로, `학적 조회`를 그 단과대학 범위로 준다.

## 레거시와 다른 점

- **발급 대장.** 레거시는 화면에서 바로 인쇄했고(`aca3/cti_*`), 대장(`SRCERT`)은 번호 생성용이라 누가 발급했는지, 취소됐는지 알 수 없었다. 신규 시스템은 발급마다 발급번호, 확인 코드, 담당자, 용도, 매수, PDF 파일과 체크섬을 남기고, 취소해도 행을 지우지 않는다.
- **진위 확인.** 레거시에는 없었다. 모든 증명서에 확인 코드와 QR이 인쇄되고, 공개 페이지가 발급 사실과 종류, 발급일, 가려진 명의자(성명의 첫 글자·마지막 글자, 학번 앞 4자리)를 보여 준다.
- **서식.** 레거시는 종류와 언어마다 PDF 생성 스크립트가 따로 있었다. 신규 시스템은 종류마다 언어별 서식(제목, 본문, 하단 문구, 발급자)을 화면에서 고친다.
- **발급 제한.** 레거시는 수강거부 명단과 무관하게 발급했다. 신규 시스템은 증명서 제한이 걸린 학생에게 발급하지 않는다([20장](20-registration.md)).
- 발급 수수료는 기록하지 않는다(레거시도 금액만 적었다).
- 학생의 온라인 신청은 없다(계획서 17.5). 직원이 발급한다.

## 종류와 서식

**증명서 종류**: 코드(발급번호에 쓴다), 이름(언어별), 대상(모든 학적 / 재학생(졸업 전) / 졸업생), 성적 포함, 사진 포함, 사용 여부, 순서. 한국 대학 프로파일(`setup_install --profile=korean-university`)이 세 종류와 4개 언어(한국어, 영어, 중국어 간체, 라오어) 서식을 넣는다. 종류가 하나라도 있으면 다시 넣지 않으므로 고친 내용이 유지된다.

| 코드 | 종류 | 대상 | 비고 |
|---|---|---|---|
| `ENR` | 재학증명서 | 재학생(졸업 전) | |
| `GRD` | 졸업증명서 | 졸업생 | 졸업일, 학위번호 |
| `TRN` | 성적증명서 | 모든 학적 | 학기별 확정 성적 표, 누계 평점과 취득 학점 |

**서식**(종류 수정 화면 아래 **서식** 칸): 언어마다 하나. 언어, 제목, 본문(빈 줄로 문단 구분), 하단 문구, 발급자. 본문에는 중괄호 치환 항목을 쓴다.

| 항목 | 값 |
|---|---|
| `{institution}` | 기관 이름(그 언어) |
| `{student_name}`, `{student_number}` | 성명(그 언어 표기, 없으면 로마자), 학번 |
| `{program}`, `{org_unit}` | 과정, 소속 조직 단위 |
| `{admission_date}`, `{graduation_date}`, `{degree_number}` | 입학일, 졸업일, 학위번호 |
| `{status}`, `{year_level}` | 학적 상태, 학년 |
| `{birth_date}`, `{gender}`, `{nationality}` | 생년월일, 성별, 국적 |
| `{issue_date}`, `{serial_number}`, `{purpose}`, `{copies}` | 발급일, 발급번호, 용도, 매수 |

날짜는 그 언어의 형식으로 찍힌다(예: `2026년 10월 24일`, `October 24, 2026`). 값이 없으면(예: 졸업일) 빈 칸이다. 목록에 없는 항목은 쓴 그대로 남는다. 본문 위에는 인적 사항 표(성명, 학번, 생년월일, 성별, 국적, 과정, 입학일, 그리고 졸업생이면 졸업일, 아니면 학적 상태와 학년)가 자동으로 들어간다. 증명서 전체(표 제목, 날짜, 학적 상태 등)가 서식의 언어로 인쇄된다.

## 설정

**설정 > 증명서 설정**(`증명서 종류, 서식, 설정 관리` 권한)

- **발급번호 형식**: 기본 `{TYPE}-{YYYY}-{SEQ:6}` → `ENR-2026-000001`. 항목은 `{TYPE}`(종류 코드), `{YYYY}`·`{YY}`(발급 연도, 기관 시간대 기준), `{SEQ:n}`(n자리 일련번호)이고 `{SEQ:n}`은 꼭 하나 있어야 하며 맨 뒤의 일반 문자 외에는 그 뒤에 항목을 둘 수 없다. 일련번호는 앞부분(접두어)이 다를 때마다 따로 센다. `{TYPE}-{SEQ:6}`이면 종류별 통산, `{YYYY}{SEQ:5}`면 연도별 통산이다. 동시에 발급해도 번호가 겹치지 않는다(DB에서 원자적으로 증가).
- **진위 확인 유효 기간(일)**: 0이면 항상. 기간이 지나면 확인 페이지가 "기간 만료"로 답한다. 발급 사실 자체는 대장에 남는다.
- **언어별 발급자**: 직인 위에 인쇄하는 이름("나인프루츠대학교 총장"). 기관 설정의 지원 언어마다 칸이 있다. 서식의 발급자가 있으면 그것이 우선한다.

## 발급

학적 화면의 **증명서 발급**: 종류(사용 중인 것), 언어(기관 지원 언어), 용도, 매수(1~20). **증명서 발급**을 누르면 PDF를 만들어 보관하고 학적 화면으로 돌아가며, 알림에 발급번호와 **PDF** 링크가 나온다.

발급을 거부하는 경우(화면에 이유가 나온다):

- 종류의 대상이 맞지 않음(재학증명서를 졸업생에게, 졸업증명서를 재학생에게)
- 사용 중지한 종류
- 그 언어의 서식이 없음
- 학생에게 **증명서 제한**이 적용 중(수강신청 제한, [20장](20-registration.md)). 해제한 뒤 발급한다. 담당자가 그 제한을 볼 수 없어도 거부한다.
- 학적이 조회 범위 밖이거나 발급 권한이 없음
- PDF 서비스(Gotenberg)가 응답하지 않음: 아무것도 발급되지 않고 "PDF를 만들지 못했습니다"가 나온다. 잠시 후 다시 발급한다.

발급은 업무 감사에 남는다(`certificate.issued`: 학번, 종류, 언어, 발급번호, 매수, 사유 칸에 용도).

## 발급 대장

**증명서 > 발급 대장**: 발급일, 발급번호, 종류와 언어, 학번, 성명, 용도, 매수, 상태, 담당자, 그리고 **PDF**·**진위 확인 페이지** 링크(새 탭). 종류와 상태로 거르고, 발급번호·학번·이름으로 찾는다. 조회 범위는 학적 조회 범위와 같다.

- **PDF**: 보관된 파일을 연다. 다시 만들지 않으므로 발급 당시 그대로다.
- **진위 확인 페이지**: 공개 페이지를 연다.
- **다시 만들기**(행 메뉴): 서식을 고친 뒤 등 현재 데이터로 PDF를 새로 만들어 바꾼다. 발급번호와 확인 코드는 그대로이고, 체크섬이 바뀐다. 감사 `certificate.rerendered`. 명령 `certificate_render`와 같다. 취소된 증명서는 다시 만들지 않는다.
- **취소**(행 메뉴): 사유 필수. 행과 파일은 남고, 상태가 취소로 바뀌며, 확인 페이지가 "취소된 증명서"로 답한다. 감사 `certificate.revoked`. 취소된 증명서는 다시 살리지 않고 새로 발급한다.

대장 행은 화면에서 고치거나 지울 수 없다(행을 누르면 읽기 전용 상세와 체크섬이 보인다).

## 진위 확인

- 증명서 하단에 확인 URL(`{기관 주소}/verify/{코드}/`)과 QR이 인쇄된다. 코드는 20자 무작위 문자열(영문 대문자와 숫자)이고 대소문자를 구분하지 않는다. 주소는 환경 변수 `APP_URL`로 만든다.
- 페이지는 로그인 없이 열리고, 주소(IP)마다 분당 30회로 제한한다(넘으면 HTTP 429). 검색 엔진에 노출하지 않는다(`noindex`). 발급 여부, 종류, 발급번호, 발급일, 가려진 성명과 학번을 보여 준다. 취소·기간 만료·없는 코드는 각각 다르게 답한다. 코드 입력 칸으로도 확인한다(`/verify/?code=...`).
- 제출받은 PDF 파일 자체를 확인하려면 대장 상세의 체크섬(SHA-256)과 파일의 해시를 비교한다. 명령 `uv run manage.py certificate_verify {코드}`로도 확인한다([운영 명령](../operations/commands.md)).
- 외부 시스템은 같은 기준과 같은 항목을 JSON으로 받는다: `GET /api/v1/certificates/verify/<확인 코드>/`(로그인 불필요, 주소당 1분 30회, [LMS 연동 가이드](../../../lms-integration-guide.md)).

## 학생 포털

**증명서**(학생·졸업생 메뉴): 자기 학적에 발급된 증명서 목록(발급일, 종류와 언어, 발급번호, 상태)과 PDF. 취소된 것도 상태와 함께 보이지만 PDF 링크가 없고, 취소된 증명서의 PDF는 학생이 내려받을 수 없다(발급 담당자는 기록 확인용으로 열 수 있다). 다른 학생의 파일은 열 수 없다(애플리케이션과 DB 양쪽). PDF 주소는 `/certificates/{발급 ID}/download/`다.

## 자주 묻는 질문

- **이름 표기가 틀리다.** 인물의 이름 변형(그 언어)을 고친 뒤 **다시 만들기**를 한다. 이미 제출한 증명서라면 취소하고 새로 발급한다.
- **서식을 고쳤는데 이미 발급한 증명서는?** 바뀌지 않는다. 필요하면 **다시 만들기**(여러 건은 명령 `certificate_render`).
- **발급번호를 건너뛰었다.** 발급 중 오류(PDF 서비스 중단 등)가 나면 번호는 소비되고 대장 행은 남지 않는다. 번호는 유일성만 보장하고 연속성은 보장하지 않는다.
- **QR 주소가 `localhost`로 찍힌다.** 운영 서버의 `APP_URL`을 기관 주소로 설정한 뒤 해당 증명서를 **다시 만들기**한다.

## 이 설치본의 화면

원본(Filament, Livewire) 화면과 기능은 같고 조작 방식이 조금 다르다.

- **증명서 발급**은 대화상자 대신 입력 화면이 열린다. 원본은 발급 뒤 PDF를 새 탭으로 열었고, 이 설치본은 학적 화면으로 돌아가 알림의 **PDF** 링크로 연다.
- 발급 대장의 **PDF**와 **진위 확인 페이지**는 행 끝의 링크이고, **다시 만들기**(확인 화면)와 **취소**(사유 입력 화면)는 행 메뉴에 있다. 다시 만들기는 취소되지 않은 증명서에만 된다.
- 서식은 종류 수정 화면 아래에서 고친다. 같은 언어의 서식을 두 개 만들 수 없다. `기준정보 조회` 권한만 있으면 종류와 서식을 읽기만 한다.
- 발급 중 PDF 서비스 오류가 나면 아무것도 발급되지 않는다(원본은 대장 행만 남고 PDF가 없을 수 있었다).
- 발급 권한은 전체 범위 부여만 인정한다(원본은 범위를 둔 부여도 화면에서 통과시킨 뒤 DB가 거부해 오류가 났다).
- 데모(`setup_demo`)에서는 `certificate-officer@demo.test`로 발급 대장을, `student@demo.test`로 포털 **증명서**를 볼 수 있다.
