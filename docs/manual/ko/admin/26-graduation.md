# 26. 졸업 사정과 졸업 처리

메뉴: **졸업 > 졸업 요건 점검**, 학적 보기 화면의 **졸업 요건 점검** 버튼, **설정 > 졸업**(학위번호 형식, 최저 누계 평점; `졸업 처리` 권한). 학생은 포털 **졸업 요건**에서 자기 이수 상황을 본다.

| 권한 | 할 수 있는 일 |
|---|---|
| `졸업 요건 점검 실행·조회` | 점검 실행(개별·일괄)과 저장된 점검 조회 |
| `졸업 처리, 요건 면제 승인` | 졸업 처리(일괄), 요건 면제 |

역할 기본값: 학적 담당은 둘 다, 교무 담당은 점검.

## 레거시와 다른 점

- **요건을 판정한다.** 레거시 졸업사정표는 교과 구분별 이수 학점과 평점을 찍기만 했고 기준과 비교하지 않았다(졸업사정결과 칸이 비어 있었음). 신규 시스템은 교육과정 연도별 **졸업 요건**([17장](17-courses-and-curriculum.md))과 비교해 요건마다 충족 여부를 낸다.
- **졸업 처리 전 점검이 필수다.** 레거시는 학적변동 코드 Z를 넣으면 끝이었다. 신규 시스템은 저장된 최신 점검이 충족일 때만 졸업 처리한다.
- **학위번호를 시스템이 발급한다.** 레거시는 학위번호 칸을 쓰지 않았고 졸업증번호를 손으로 적었다.
- 졸업생은 다른 테이블로 옮겨지지 않는다. 학적 상태만 `졸업`으로 바뀌고 계정은 졸업생 권한으로 유지된다([13장](13-status-changes-and-advisors.md)).

## 판정 규칙

학생의 **주전공 프로그램 × 교육과정 연도**에 해당하는 졸업 요건 세트를 찾아 요건마다 판정한다.

| 요건 종류 | 판정 |
|---|---|
| 교과 구분별 학점 | 이수한 과목 중 교과 구분이 그 구분 **또는 하위 구분**인 학점의 합 ≥ 최소 학점 |
| 필수 과목 | 목록의 과목을 모두 이수. 수강 당시 유효한 **대체과목**을 인정 |
| 지정 과목 중 선택 | 목록(대체 포함) 중 이수한 과목의 학점·과목 수가 기준 이상 |
| 시험 합격 | 그 시험 종류의 합격 결과가 있음([24장](24-assessments.md)) |

- "이수"는 확정 성적이 합격(`is_passed`)인 수강이다. 같은 사람의 다른 학적(재입학 전)에서 이수한 과목도 인정한다.
- 요건 세트의 **총 학점**과 **설정 > 졸업**의 **최저 누계 평점**(기본 2.0, 비우면 적용 안 함)도 확인한다.
- 복수전공·부전공은 해당 요건 세트로 따로 판정해 함께 보여 준다. 졸업 처리 조건은 주전공 충족이다.
- 교육과정 연도에 맞는 요건 세트가 없으면 미충족으로 나온다(세트를 만들어야 한다).

## 점검

- **지금 점검**: 학적 보기 화면의 **졸업 요건 점검** 버튼. 현재 데이터로 즉시 판정해 요건별 이수 과목·미이수 과목을 보여 준다. **이 점검 저장**을 누르면 저장된다.
- **일괄 점검**: **졸업 요건 점검 > 점검 실행**(학기, 학년 이상) 또는 명령 `uv run manage.py degree_audit_run --term={학기} --min-year-level=4 --actor=...`([운영 명령](../operations/commands.md)). 재학생마다 점검을 저장한다.
- 저장된 점검은 **스냅샷**이다. 이후 성적이 바뀌어도 저장본은 그대로이며, 다시 점검하면 새 스냅샷이 쌓인다. 목록은 학생·이수 구분별 **최신** 점검만 보여 주고, 졸업 처리도 최신 점검을 본다.

## 면제

전과·편입·교환학생처럼 개별 사정이 있을 때 요건 하나를 면제한다. 두 사람이 관여한다(2026-10-23 결정).

1. **요청**: 학적 보기 화면의 **요건 면제**에서 요건을 고르고 사유를 적는다(`졸업 처리, 요건 면제 승인` 권한). 감사 `graduation.waiver_requested`.
2. **승인·반려**: **졸업 > 요건 면제**에서 같은 권한을 가진 **다른 담당자**가 승인(의견 선택) 또는 반려(의견 필수)한다. 자기 요청은 결정할 수 없다. 감사 `graduation.waiver_approved`/`waiver_rejected`.
3. 승인된 면제만 점검에서 충족으로 친다. 요건마다 대기 중·승인된 면제는 하나다.
4. **해제**: 승인된 면제를 **해제**(사유 필수)하면 더 이상 적용되지 않고 이력이 남는다(상태 `해제`, 감사 `graduation.waiver_lifted`). 이미 졸업 처리한 학생의 졸업은 되돌리지 않는다.

데이터 변경 기록에도 모든 단계가 남는다.

## 졸업 처리

**졸업 요건 점검** 목록에서 대상을 고르고 **졸업 처리**(졸업일, 사유). 학생마다:

1. 재학 중이고 최신 주전공 점검이 충족인지 확인한다. 아니면 그 학생만 건너뛰고 사유를 알린다.
2. 학적 변동 `졸업`을 기록한다(상태 `졸업`, 졸업일). [13장](13-status-changes-and-advisors.md)의 변동 이력에 남는다.
3. 학위번호를 발급한다. 형식은 **설정 > 졸업**의 `{PROGRAM}-{YYYY}-{SEQ:5}`(기본, 예: `CS-2026-00001`. 토큰 `{PROGRAM}` 과정 코드, `{YYYY}`, `{YY}` 졸업 연도, `{SEQ:n}` 접두어별 일련번호). 동시에 처리해도 겹치지 않는다.
4. 감사 `graduation.processed`(학번, 졸업일, 학위번호, 근거 점검).

졸업한 학생은 포털에서 성적과 증명서를 계속 보고, 졸업증명서에 졸업일·학위번호가 찍힌다([23장](23-certificates.md)). 잘못 처리했다면 학적 변동(재입학 등)으로 바로잡는다. 졸업 처리 자체를 취소하는 기능은 없다.

## 자주 묻는 질문

- **점검이 "요건 세트 없음"이다.** 학생의 교육과정 연도를 포함하는 졸업 요건 세트가 프로그램에 없다. [17장](17-courses-and-curriculum.md)에서 만든다.
- **대체과목을 인정하지 않는다.** 대체 관계의 유효 기간이 수강 학기 시작일을 포함해야 한다.
- **학위번호 형식을 바꾸면?** 이후 발급부터 적용된다. 접두어가 바뀌면 일련번호는 1부터 시작한다.

## 이 설치본의 화면

원본(Filament, Livewire) 화면과 기능은 같고 조작 방식이 조금 다르다.

- **졸업 > 졸업 요건 점검** 목록(`/admin/graduation/degreeaudit/`): 필터 기본값은 이수 구분 **주전공**, 학적 상태 **재학**이다. 행의 **열기**는 저장된 점검을, **다시 점검**은 확인 화면을 연다. **점검 실행**은 목록 위 동작 버튼(학기, 학년 이상 기본 4)이다.
- **졸업 처리**는 목록에서 행을 체크하고 동작 목록에서 **졸업 처리**를 고른 뒤 실행하면 졸업일·사유 입력 화면이 열린다. 처리하지 못한 학생은 학번과 이유가 경고 메시지로 보인다(최대 10명).
- 학적 화면의 **졸업 요건 점검**은 즉시 판정 결과를 별도 화면에 보여 주고, 아래 **이 점검 저장**으로 저장한다. **요건 면제**는 요건 선택과 사유 입력 화면이다.
- **졸업 > 요건 면제**(`/admin/graduation/degreerequirementwaiver/`): 상태 필터 기본값은 **대기**, 메뉴에 대기 건수가 표시된다. 행의 **승인**·**반려**·**면제 해제**는 의견(사유) 입력 화면을 연다. 자기 요청이나 이미 결정된 면제의 버튼을 열면 403이다.
- **설정 > 졸업 설정**(`/admin/settings/graduation/`): 학위번호 형식은 `{SEQ:n}`이 정확히 하나 있어야 저장된다. 최저 누계 평점은 0~5, 비우면 적용하지 않는다.
- 포털 **졸업 요건**(`/portal/graduation/`): 학생·졸업생 메뉴에 있다. 재입학으로 학적이 여럿이면 포털에서 고른 학적 기준이다.
- 졸업 처리의 학적 변동·학위번호 기록은 권한(졸업 처리, 학적 범위, 학적 변동 승인 범위)을 확인한 뒤 시스템 컨텍스트로 쓴다. 졸업 처리 담당에게 `학적 관리` 권한이 따로 없어도 된다. 데이터 변경 기록에는 처리한 사용자가 남는다.
