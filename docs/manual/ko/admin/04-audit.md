# 4. 감사 조회

**감사** 메뉴의 세 화면은 조회만 가능하며 누구도 수정하거나 지울 수 없다(`감사 기록 조회`, `보안 이벤트 조회` 권한 필요). 목록 화면에는 추가, 수정, 삭제 버튼이 없고, 행을 열면 상세 내용을 읽기 전용으로 보여 준다.

| 화면 | 무엇을 보나 | 예 |
|---|---|---|
| 업무 감사 기록 | 누가, 무엇을, **왜** 했는지. 사유와 상세 내용 | 역할 할당(사유: 학기 중 대체 근무), 권한 변경(추가/제거 목록), 설정 변경(변경 전/후), 명령 실행 |
| 데이터 변경 기록 | 테이블 행의 변경 전/후 값. 프로그램을 거치지 않은 직접 변경도 남는다 | `users` UPDATE, 변경 컬럼 `locale` |
| 보안 이벤트 | 로그인, 로그인 실패, 2단계 인증, 권한 관련 사건, 비밀번호·이메일 변경, 감사 기록 정리(`audit_prune`) | 로그인 실패(로그인 이름, IP) |

## 읽는 법

- **사용자** 열: 화면에서 한 작업은 사용자 이름 또는 `user:번호`, 자동 작업(Celery)은 `system:job:...`, 명령은 `system:command:...`로 표시된다.
- 비밀번호, 2단계 인증 비밀값 등은 `[redacted]`로 가려진다.
- **요청 ID**가 같은 기록은 한 번의 화면 요청에서 함께 생긴 것이다. 여러 화면을 오가며 같은 요청 ID로 찾으면 한 작업의 전체 기록을 볼 수 있다. 명령 실행은 `cmd-`로 시작하는 실행 ID를 쓴다.

## 자주 하는 조회

목록 오른쪽 위 **필터**에서 조건을 고르고, 검색 칸에 값을 넣는다.

| 알고 싶은 것 | 방법 |
|---|---|
| 특정 사용자의 권한이 언제 바뀌었나 | 업무 감사 기록에서 로그 `security`, 이벤트 `role.assigned`, `role.assignment_revoked` |
| 로그인 실패가 몰린 계정 | 보안 이벤트에서 이벤트 `로그인 실패` 필터, 로그인 이름 열 |
| 누가 보안 정책을 바꿨나 | 업무 감사 기록 이벤트 `settings.updated` |
| 특정 행이 어떻게 바뀌었나 | 데이터 변경 기록에서 테이블 필터와 레코드 ID 검색 |
