# 21. ເກຣດ

ເມນູ: **ເກຣດ > ຄວາມຄືບໜ້າເກຣດ**, **ການແກ້ໄຂເກຣດ**, **ບັນທຶກພາກຮຽນ**, **ການຕັ້ງຄ່າ > ນະໂຍບາຍການໃຫ້ເກຣດ**. ອາຈານໃຊ້ພອດທໍ **ການສອນຂອງຂ້ອຍ > ການປ້ອນເກຣດ**.

| ສິດ | ສິ່ງທີ່ເຮັດໄດ້ |
|---|---|
| `ເບິ່ງເກຣດ, ຄວາມຄືບໜ້າເກຣດ ແລະ ບັນທຶກພາກຮຽນ` | ເບິ່ງຄວາມຄືບໜ້າເກຣດ, ບັນທຶກພາກຮຽນ, ໃບລາຍງານເກຣດຂອງນັກສຶກສາ |
| `ຢືນຢັນ ແລະ ສົ່ງຄືນເກຣດ, ປ້ອນເກຣດແທນອາຈານ, ປິດພາກຮຽນ` | ຢືນຢັນ·ສົ່ງຄືນເກຣດຂອງກຸ່ມຮຽນ, ປ້ອນແທນອາຈານ (ບໍ່ຂຶ້ນກັບໄລຍະເວລາ), ສົ່ງແບບຍົກເວັ້ນເກີນເພດານສັດສ່ວນເກຣດ, ປິດພາກຮຽນ, ຄິດໄລ່ຄືນ. ຖ້າມອບໝາຍຕາມຂອບເຂດໜ່ວຍງານ ຈະເຮັດໄດ້ສະເພາະກຸ່ມຮຽນທີ່ໜ່ວຍງານນັ້ນເປີດສອນ |
| `ຮັບແຈ້ງເມື່ອພະນັກງານສົ່ງເກຣດນອກເພດານສັດສ່ວນເກຣດ` | ຮັບການແຈ້ງເຕືອນການສົ່ງແບບຍົກເວັ້ນ. ມອບໝາຍໃຫ້ຫົວໜ້າພາກວິຊາ, ຫົວໜ້າຫ້ອງການວິຊາການ ຕາມຂອບເຂດໜ່ວຍງານ |
| `ຂໍແກ້ໄຂເກຣດທີ່ຢືນຢັນແລ້ວ` | ຂໍແກ້ໄຂເກຣດຂອງກຸ່ມຮຽນທີ່ຕົນບໍ່ໄດ້ສອນ (ຕົວຢ່າງ: ການຍົກເລີກເກຣດຍ້ອນການທຸຈະລິດ) |
| `ອະນຸມັດ ຫຼື ປະຕິເສດການແກ້ໄຂເກຣດ (ບໍ່ແມ່ນຄຳຂໍຂອງຕົນເອງ)` | ດຳເນີນການຄຳຂໍແກ້ໄຂ |
| `ຄຸ້ມຄອງນະໂຍບາຍ GPA, ການຮຽນຄືນ, ສະຖານະທາງວິຊາການ ແລະ ນັກສຶກສາດີເດັ່ນ` | ຕັ້ງຄ່ານະໂຍບາຍການໃຫ້ເກຣດ |

ອາຈານຜູ້ສອນສາມາດປ້ອນເກຣດ ແລະ ຂໍແກ້ໄຂເກຣດຂອງກຸ່ມຮຽນຕົນເອງໄດ້ໂດຍບໍ່ຕ້ອງມີສິດ. ຄ່າເລີ່ມຕົ້ນຂອງບົດບາດ: ພະນັກງານທະບຽນມີສິດເບິ່ງ·ຢືນຢັນ·ອະນຸມັດ·ຮັບແຈ້ງການສົ່ງແບບຍົກເວັ້ນ, ພະນັກງານວິຊາການມີສິດເບິ່ງ·ຂໍແກ້ໄຂ·ຄຸ້ມຄອງນະໂຍບາຍ, ພະນັກງານອອກໃບຢັ້ງຢືນ ແລະ ຜູ້ຊ່ວຍພາກວິຊາມີສິດເບິ່ງ. ຄຳຂໍປ່ຽນວິທີປະເມີນດຳເນີນການດ້ວຍສິດ `ວາງແຜນກຸ່ມຮຽນ`.

## ສິ່ງທີ່ຕ່າງຈາກລະບົບເກົ່າ

- ໃນລະບົບເກົ່າ (YUSTIC) ເມື່ອອາຈານບັນທຶກເກຣດ ກໍເປັນເກຣດສຸດທ້າຍທັນທີ ແລະ ຫ້ອງການວິຊາການແກ້ໄຂໂດຍກົງໃນໜ້າຈໍ. ບໍ່ມີເຫດຜົນ ແລະ ຂັ້ນຕອນອະນຸມັດ ແລະ ການແກ້ໄຂຂອງບາງບັນຊີບໍ່ຖືກບັນທຶກແມ່ນແຕ່ໃນບັນທຶກສຳຮອງ. ລະບົບໃໝ່ມີຂັ້ນຕອນ **ປ້ອນ → ສົ່ງ → ຢືນຢັນ** ແລະ ເກຣດທີ່ຢືນຢັນແລ້ວຈະປ່ຽນໄດ້ກໍຕໍ່ເມື່ອ **ຄຳຂໍແກ້ໄຂຖືກອະນຸມັດໂດຍຄົນອື່ນ**. ທັງແອັບພລິເຄຊັນ ແລະ DB (ທຣິກເກີ) ຂັດຂວາງ.
- ໃນລະບົບເກົ່າ ອາຈານສາມາດດັດແປງຄຳຮ້ອງເພື່ອບັນທຶກເກຣດຂອງກຸ່ມຮຽນທີ່ຕົນບໍ່ໄດ້ສອນ. ລະບົບໃໝ່ກວດອາຈານຜູ້ສອນ ແລະ ຂອບເຂດສິດທັງທີ່ເຊີບເວີ ແລະ DB.
- GPA, ການເຕືອນທາງວິຊາການ ແລະ ນັກສຶກສາດີເດັ່ນ ບໍ່ຄິດໄລ່ໃໝ່ທຸກຄັ້ງໃນແຕ່ລະໜ້າຈໍ ແຕ່ບັນທຶກເປັນ **ບັນທຶກພາກຮຽນ**. ເມື່ອປິດພາກຮຽນ ຈະກາຍເປັນບັນທຶກທາງການຂອງພາກຮຽນນັ້ນ.
- ການຮຽນຄືນຈະເອົາເກຣດເກົ່າອອກຈາກ GPA ສະສົມ **ຫຼັງຈາກ** ເກຣດໃໝ່ຖືກຢືນຢັນແລ້ວ (ລະບົບເກົ່າເອົາອອກທັນທີທີ່ລົງທະບຽນ ແລະ ບໍ່ຄືນຄ່າເຖິງກຸ່ມຮຽນຖືກຍົກເລີກ).
- ລະບົບເກົ່າພຽງປິດເມນູເກຣດ ແຕ່ຖ້າເຂົ້າດ້ວຍທີ່ຢູ່ໂດຍກົງກໍເຫັນເກຣດ. ລະບົບໃໝ່ນຳໃຊ້ການຂັດຂວາງການເບິ່ງເກຣດທີ່ເຊີບເວີ.

## ລຳດັບຂອງພາກຮຽນ

1. **ໄລຍະເວລາດຳເນີນງານ** ([ບົດທີ 10](10-terms.md)): ໄລຍະເວລາ **ປ້ອນເກຣດ** ຕາມຊ່ວງຮຽນ (ຊ່ວງຍ່ອຍຂອງພາກຮຽນ). ອາຈານປ້ອນ·ສົ່ງໄດ້ສະເພາະໃນໄລຍະນີ້.
2. ອາຈານປ້ອນເກຣດ ແລະ ສົ່ງ. ສົ່ງອີເມວແຈ້ງເຕືອນຫາອາຈານທີ່ຍັງບໍ່ສົ່ງດ້ວຍ `uv run manage.py grades_remind_missing {ພາກຮຽນ}`.
3. ທີ່ **ຄວາມຄືບໜ້າເກຣດ** ຢືນຢັນຕໍ່ກຸ່ມຮຽນ ຫຼື ສົ່ງຄືນໃຫ້ອາຈານ.
4. ເມື່ອທຸກກຸ່ມຮຽນຢືນຢັນແລ້ວ **ບັນທຶກພາກຮຽນ > ປິດພາກຮຽນ**. ບັນທຶກພາກຮຽນ, ສະຖານະທາງວິຊາການ ແລະ ນັກສຶກສາດີເດັ່ນຖືກກຳນົດ ແລະ ພາກຮຽນກາຍເປັນສະຖານະ **ປິດເກຣດແລ້ວ**.
5. ເກຣດທີ່ຕ້ອງປ່ຽນຫຼັງຈາກນັ້ນ ດຳເນີນການດ້ວຍ **ການແກ້ໄຂເກຣດ**.

## ມາດຕາເກຣດ ແລະ ວິທີປະເມີນ

**ມາດຕາເກຣດຖືກກຳນົດຕອນຕິດຕັ້ງ ແລະ ປ່ຽນບໍ່ໄດ້** (ການຕັດສິນໃຈ 2026-10-23). ເພາະວ່າທັງເກຣດ ແລະ GPA ຢູ່ໃນມາດຕານັ້ນ. ກຳນົດດ້ວຍ `uv run manage.py setup_install --grade-scale=4.5|4.3` ຫຼື ຖ້າບໍ່ກຳນົດ ຈະເປັນມາດຕາຂອງໂປຣໄຟລ໌ທຳອິດ (ມະຫາວິທະຍາໄລເກົາຫຼີ 4.5, YUST ຂອງລະບົບເກົ່າ 4.3). ເຄື່ອງໝາຍ **ຄ່າເລີ່ມຕົ້ນ** ໃນ ຂໍ້ມູນອ້າງອີງ > ມາດຕາເກຣດ ປ່ຽນບໍ່ໄດ້ ແລະ ມາດຕາເລີ່ມຕົ້ນລຶບບໍ່ໄດ້. **ຊ່ວງຄະແນນ** ຕໍ່ເກຣດ (ຂັ້ນຕ່ຳ·ຂັ້ນສູງ %) ແລະ ຄ່າ GPA ແກ້ໄຂໃນໜ້າດຽວກັນ ([ບົດທີ 11](11-course-categories-and-grade-scales.md)).

ແຕ່ລະກຸ່ມຮຽນມີ **ວິທີປະເມີນ**. ຄ່າເລີ່ມຕົ້ນຄື **ການປະເມີນແບບເກນຄະແນນ**.

| ວິທີປະເມີນ | ການປ້ອນຂອງອາຈານ | ການບັນທຶກ | ເງື່ອນໄຂການສົ່ງ |
|---|---|---|---|
| ການປະເມີນແບບເກນຄະແນນ (ຄ່າເລີ່ມຕົ້ນ) | **ຄະແນນ (0~100)** ຕໍ່ນັກສຶກສາ. ເກຣດກຳນົດຕາມຊ່ວງຄະແນນ ເລືອກເອງບໍ່ໄດ້ (ເລືອກໂດຍກົງສະເພາະເກຣດທີ່ບໍ່ມີຄະແນນ ເຊັ່ນ I) | ຄະແນນ (ຕົ້ນສະບັບ), ເກຣດ, ຄ່າ GPA | ທຸກນັກສຶກສາມີເກຣດ |
| ການປະເມີນແບບອີງກຸ່ມ | **ເກຣດ** ຕໍ່ນັກສຶກສາ. ບໍ່ປ້ອນຄະແນນ (ຖ້າປ້ອນ ຈະປະຕິເສດ) | ເກຣດ, ຄ່າ GPA | ທຸກນັກສຶກສາມີເກຣດ + ປະຕິບັດຕາມ **ເພດານສັດສ່ວນເກຣດ** |
| ວິຊາຜ່ານ/ບໍ່ຜ່ານ | P/NP ບໍ່ຂຶ້ນກັບວິທີປະເມີນ | ເກຣດ | ທຸກນັກສຶກສາມີເກຣດ |

- ອາຈານທີ່ຕ້ອງການການປະເມີນແບບອີງກຸ່ມ ສົ່ງ **ຂໍການປະເມີນແບບອີງກຸ່ມ** (ພ້ອມເຫດຜົນ) ຈາກໜ້າປ້ອນເກຣດ. ຜູ້ມີສິດ `ວາງແຜນກຸ່ມຮຽນ` ຂອງໜ່ວຍງານເປີດສອນ (ຜູ້ຊ່ວຍພາກວິຊາ, ພະນັກງານວິຊາການ) ອະນຸມັດ ຫຼື ປະຕິເສດ (ຕ້ອງໃສ່ຄຳເຫັນ) ທີ່ **ເກຣດ > ຄຳຂໍປ່ຽນວິທີປະເມີນ** ແລະ ຜົນລັບຈະສົ່ງຫາອາຈານທາງອີເມວ. ເມື່ອອະນຸມັດແລ້ວ ເກຣດຮ່າງທີ່ບັນທຶກດ້ວຍວິທີເກົ່າຈະຖືກລຶບ. **ຫຼັງຈາກສົ່ງເກຣດແລ້ວ** ຂໍ ຫຼື ປ່ຽນບໍ່ໄດ້. ພະນັກງານກໍປ່ຽນໄດ້ຈາກໜ້າກຸ່ມຮຽນສະເພາະກ່ອນທີ່ຈະມີການປ້ອນເກຣດເທົ່ານັ້ນ.
- ເກຣດສູງສຸດຂອງການຮຽນຄືນ: ໃນການປະເມີນແບບເກນຄະແນນ ຖ້າຄະແນນໃຫ້ເກຣດສູງກວ່າເພດານ ຈະ **ຫຼຸດລົງເປັນເກຣດເພດານ** (ຄະແນນຄົງເດີມ). ໃນການປະເມີນແບບອີງກຸ່ມ ເລືອກເກຣດສູງກວ່າເພດານບໍ່ໄດ້.

## ເພດານສັດສ່ວນເກຣດ (ການປະເມີນແບບອີງກຸ່ມ)

**ການຕັ້ງຄ່າ > ນະໂຍບາຍການໃຫ້ເກຣດ > ການປະເມີນແບບອີງກຸ່ມ**: ເພດານຕໍ່ກຸ່ມເກຣດ (ຄ່າເລີ່ມຕົ້ນ ກຸ່ມ A 30%, ກຸ່ມ B 40%), ຄວາມຄາດເຄື່ອນທີ່ອະນຸຍາດເໜືອເພດານ (ຄ່າເລີ່ມຕົ້ນ 1%p), ຈຳນວນນັກສຶກສາຂັ້ນຕ່ຳທີ່ຈະກວດ (ຄ່າເລີ່ມຕົ້ນ 10 ຄົນ).

- ກຸ່ມເກຣດອີງຕາມຕົວອັກສອນ. A+·A0·A- ແມ່ນກຸ່ມ A, B+·B0·B- ແມ່ນກຸ່ມ B. ກຸ່ມເກຣດທີ່ບໍ່ມີເພດານ (C, D, F) ບໍ່ມີການຈຳກັດ.
- ຕົວຫານຂອງສັດສ່ວນຄືຈຳນວນນັກສຶກສາທີ່ໄດ້ເກຣດທີ່ນັບເຂົ້າ GPA ໃນກຸ່ມຮຽນນັ້ນ. ນັກສຶກສາທີ່ຖອນຕົວ ແລະ P/NP/I ບໍ່ນັບ.
- ກຸ່ມຮຽນທີ່ມີນັກສຶກສາໜ້ອຍກວ່າຈຳນວນຂັ້ນຕ່ຳ ຈະບໍ່ກວດ (ເພາະ A 30% ຈາກ 7 ຄົນ ເຮັດໃຫ້ພໍດີບໍ່ໄດ້).
- ອາຈານເບິ່ງການແຈກຢາຍປັດຈຸບັນ ແລະ ເພດານດ້ວຍ **ກວດເພດານສັດສ່ວນເກຣດ** ໃນໜ້າປ້ອນເກຣດ ແລະ ຖ້າເກີນເພດານ **ສົ່ງບໍ່ໄດ້**.
- ພະນັກງານທີ່ມີສິດຄຸ້ມຄອງເກຣດ ສົ່ງໄດ້ເຖິງເກີນເພດານ. ແຕ່ເປັນ **ການສົ່ງແບບຍົກເວັ້ນ**. ຕ້ອງໃສ່ເຫດຜົນ, ການແຈກຢາຍ ແລະ ເຫດຜົນຖືກບັນທຶກໃນບັນທຶກການກວດສອບກິດຈະກຳ, ມີອີເມວສົ່ງຫາຜູ້ມີສິດຮັບແຈ້ງ `ການສົ່ງເກຣດແບບຍົກເວັ້ນ` (ຫົວໜ້າພາກວິຊາ, ຫົວໜ້າຫ້ອງການວິຊາການ ແລະ ອື່ນໆ ທີ່ມອບໝາຍຕາມຂອບເຂດໜ່ວຍງານ) ແລະ ກຸ່ມຮຽນຈະມີເຄື່ອງໝາຍ **ສົ່ງແບບຍົກເວັ້ນ**. ທີ່ **ຄວາມຄືບໜ້າເກຣດ** ສາມາດກັ່ນຕອງເບິ່ງສະເພາະກຸ່ມຮຽນທີ່ສົ່ງແບບຍົກເວັ້ນໄດ້.

## ການປ້ອນເກຣດ (ອາຈານ)

ເປີດ **ການປ້ອນເກຣດ** ຂອງກຸ່ມຮຽນໃນພອດທໍ **ການສອນຂອງຂ້ອຍ**. ເທິງໜ້າຈໍສະແດງວິທີປະເມີນຂອງກຸ່ມຮຽນ, ຄຳແນະນຳການປ້ອນ ແລະ ຄຳຂໍປ່ຽນວິທີປະເມີນ.

- ການປະເມີນແບບເກນຄະແນນ: ເມື່ອໃສ່ຄະແນນ ເກຣດຈະສະແດງທັນທີ.
- ການປະເມີນແບບອີງກຸ່ມ: ເລືອກສະເພາະເກຣດ. ບໍ່ມີຊ່ອງຄະແນນ. ກວດເພດານດ້ວຍ **ກວດເພດານສັດສ່ວນເກຣດ** ແລ້ວສົ່ງ.
- ລາຍການເກຣດຕາມວິທີໃຫ້ເກຣດຂອງວິຊາ. ວິຊາທົ່ວໄປສະແດງເກຣດຕົວອັກສອນ ວິຊາຜ່ານ/ບໍ່ຜ່ານສະແດງ P/NP ([ບົດທີ 11](11-course-categories-and-grade-scales.md)).
- **ບັນທຶກຮ່າງ** ເຮັດໄດ້ທຸກເວລາ. ນັກສຶກສາບໍ່ເຫັນເກຣດທີ່ບັນທຶກເປັນຮ່າງ.
- **ສົ່ງເກຣດ** ຕ້ອງໃຫ້ທຸກນັກສຶກສາມີເກຣດ. ເມື່ອສົ່ງແລ້ວ ອາຈານແກ້ໄຂບໍ່ໄດ້ອີກ. ເກຣດທີ່ຜິດ ຖ້າກ່ອນຢືນຢັນ ໃຫ້ຂໍພະນັກງານວິຊາການສົ່ງຄືນ ຖ້າຫຼັງຢືນຢັນ ໃຫ້ຂໍແກ້ໄຂ.
- ນັກສຶກສາທີ່ຖອນຕົວສະແດງເປັນ W ແລະ ບໍ່ຕ້ອງໃສ່ເກຣດ.

## ການຢືນຢັນ ແລະ ສົ່ງຄືນ (ພະນັກງານວິຊາການ)

**ຄວາມຄືບໜ້າເກຣດ**: ລາຍຊື່ກຸ່ມຮຽນຕາມພາກຮຽນ ແລະ ຈຳນວນທີ່ຍັງບໍ່ສົ່ງ·ສົ່ງແລ້ວ·ຢືນຢັນແລ້ວ. ຕົວກັ່ນຕອງ **ພ້ອມຢືນຢັນ** ສະແດງສະເພາະກຸ່ມຮຽນທີ່ເກຣດຂອງທຸກນັກສຶກສາຖືກສົ່ງແລ້ວ.

- **ຢືນຢັນ**: ຢືນຢັນເກຣດທີ່ສົ່ງແລ້ວ. ລາຍການລົງທະບຽນກາຍເປັນສະຖານະ **ສຳເລັດ** ແລະ ນັກສຶກສາເຫັນເກຣດ. ບັນທຶກພາກຮຽນຂອງນັກສຶກສາຖືກຄິດໄລ່ຄືນ. ສາມາດເລືອກຫຼາຍກຸ່ມຮຽນແລ້ວ **ຢືນຢັນທີ່ເລືອກ** ໄດ້. ກຸ່ມຮຽນທີ່ມີນັກສຶກສາຍັງບໍ່ສົ່ງຈະຖືກຂ້າມ.
- **ສົ່ງຄືນໃຫ້ອາຈານ**: ຍົກເລີກການສົ່ງພ້ອມເຫດຜົນ. ເກຣດກັບໄປເປັນສະຖານະຮ່າງ ແລະ ມີອີເມວສົ່ງຫາອາຈານ.
- **ເກຣດ**: ເປີດໜ້າປ້ອນເກຣດ. ພະນັກງານວິຊາການສາມາດປ້ອນ ຫຼື ແກ້ໄຂເກຣດກ່ອນຢືນຢັນໄດ້ໂດຍບໍ່ຂຶ້ນກັບໄລຍະເວລາ. ຖ້າພະນັກງານແກ້ໄຂເກຣດທີ່ອາຈານ **ສົ່ງແລ້ວ** ຄ່າເກົ່າ ແລະ ຄ່າໃໝ່ຈະຖືກບັນທຶກໃນບັນທຶກການກວດສອບ `grades.submitted_changed`.

## ການແກ້ໄຂເກຣດ

ເປັນວິທີດຽວທີ່ຈະປ່ຽນເກຣດທີ່ຢືນຢັນແລ້ວ.

1. ຄຳຂໍ: ອາຈານກົດ **ຂໍແກ້ໄຂ** ຂອງນັກສຶກສາຄົນນັ້ນໃນໜ້າປ້ອນເກຣດ (ພ້ອມເຫດຜົນ, ການປະເມີນແບບເກນຄະແນນໃສ່ຄະແນນໃໝ່, ການປະເມີນແບບອີງກຸ່ມໃສ່ເກຣດໃໝ່). ເພດານຂອງການຮຽນຄືນນຳໃຊ້ກັບການແກ້ໄຂເຊັ່ນກັນ. ສຳລັບກຸ່ມຮຽນທີ່ຕົນບໍ່ໄດ້ສອນ ພະນັກງານທີ່ມີສິດ `ຂໍແກ້ໄຂເກຣດທີ່ຢືນຢັນແລ້ວ` ສົ່ງຄຳຂໍຈາກໜ້າດຽວກັນ. ໜຶ່ງເກຣດມີຄຳຂໍທີ່ກຳລັງດຳເນີນການໄດ້ພຽງໜຶ່ງ.
2. ການດຳເນີນການ: ທີ່ **ເກຣດ > ການແກ້ໄຂເກຣດ** (ຄ່າເລີ່ມຕົ້ນຄືລາຍການລໍຖ້າ ແລະ ເມນູສະແດງຈຳນວນທີ່ລໍຖ້າ) ກົດ **ອະນຸມັດ** ຫຼື **ປະຕິເສດ** (ຕ້ອງໃສ່ຄຳເຫັນ). ຜູ້ສົ່ງຄຳຂໍດຳເນີນການຄຳຂໍຂອງຕົນເອງບໍ່ໄດ້ (ຂໍ້ຈຳກັດຂອງ DB ກໍຂັດຂວາງ).
3. ເມື່ອອະນຸມັດ ເກຣດ (ການປະເມີນແບບເກນຄະແນນແມ່ນຄະແນນ ແລະ ເກຣດ) ຈະປ່ຽນທັນທີ ແລະ ບັນທຶກພາກຮຽນຂອງນັກສຶກສາ ແລະ GPA ສະສົມຂອງພາກຮຽນຕໍ່ໆໄປຈະຖືກຄິດໄລ່ຄືນ. ສະຖານະທາງວິຊາການ ແລະ ນັກສຶກສາດີເດັ່ນຍັງຄົງຄ່າທີ່ກຳນົດຕອນປິດພາກຮຽນ.

ຜູ້ສົ່ງຄຳຂໍສາມາດ **ຍົກເລີກຄຳຂໍ** ທີ່ລໍຖ້າຢູ່ໄດ້. ທຸກຄຳຂໍ ແລະ ການດຳເນີນການຖືກບັນທຶກພ້ອມເຫດຜົນໃນບັນທຶກການກວດສອບກິດຈະກຳ.

|---|---|---|
| ເກນການເຕືອນທາງວິຊາການ | GPA ພາກຮຽນຕ່ຳກວ່າ 1.75 | ຕ່ຳກວ່າ 1.3 |

| ທົດສະນິຍົມຂອງ GPA | 2 ຕຳແໜ່ງ ປັດເສດ | 3 ຕຳແໜ່ງ ປັດເສດ |
| ມາດຕາເກຣດ (ກຳນົດຕອນຕິດຕັ້ງ) | 4.5 (KR45) | 4.3 (YUST43) |

- **ການເຕືອນທາງວິຊາການ**: GPA ພາກຮຽນ **ຕ່ຳກວ່າ** ເກນ. ພາກຮຽນທີ່ຮຽນແຕ່ວິຊາຜ່ານ/ບໍ່ຜ່ານ ບໍ່ເຕືອນ.
- **ພິຈາລະນາໃຫ້ອອກ**: ໝາຍເມື່ອຈຳນວນການເຕືອນເຖິງເກນ. ການໃຫ້ອອກຈິງດຳເນີນການດ້ວຍການປ່ຽນສະຖານະນັກສຶກສາ ([ບົດທີ 13](13-status-changes-and-advisors.md)).
- ຖ້າຕັດສິນສະເພາະພາກຮຽນປົກກະຕິ ພາກຮ້ອນ·ພາກໜາວຈະບໍ່ມີສະຖານະທາງວິຊາການ ແລະ ບໍ່ຕັດການເຕືອນຕິດຕໍ່ກັນ.
- **ນັກສຶກສາດີເດັ່ນ**: ຈັດອັນດັບນັກສຶກສາທີ່ຄົບເກນຕາມ GPA ພາກຮຽນ ແຍກຕາມຫຼັກສູດ (ຄະແນນເທົ່າກັນໄດ້ອັນດັບດຽວກັນ ແລະ ຂ້າມອັນດັບຖັດໄປ).
- **ສະຖານະທາງວິຊາການ** ຂອງບັນທຶກນັກສຶກສາປ່ຽນຕາມການຕັດສິນຫຼ້າສຸດ. "ສະຖານະທາງວິຊາການ" ໃນໄລຍະເວລາດຳເນີນງານ ຫຼື ເງື່ອນໄຂຜູ້ລົງທະບຽນໃຊ້ຄ່ານີ້.

ໃນໜ້າ **ບັນທຶກພາກຮຽນ** ກັ່ນຕອງຕາມພາກຮຽນ, ສະຖານະທາງວິຊາການ, ນັກສຶກສາດີເດັ່ນ ແລະ ຫຼັກສູດ ເພື່ອເບິ່ງລາຍຊື່ຜູ້ຖືກເຕືອນທາງວິຊາການ ແລະ ລາຍຊື່ນັກສຶກສາດີເດັ່ນ (ບົດລາຍງານການເຕືອນທາງວິຊາການ·ນັກສຶກສາດີເດັ່ນຂອງລະບົບເກົ່າ). **ປິດພາກຮຽນ** ໃຫ້ແລ່ນດ້ວຍ **ກວດຜົນເທົ່ານັ້ນ** (ຄ່າເລີ່ມຕົ້ນ) ກ່ອນ ເພື່ອເບິ່ງກຸ່ມຮຽນທີ່ຍັງບໍ່ຢືນຢັນ ແລ້ວປິດຕົວເລືອກນັ້ນແລ້ວແລ່ນອີກຄັ້ງ. **ຄິດໄລ່ຄືນ** ໃຊ້ເມື່ອປ່ຽນນະໂຍບາຍແລ້ວຕ້ອງການນຳໃຊ້ກັບບັນທຶກພາກຮຽນທີ່ຜ່ານມາ (ຕ້ອງໃສ່ເຫດຜົນ).

## ໜ້າຈໍຂອງນັກສຶກສາ ແລະ ໃບລາຍງານເກຣດ

ເມື່ອພະນັກງານເປີດເບິ່ງໃບລາຍງານເກຣດຂອງນັກສຶກສາ ຈະຖືກບັນທຶກໃນບັນທຶກການກວດສອບ `transcript.viewed` (ລວມລະຫັດນັກສຶກສາ).

- ພອດທໍ **ເກຣດ**: ເກຣດທີ່ຢືນຢັນແລ້ວຕາມພາກຮຽນ (ຖອນຕົວເປັນ W), GPA ພາກຮຽນ ແລະ ໜ່ວຍກິດທີ່ໄດ້ຮັບ, GPA ສະສົມ, ສະຖານະທາງວິຊາການ, ນັກສຶກສາດີເດັ່ນ. ຜູ້ຈົບການສຶກສາກໍເບິ່ງໄດ້. ເກຣດທີ່ຍັງບໍ່ຢືນຢັນຈະບໍ່ສະແດງ.
- **ພິມ**: ໃບລາຍງານເກຣດເພື່ອກວດເບິ່ງ (ບໍ່ເປັນທາງການ). ໃບຄະແນນທາງການສ້າງດ້ວຍການອອກໃບຢັ້ງຢືນ ([ບົດທີ 23](23-certificates.md)). ພະນັກງານເປີດໃບລາຍງານເກຣດຂອງນັກສຶກສາດ້ວຍ **ໃບລາຍງານເກຣດ** ໃນໜ້າບັນທຶກນັກສຶກສາ ຫຼື ບັນທຶກພາກຮຽນ (ສິດ `ເບິ່ງເກຣດ`).
- ນັກສຶກສາທີ່ຖືກເປີດ **ຂັດຂວາງການເບິ່ງເກຣດ** ໃນ **ການລະງັບການລົງທະບຽນ** ຈະເບິ່ງໜ້າເກຣດ ແລະ ໃບລາຍງານເກຣດບໍ່ໄດ້ ([ບົດທີ 20](20-registration.md)).
- ໃນໄລຍະການປະເມີນການສອນ ນັກສຶກສາທີ່ຍັງບໍ່ສຳເລັດການປະເມີນການສອນຂອງພາກຮຽນນັ້ນ ຈະຖືກປິດເກຣດຂອງພາກຮຽນນັ້ນ (ການຕັ້ງຄ່າ, [ບົດທີ 22](22-course-evaluation.md)).

## ນະໂຍບາຍການໃຫ້ເກຣດ

**ການຕັ້ງຄ່າ > ນະໂຍບາຍການໃຫ້ເກຣດ** (ສິດ `ຄຸ້ມຄອງນະໂຍບາຍ GPA, ການຮຽນຄືນ, ສະຖານະທາງວິຊາການ ແລະ ນັກສຶກສາດີເດັ່ນ`). ປ່ຽນລາຍການໃນຕາຕະລາງຂ້າງເທິງ. ນະໂຍບາຍທີ່ປ່ຽນຈະນຳໃຊ້ຕັ້ງແຕ່ການຄິດໄລ່ຄັ້ງຕໍ່ໄປ. ຖ້າຕ້ອງການນຳໃຊ້ກັບບັນທຶກພາກຮຽນທີ່ຜ່ານມາ ໃຫ້ **ຄິດໄລ່ຄືນ**. ສະຖານະທາງວິຊາການ ແລະ ນັກສຶກສາດີເດັ່ນຖືກກຳນົດຕອນປິດພາກຮຽນ ຈຶ່ງບໍ່ນຳໃຊ້ຄືນກັບພາກຮຽນທີ່ປິດແລ້ວ.

## ໜ້າຈໍຂອງການຕິດຕັ້ງນີ້

ໜ້າຈໍ ແລະ ໜ້າທີ່ຄືກັນກັບລະບົບເດີມ (Filament, Livewire); ວິທີໃຊ້ແຕກຕ່າງເລັກນ້ອຍ.

- ເມນູແຖວຂອງ **ສະຖານະການປະມວນຜົນເກຣດ**: **ເກຣດ** (ໜ້າປ້ອນເກຣດຂອງພອດທັລ), **ຢືນຢັນ** (ໜ້າຢືນຢັນ), **ສົ່ງຄືນໃຫ້ອາຈານ** (ໜ້າປ້ອນເຫດຜົນ). ເພື່ອຢືນຢັນຫຼາຍກຸ່ມຮຽນ ໃຫ້ເລືອກໃນລາຍການແລ້ວເລືອກ **ຢືນຢັນກຸ່ມຮຽນທີ່ເລືອກ** ໃນລາຍການຄຳສັ່ງ. ຕົວກັ່ນຕອງ: ພາກຮຽນ (ຄ່າເລີ່ມຕົ້ນແມ່ນພາກຮຽນທີ່ກຳລັງດຳເນີນ, **ທັງໝົດ** ສຳລັບທຸກພາກຮຽນ), ໜ່ວຍງານທີ່ເປີດ, ສົ່ງແບບຂໍ້ຍົກເວັ້ນ, ພ້ອມຢືນຢັນ.
- **ອະນຸມັດ** ແລະ **ປະຕິເສດ** ໃນເມນູແຖວຂອງ **ການແກ້ໄຂເກຣດ** ແລະ **ຄຳຮ້ອງປ່ຽນວິທີປະເມີນ** ຈະເປີດໜ້າປ້ອນຄຳເຫັນ. ລາຍການເລີ່ມຕົ້ນແມ່ນຄຳຮ້ອງທີ່ລໍຖ້າ ແລະ ເມນູສະແດງຈຳນວນທີ່ລໍຖ້າ.
- **ປິດພາກຮຽນ** ຢູ່ເທິງລາຍການ **ບັນທຶກພາກຮຽນ**: ພາກຮຽນ, **ເບິ່ງຕົວຢ່າງເທົ່ານັ້ນ** (ເປີດໄວ້ເປັນຄ່າເລີ່ມຕົ້ນ), ເຫດຜົນ. ການເບິ່ງຕົວຢ່າງສະແດງເປັນຂໍ້ຄວາມວ່າປິດໄດ້ຫຼືບໍ່ ແລະ ກຸ່ມຮຽນທີ່ຍັງບໍ່ຢືນຢັນ (ສູງສຸດ 30). ເມື່ອເລີ່ມປິດ ຈະດຳເນີນເປັນວຽກໃນຄິວ (Celery) ຄັ້ງລະ 100 ນັກສຶກສາ ແລະ ການປິດທີ່ກຳລັງດຳເນີນຈະສະແດງຄວາມຄືບໜ້າຢູ່ເທິງລາຍການບັນທຶກພາກຮຽນ. ເມື່ອສຳເລັດ ພາກຮຽນຈະປ່ຽນເປັນ **ປິດເກຣດ** ແລະ ພະນັກງານທີ່ເລີ່ມຈະໄດ້ຮັບເມວ. ຖ້າວຽກໃດໜຶ່ງລົ້ມເຫຼວ ການປິດຈະບໍ່ສຳເລັດ ແລະ ພາກຮຽນຄົງເດີມ; ແກ້ໄຂສາເຫດແລ້ວປິດອີກຄັ້ງ (ໄດ້ຜົນຄືເກົ່າ). ດ້ວຍຄຳສັ່ງ: `uv run manage.py term_close {ພາກຮຽນ} --dry-run`, `uv run manage.py term_close {ພາກຮຽນ} --reason=...` ([ຄຳສັ່ງ](../operations/commands.md)).
- ໃນ **ນະໂຍບາຍການປະມວນຜົນເກຣດ** ໃຫ້ຂຽນເພດານອັດຕາເກຣດເປັນຕົວອັກສອນ ແລະ ເປີເຊັນ ຂັ້ນດ້ວຍເຄື່ອງໝາຍຈຸດ ເຊັ່ນ `A=30, B=40`. ປ່ອຍວ່າງໝາຍເຖິງບໍ່ມີເພດານ.
- ການປ້ອນເກຣດໃນພອດທັລ: ສຳລັບການປະເມີນແບບສົມບູນ ເກຣດຈະສະແດງຢູ່ຂ້າງຄະແນນບໍ່ດົນຫຼັງປ້ອນ. ປຸ່ມ **ບັນທຶກຊົ່ວຄາວ**, **ກວດເພດານອັດຕາເກຣດ** ແລະ **ສົ່ງເກຣດ** ຢູ່ລຸ່ມສຸດຂອງໜ້າ; ເມື່ອບັນທຶກບໍ່ສຳເລັດ (ເຊັ່ນ ຄະແນນນອກຂອບເຂດ) ຄ່າທີ່ປ້ອນ ແລະ ຂໍ້ຜິດພາດຈະສະແດງອີກຄັ້ງ. ກົດ **ຂໍແກ້ໄຂ** ໃນແຖວນັກສຶກສາ ຈະເປີດຊ່ອງປ້ອນຢູ່ລຸ່ມຕາຕະລາງ.
- ທີ່ຢູ່ໃບລາຍງານເກຣດສຳລັບພະນັກງານ: `/student-records/{ID ທະບຽນນັກສຶກສາ}/transcript/` (ປຸ່ມ **ໃບລາຍງານເກຣດ** ໃນໜ້າທະບຽນນັກສຶກສາ, **ໃບລາຍງານເກຣດ** ໃນແຖວບັນທຶກພາກຮຽນ). ເພີ່ມ `?format=pdf` ທາງທ້າຍເພື່ອໄດ້ PDF.
- ການນຳເຂົ້າຄະແນນຈາກ LMS ຈະເພີ່ມໃນໜ້າປ້ອນເກຣດໃນ Phase 12. ການເຊື່ອງເກຣດຂອງພາກຮຽນທີ່ຍັງປະເມີນການສອນບໍ່ສຳເລັດ ຈະເຊື່ອມໂດຍການປະເມີນການສອນໃນ Phase 7.
