# 2. ຜູ້ໃຊ້ ແລະ ບົດບາດ

## ແນວຄວາມຄິດ

| ຄຳສັບ | ຄວາມໝາຍ |
|---|---|
| ສິດ | ຄຸນສົມບັດໃນການໃຊ້ໜ້າທີ່ໜຶ່ງ. ຕົວຢ່າງ: `ເບິ່ງຜູ້ໃຊ້`, `ຣີເຊັດການຢືນຢັນສອງຂັ້ນຕອນ` |
| ບົດບາດ | ຊຸດຂອງສິດ. ຕົວຢ່າງ: ຜູ້ຮັບຜິດຊອບທະບຽນນັກສຶກສາ, ຜູ້ຊ່ວຍພາກວິຊາ |
| ການມອບບົດບາດ | ການມອບບົດບາດໃຫ້ຜູ້ໃຊ້ໂດຍກຳນົດຂອບເຂດ ແລະ ໄລຍະເວລາ |
| ຂອບເຂດ | ບ່ອນທີ່ບົດບາດມີຜົນ. **ທັງໝົດ**, **ໜ່ວຍງານ** (ຄະນະ, ພາກວິຊາ ແລະ ອື່ນໆ), **ຫຼັກສູດ** |
| ບົດບາດຕາມສະຖານະ (Persona) | ຜູ້ສະໝັກ, ນັກສຶກສາ, ຜູ້ຈົບການສຶກສາ, ອາຈານ, ອາຈານທີ່ປຶກສາ. ໄດ້ຮັບໂດຍອັດຕະໂນມັດຕາມຂໍ້ມູນວິຊາການ ແລະ ບໍ່ສາມາດມອບໂດຍກົງໄດ້ |

ເມື່ອຜູ້ຮັບຜິດຊອບວຽກປ່ຽນ ພຽງແຕ່ປ່ຽນການຈັດບົດບາດ ຫຼື ການມອບບົດບາດ ໂດຍບໍ່ຕ້ອງແກ້ໄຂໂປຣແກຣມ. ການປ່ຽນແປງທັງໝົດຈະຖືກບັນທຶກໄວ້ໃນບັນທຶກການກວດສອບ.

## ການສ້າງບັນຊີຜູ້ໃຊ້

1. ທີ່ **ຜູ້ໃຊ້ ແລະ ສິດເຂົ້າໃຊ້ > ຜູ້ໃຊ້** ກົດ **ເພີ່ມຜູ້ໃຊ້**.
2. ປ້ອນຊື່, ອີເມວ, ພາສາ ແລ້ວບັນທຶກ.
3. ລິ້ງຕັ້ງລະຫັດຜ່ານຈະຖືກສົ່ງໄປຫາອີເມວຂອງຜູ້ໃຊ້. ຜູ້ບໍລິຫານບໍ່ສາມາດຮູ້ລະຫັດຜ່ານໄດ້.

ບັນຊີຈະບໍ່ຖືກລຶບ. ຖ້າຕ້ອງການຢຸດການໃຊ້ງານ ເຊັ່ນ ກໍລະນີລາອອກຈາກວຽກ ໃຫ້ເປີດໜ້າຜູ້ໃຊ້ ແລ້ວປິດ **ເປີດໃຊ້** ແລະ ບັນທຶກ. ບັນຊີທີ່ຖືກປິດໃຊ້ງານຈະເຂົ້າສູ່ລະບົບບໍ່ໄດ້ ແລະ ສິດທັງໝົດຈະຫາຍໄປ. ໜ້າຈໍທີ່ເຂົ້າສູ່ລະບົບຄ້າງຢູ່ກໍຈະຖືກອອກຈາກລະບົບທັນທີໃນຄຳຮ້ອງຂໍຄັ້ງຕໍ່ໄປ.

ມາດຕະການປ້ອງກັນໃນການແກ້ໄຂບັນຊີ

- ບໍ່ສາມາດປິດໃຊ້ງານບັນຊີຂອງຕົນເອງໄດ້.
- ບໍ່ສາມາດແກ້ໄຂບັນຊີທີ່ມີສິດທີ່ຕົນເອງບໍ່ມີ (ຜູ້ບໍລິຫານທີ່ມີສິດສູງກວ່າ) ໄດ້.
- ຖ້າປ່ຽນອີເມວ ການຢືນຢັນອີເມວຈະຖືກຣີເຊັດ, ທຸກຊ່ວງຮຽນການເຂົ້າສູ່ລະບົບຂອງຜູ້ໃຊ້ນັ້ນຈະສິ້ນສຸດ ແລະ ເຫດການຄວາມປອດໄພ `ປ່ຽນອີເມວ` ຈະຖືກບັນທຶກໄວ້.
- ເມື່ອຜູ້ໃຊ້ປ່ຽນລະຫັດຜ່ານ ຊ່ວງຮຽນໃນອຸປະກອນອື່ນ ແລະ ອຸປະກອນທີ່ຖືກຈື່ໄວ້ ຈະສິ້ນສຸດ ແລະ ເຫດການຄວາມປອດໄພ `ປ່ຽນລະຫັດຜ່ານ` ຈະຖືກບັນທຶກໄວ້.

## ການສ້າງ ແລະ ແກ້ໄຂບົດບາດ

1. ທີ່ **ຜູ້ໃຊ້ ແລະ ສິດເຂົ້າໃຊ້ > ບົດບາດ** ກົດ **ເພີ່ມບົດບາດ** ຫຼື ເປີດບົດບາດຈາກລາຍການ.
2. **ຊື່ພາຍໃນ** ຂຽນດ້ວຍຕົວອັກສອນລາຕິນຕົວນ້ອຍ ແລະ ຂີດກ້ອງ (ຕົວຢ່າງ: `exam_office`). ຫຼັງຈາກສ້າງແລ້ວ ບໍ່ຄວນປ່ຽນ.
3. **ຊື່ສະແດງ** ປ້ອນຕາມແຕ່ລະພາສາ. ຊື່ພາສາອັງກິດແມ່ນບັງຄັບ. ຖ້າປະຊ່ອງພາສາໃດວ່າງ ຊື່ໃນພາສານັ້ນຈະຖືກລຶບ.
4. ທີ່ **ສິດ** ໝາຍຕິກຕາມແຕ່ລະໜ້າທີ່. ເມື່ອບັນທຶກ ສິດທີ່ເພີ່ມ/ລຶບຈະຖືກບັນທຶກໄວ້ໃນບັນທຶກການກວດສອບ.

| ປະເພດບົດບາດ | ແກ້ໄຂ | ລຶບ |
|---|---|---|
| ບົດບາດລະບົບ (ຜູ້ບໍລິຫານລະບົບ) | ສະເພາະຊື່. ສິດມີຄົບທຸກລາຍການສະເໝີ | ບໍ່ໄດ້ |
| ບົດບາດຕາມສະຖານະ | ຊື່ສະແດງ ແລະ ສິດ. ຊື່ພາຍໃນບໍ່ໄດ້ | ບໍ່ໄດ້ |
| ບົດບາດທົ່ວໄປ | ທັງໝົດ | ສະເພາະເມື່ອບໍ່ມີການມອບບົດບາດໃນປັດຈຸບັນ |

## ການມອບບົດບາດ

1. ທີ່ **ຜູ້ໃຊ້ ແລະ ສິດເຂົ້າໃຊ້ > ຜູ້ໃຊ້** ເປີດຜູ້ໃຊ້ ແລ້ວໄປທີ່ລາຍການ **ການມອບບົດບາດ** ຢູ່ດ້ານລຸ່ມ.
2. ກົດ **ມອບບົດບາດ** ຢູ່ດ້ານເທິງຂອງໜ້າ ແລ້ວປ້ອນບົດບາດ, ຂອບເຂດ, ວັນເລີ່ມ/ສິ້ນສຸດ (ທາງເລືອກ) ແລະ **ເຫດຜົນ**.
   - ຖ້າຂອບເຂດເປັນໜ່ວຍງານ ຫຼື ຫຼັກສູດ ໃຫ້ເລືອກທີ່ **ເປົ້າໝາຍຂອບເຂດ**. ຖ້າເລືອກໜ່ວຍງານ ໜ່ວຍງານທັງໝົດທີ່ຢູ່ລຸ່ມມັນຈະຖືກລວມເຂົ້ານຳ.
   - ຖ້າປະວັນເລີ່ມວ່າງ ຈະມີຜົນທັນທີ, ຖ້າປະວັນສິ້ນສຸດວ່າງ ຈະບໍ່ມີກຳນົດ.
3. ການມອບບົດບາດຈະບໍ່ຖືກແກ້ໄຂ. ເມື່ອຕ້ອງການປ່ຽນ ໃຫ້ **ສິ້ນສຸດການມອບບົດບາດ** ເດີມ (ຕ້ອງມີເຫດຜົນ) ແລ້ວມອບໃໝ່. ປະຫວັດຈະຄົງຢູ່ຄືເກົ່າ.

ບໍ່ສາມາດສິ້ນສຸດການມອບບົດບາດຂອງຕົນເອງໄດ້ (ການແບ່ງແຍກໜ້າທີ່). ໃຫ້ຂໍຜູ້ບໍລິຫານຄົນອື່ນດຳເນີນການ.

ກົດລະບຽບປ້ອງກັນການຍົກລະດັບສິດ

- ບໍ່ສາມາດມອບບົດບາດໃຫ້ຕົນເອງໄດ້.
- ບໍ່ສາມາດມອບບົດບາດທີ່ມີສິດທີ່ຕົນເອງບໍ່ມີໄດ້.
- ຂອບເຂດເລືອກໄດ້ພຽງພາຍໃນຂອບເຂດຂອງສິດ `ມອບ ແລະ ສິ້ນສຸດບົດບາດ` ຂອງຕົນເອງເທົ່ານັ້ນ. ຕົວຢ່າງ ຜູ້ບໍລິຫານທີ່ໄດ້ຮັບສິດໃນຂອບເຂດຄະນະວິສະວະກຳສາດ ບໍ່ສາມາດມອບໃນຂອບເຂດທັງໝົດ ຫຼື ຂອບເຂດຄະນະອື່ນໄດ້.
- ຄຳສັ່ງ `security_create_administrator` ທີ່ສ້າງຜູ້ບໍລິຫານຄົນທຳອິດແມ່ນຜູ້ດຳເນີນງານເຊີບເວີເປັນຜູ້ແລ່ນ ຈຶ່ງບໍ່ນຳໃຊ້ກົດລະບຽບນີ້.
