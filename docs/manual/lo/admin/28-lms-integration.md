# 28. ການເຊື່ອມຕໍ່ LMS

ເມນູ: ໜ້າບໍລິຫານ **ການເຊື່ອມຕໍ່ LMS > ແພລດຟອມ LMS**, **ການເຊື່ອມຕໍ່ວິຊາ**, **ບັນທຶກການຊິງຄ໌** (ສິດ `ຄຸ້ມຄອງແພລດຟອມ LMS, ການເຊື່ອມຕໍ່ ແລະ ການຊິງຄ໌`, ຄ່າເລີ່ມຕົ້ນ: ຜູ້ບໍລິຫານລະບົບ, ຜູ້ຮັບຜິດຊອບວິຊາການ). ອາຈານໃຊ້ລິ້ງ LMS ໃນ **ການສອນຂອງຂ້ອຍ** ຂອງພອດທໍ ແລະ ລາຍລະອຽດກຸ່ມຮຽນ ແລະ **ໂຫຼດຄະແນນຈາກ LMS** ໃນການປ້ອນເກຣດ. ການໂຫຼດມີເງື່ອນໄຂດຽວກັນກັບການປ້ອນເກຣດ (ອາຈານຜູ້ສອນພາຍໃນໄລຍະເວລາປ້ອນເກຣດ).

ລາຍລະອຽດສຳລັບນັກພັດທະນາ (ການຂຽນຕົວເຊື່ອມຕໍ່, API) ຢູ່ທີ່ [ຄູ່ມືການເຊື່ອມຕໍ່ LMS](../../../lms-integration-guide.md).

## ອັນໃດໄປໃສ

| ລະບົບທະບຽນ → LMS | ເວລາ |
|---|---|
| ກຸ່ມຮຽນ (ສ້າງວິຊາ) + ອາຈານຜູ້ສອນ | ເມື່ອ **ເຜີຍແຜ່** ກຸ່ມຮຽນ ແລະ `lms_sync` |
| ຢືນຢັນການລົງທະບຽນ → ເພີ່ມສະມາຊິກ | ທັນທີທີ່ລົງທະບຽນຮຽນ·ເລື່ອນຂຶ້ນຈາກລາຍຊື່ລໍຖ້າ·ພະນັກງານດຳເນີນການລົງທະບຽນ |
| ຖອນ·ຖອນຕົວ → ເອົາສະມາຊິກອອກ | ທັນທີ |
| ການທຽບທັງໝົດ | ທຸກວັນ 02:30 (`lms_reconcile`, ວຽກຕາມກຳນົດເວລາ `lms.reconcile`) |

| LMS → ລະບົບທະບຽນ | ເວລາ |
|---|---|
| ຄະແນນສຸດທ້າຍ (ຮ່າງ) | ເມື່ອອາຈານກົດ **ໂຫຼດຄະແນນຈາກ LMS** ໃນການປ້ອນເກຣດ. ການບັນທຶກ·ສົ່ງເປັນໜ້າທີ່ຂອງອາຈານ |

ເກຣດທີ່ຢືນຢັນແລ້ວບໍ່ສົ່ງໄປ LMS. ເອກະສານການສອນ·ວຽກບ້ານ·ແບບທົດສອບຢູ່ໃນ LMS.

## ແພລດຟອມ

**ແພລດຟອມ LMS**: ລະຫັດ, ຊື່ (ຕາມພາສາ), ໄດຣເວີ, URL ພື້ນຖານ, ຂໍ້ມູນຢືນຢັນຕົວຕົນ, ໃຊ້ງານ, ຊິງຄ໌ລາຍຊື່ນັກສຶກສາ, ດຶງຄະແນນສຸດທ້າຍ.

- ໄດຣເວີ **ບໍ່ມີ (ບັນທຶກເທົ່ານັ້ນ)**: ບໍ່ເອີ້ນຫຍັງເລີຍ ພຽງບັນທຶກເນື້ອໃນທີ່ຈະສົ່ງ. ໃຊ້ເມື່ອກວດສອບຂັ້ນຕອນກ່ອນເຊື່ອມຕໍ່ ຫຼື ສາທິດ. ແພລດຟອມ `DEMO` ໃນຂໍ້ມູນເດໂມແມ່ນອັນນີ້.
- `Moodle`, `Open edX`: ຍັງບໍ່ມີຕົວເຊື່ອມຕໍ່ (ສະແດງວ່າ "ຍັງບໍ່ໄດ້ພັດທະນາ"). ຖ້າເລືອກ ການຊິງຄ໌ຈະຖືກບັນທຶກເປັນລົ້ມເຫຼວ.
- ເມື່ອເປີດ **ໃຊ້ງານ** ຕັ້ງແຕ່ນັ້ນການເຜີຍແຜ່ກຸ່ມຮຽນ·ການປ່ຽນແປງການລົງທະບຽນຈະຖືກສົ່ງທັນທີ ແລະ ຖືກລວມໃນການທຽບຕອນກາງຄືນ.
- **ຂໍ້ມູນຢືນຢັນຕົວຕົນ** ຂຽນແຖວລະໜຶ່ງ `key=value` (ເຊັ່ນ `token=...`). ເກັບແບບເຂົ້າລະຫັດ ແລະ ບໍ່ສະແດງຄືນ. ຖ້າປ່ອຍວ່າງຕອນແກ້ໄຂ ຈະຄົງຄ່າທີ່ເກັບໄວ້. ບັນທຶກການປ່ຽນແປງຂໍ້ມູນກໍ່ບໍ່ເກັບຄ່ານີ້.

## ການເຊື່ອມຕໍ່ວິຊາ ແລະ ບັນທຶກການຊິງຄ໌

- **ການເຊື່ອມຕໍ່ວິຊາ**: ກຸ່ມຮຽນໃດເຊື່ອມຕໍ່ກັບວິຊາໃດຂອງແພລດຟອມ (ID, URL), ສະຖານະ (ລໍຖ້າ/ເຊື່ອມຕໍ່ແລ້ວ/ລົ້ມເຫຼວ), ການຊິງຄ໌ຄັ້ງຫຼ້າສຸດ ແລະ ຂໍ້ຜິດພາດ. ກັ່ນຕອງຕາມແພລດຟອມ, ສະຖານະ, ພາກຮຽນ ແລະ ຄົ້ນຫາຕາມລະຫັດວິຊາ. ການດຳເນີນການຂອງແຖວ **ຊິງຄ໌ອີກຄັ້ງ** (ຜ່ານໜ້າຢືນຢັນ) ເພື່ອສົ່ງກຸ່ມຮຽນ·ອາຈານ·ນັກສຶກສາໄປໃໝ່.
- **ບັນທຶກການຊິງຄ໌**: ຜົນ ແລະ ຂໍ້ຄວາມຕໍ່ຂັ້ນຕອນ (ວິຊາ, ເພີ່ມ·ເອົາສະມາຊິກອອກ, ດຶງຄະແນນ, ສົ່ງຄະແນນມາແລ້ວ, ທຽບ). ເບິ່ງສາເຫດຂອງຄວາມລົ້ມເຫຼວໄດ້ທີ່ນີ້. ເປີດແຖວເພື່ອເບິ່ງເວລາເລີ່ມ·ສິ້ນສຸດ ແລະ ເນື້ອໃນ (payload).
- ຄຳສັ່ງ: `uv run manage.py lms_sync {ແພລດຟອມ} --term={ພາກຮຽນ}` (ສົ່ງທັງໝົດ, `--dry-run`), `uv run manage.py lms_reconcile` (ທຽບ). ເບິ່ງ [ຄຳສັ່ງການດຳເນີນງານ](../operations/commands.md).

## ພອດທໍ

- ລິ້ງວິຊາຂອງແພລດຟອມສະແດງໃນລາຍລະອຽດກຸ່ມຮຽນຂອງນັກສຶກສາ·ອາຈານ ແລະ ລາຍການ **ການສອນຂອງຂ້ອຍ** ຂອງອາຈານ (ຖັນ **LMS**, ສະເພາະກຸ່ມຮຽນທີ່ເຊື່ອມຕໍ່ແລ້ວ).
- ການປ້ອນເກຣດ: ຖ້າແພລດຟອມເປີດ **ດຶງຄະແນນສຸດທ້າຍ** ແລະ ກຸ່ມຮຽນເຊື່ອມຕໍ່ແລ້ວ ຈະມີປຸ່ມ **ໂຫຼດຄະແນນຈາກ LMS**. ຕື່ມສະເພາະຊ່ອງຄະແນນ ບໍ່ບັນທຶກ.

## API ສຳລັບການເຊື່ອມຕໍ່ພາຍນອກ

ມີ API (`/api/v1/lms/platforms/...`) ສຳລັບແພລດຟອມທີ່ແຈ້ງຜົນພາຍຫຼັງ ຫຼື ສົ່ງຄະແນນມາເອງ. ສ້າງບັນຊີສຳລັບການເຊື່ອມຕໍ່ແຍກຕ່າງຫາກ ແລະ ໃຫ້ສະເພາະສິດ `ຄຸ້ມຄອງແພລດຟອມ LMS, ການເຊື່ອມຕໍ່ ແລະ ການຊິງຄ໌`; ຜູ້ດຳເນີນງານອອກ token ດ້ວຍ `uv run manage.py api_issue_token {ອີເມວ} --days=365` ແລ້ວມອບໃຫ້ຜູ້ດູແລແພລດຟອມ. Token ສະແດງພຽງເທື່ອດຽວຕອນອອກ. ຍົກເລີກດ້ວຍ `api_revoke_tokens`. ການອອກ ແລະ ການຍົກເລີກຖືກບັນທຶກໃນບັນທຶກການກວດສອບ.

- ຄະແນນທີ່ໄດ້ຮັບຜ່ານການສົ່ງຄະແນນ (`.../scores/`) ກໍ່ບໍ່ຖືກບັນທຶກເຊັ່ນກັນ. ເມື່ອອາຈານກົດ **ໂຫຼດຄະແນນຈາກ LMS** ຄະແນນທີ່ໄດ້ຮັບຫຼ້າສຸດຈະຖືກຕື່ມເປັນຮ່າງ.
- ຜົນການຊິງຄ໌ (`.../sync-results/`) ຖືກເກັບໃນ **ບັນທຶກການຊິງຄ໌** ແລະ ຜົນຂອງວິຊາຈະປ່ຽນສະຖານະໃນ **ການເຊື່ອມຕໍ່ວິຊາ**.

## ຄຳຖາມທີ່ພົບເລື້ອຍ

- **ນັກສຶກສາບໍ່ຢູ່ໃນ LMS.** ນັກສຶກສາຕ້ອງມີບັນຊີ (ຜູ້ໃຊ້) ຈຶ່ງຈະຊິງຄ໌ໄດ້. ຖ້າບໍ່ມີບັນຊີ ຫຼັງຈາກເຊີນ ([ບົດທີ 14](14-merge-and-invitations.md)) ຈະຖືກເພີ່ມໃນການທຽບຄັ້ງຕໍ່ໄປ.
- **ການຊິງຄ໌ຄ້າງເປັນລົ້ມເຫຼວ.** ເບິ່ງຂໍ້ຄວາມໃນບັນທຶກ. ຂໍ້ມູນຢືນຢັນຕົວຕົນໝົດອາຍຸເປັນສາເຫດທີ່ພົບເລື້ອຍ. ປ່ຽນຄ່າໃນການແກ້ໄຂແພລດຟອມ ແລ້ວ **ຊິງຄ໌ອີກຄັ້ງ**.
- **ປ່ຽນແພລດຟອມ.** ສ້າງແພລດຟອມໃໝ່ ແລະ ປິດການໃຊ້ງານຂອງແພລດຟອມເກົ່າ. ການເຊື່ອມຕໍ່ຖືກສ້າງແຍກຕາມແພລດຟອມ.

## ໜ້າຈໍຂອງການຕິດຕັ້ງນີ້

ໜ້າຈໍ ແລະ ຄຸນສົມບັດຄືກັບລະບົບເດີມ (Filament, Livewire), ວິທີການໃຊ້ງານບາງຢ່າງແຕກຕ່າງເລັກນ້ອຍ.

- ຂໍ້ມູນຢືນຢັນຕົວຕົນປ້ອນເປັນແຖວ `key=value` ໃນຊ່ອງຂໍ້ຄວາມຫຼາຍແຖວ ແທນຕາຕະລາງຄີ/ຄ່າຂອງລະບົບເດີມ. ແຖວທີ່ຮູບແບບບໍ່ຖືກຕ້ອງຈະຖືກປະຕິເສດພ້ອມເລກແຖວ.
- **ຕົວເລືອກ** ຂອງແພລດຟອມ (ID ບົດບາດຕາມແພລດຟອມ ແລະ ອື່ນໆ) ບໍ່ມີຊ່ອງປ້ອນໃນໜ້າຈໍ. ນັກພັດທະນາຕັ້ງຄ່າເມື່ອຕົວເຊື່ອມຕໍ່ຕ້ອງການ ([ຄູ່ມືການເຊື່ອມຕໍ່](../../../lms-integration-guide.md) ຂໍ້ 3).
- **ຊິງຄ໌ອີກຄັ້ງ** ຜ່ານໜ້າຢືນຢັນ. ຂໍ້ຜິດພາດຂອງຕົວເຊື່ອມຕໍ່ (ໄດຣເວີທີ່ບໍ່ມີຕົວເຊື່ອມຕໍ່, ແພລດຟອມຂັດຂ້ອງ) ສະແດງເປັນຂໍ້ຄວາມ "ການຊິງລົ້ມເຫຼວ: ..." ແລະ ການເຊື່ອມຕໍ່ວິຊາກາຍເປັນ "ລົ້ມເຫຼວ" (ລະບົບເດີມສະແດງໜ້າຂໍ້ຜິດພາດ).
- ບັນທຶກການຊິງຄ໌ເປັນແບບອ່ານຢ່າງດຽວ. ເປີດແຖວເພື່ອເບິ່ງເນື້ອໃນ (payload) ເປັນ JSON.
- **ໂຫຼດຄະແນນຈາກ LMS** ໃນການປ້ອນເກຣດຢູ່ໃນແຖວປຸ່ມທາງລຸ່ມຕາຕະລາງ. ເມື່ອກົດ ຈະສະແດງໜ້າຄືນໂດຍປ່ຽນສະເພາະຊ່ອງຄະແນນ ແລະ ຮັກສາຄ່າທີ່ປ້ອນໄວ້ແລ້ວ. ຈະບັນທຶກເມື່ອກົດ **ບັນທຶກຮ່າງ** ເທົ່ານັ້ນ.
- API ສຳລັບການເຊື່ອມຕໍ່ພາຍນອກ ແລະ ຄຳສັ່ງ token (`api_issue_token`, `api_revoke_tokens`) ເປັນສິ່ງໃໝ່ໃນການຕິດຕັ້ງນີ້ (ລະບົບເດີມບໍ່ມີ API).
