# 15. ການຕັ້ງຄ່າວິທີເຂົ້າສູ່ລະບົບ

ເມນູ: **ການຕັ້ງຄ່າ > ວິທີເຂົ້າສູ່ລະບົບ** (ສິດ `ຈັດການວິທີເຂົ້າສູ່ລະບົບ ແລະ SSO`)

## ຊື່ເຂົ້າສູ່ລະບົບ

ອີເມວຂອງບັນຊີແມ່ນຊື່ເຂົ້າສູ່ລະບົບເລີ່ມຕົ້ນ. ຖ້າເປີດການເຂົ້າສູ່ລະບົບດ້ວຍລະຫັດນັກສຶກສາ ຊ່ອງໃນໜ້າເຂົ້າສູ່ລະບົບຈະກາຍເປັນ "ອີເມວ ຫຼື ລະຫັດນັກສຶກສາ".

| ເຂົ້າສູ່ລະບົບດ້ວຍລະຫັດນັກສຶກສາ | ການເຮັດວຽກ |
|---|---|
| ບໍ່ອະນຸຍາດ | ອີເມວເທົ່ານັ້ນ |
| ສະເພາະນັກສຶກສາປັດຈຸບັນ | ເຂົ້າສູ່ລະບົບດ້ວຍລະຫັດນັກສຶກສາຂອງບັນທຶກນັກສຶກສາທີ່ກຳລັງສຶກສາ ຫຼື ພັກການຮຽນໄດ້ |
| ນັກສຶກສາປັດຈຸບັນ ແລະ ຜູ້ຈົບການສຶກສາ | ລະຫັດນັກສຶກສາຂອງບັນທຶກນັກສຶກສາທີ່ສິ້ນສຸດແລ້ວ ເຊັ່ນ ຈົບການສຶກສາ, ລາອອກ ກໍໃຊ້ໄດ້ |

ຜູ້ທີ່ມີຫຼາຍບັນທຶກນັກສຶກສາ ເຂົ້າສູ່ລະບົບດ້ວຍລະຫັດນັກສຶກສາໃດກໍເປັນບັນຊີດຽວກັນ.

## ການລັອກບັນຊີ

| ການຕັ້ງຄ່າ | ຄຳອະທິບາຍ |
|---|---|
| ລັອກຫຼັງຈາກລົ້ມເຫຼວ (ຄັ້ງ) | ຖ້າປ້ອນລະຫັດຜ່ານຜິດຕິດຕໍ່ກັນເຖິງຈຳນວນນີ້ ຈະລັອກ. ຖ້າເປັນ 0 ຈະບໍ່ລັອກ |
| ໄລຍະເວລາລັອກ (ນາທີ) | ເມື່ອເວລາຜ່ານໄປ ຈະປົດລັອກອັດຕະໂນມັດ |

ບໍ່ວ່າຈະພະຍາຍາມດ້ວຍອີເມວ ຫຼື ລະຫັດນັກສຶກສາ ກໍນັບເປັນຄວາມລົ້ມເຫຼວຂອງບັນຊີດຽວກັນ. ບັນຊີທີ່ຖືກລັອກຈະໄດ້ຮັບຂໍ້ຄວາມແບບດຽວກັບເມື່ອລະຫັດຜ່ານຜິດ ຈຶ່ງບໍ່ສາມາດຮູ້ໄດ້ວ່າມີບັນຊີຢູ່ຫຼືບໍ່. ການລັອກຖືກບັນທຶກໃນເຫດການຄວາມປອດໄພ (**ການເຂົ້າສູ່ລະບົບຖືກລັອກ**).

ຖ້າຕ້ອງການປົດລັອກກ່ອນເວລາ ໃຫ້ໃຊ້ **ປົດລັອກການເຂົ້າສູ່ລະບົບ** ໃນລາຍລະອຽດ **ຜູ້ໃຊ້** (ຕ້ອງມີເຫດຜົນ, ສິດ `ແກ້ໄຂຜູ້ໃຊ້`). ເມື່ອໃຊ້ໜ້າບໍລິຫານບໍ່ໄດ້ ຜູ້ດຳເນີນງານ IT ໃຊ້ `uv run manage.py security_unlock_user`.

## ການເຂົ້າສູ່ລະບົບຂອງສະຖາບັນ (SSO)

ຖ້າລົງທະບຽນການເຂົ້າສູ່ລະບົບ OpenID Connect ຂອງສະຖາບັນ (ຕົວຢ່າງ: Microsoft Entra ID, Google Workspace, Keycloak) ປຸ່ມ "ເຂົ້າສູ່ລະບົບດ້ວຍ OO" ຈະປາກົດໃນໜ້າເຂົ້າສູ່ລະບົບ.

| ລາຍການ | ຄຳອະທິບາຍ |
|---|---|
| ຄີ | ຕົວລະບຸດ້ວຍຕົວອັກສອນລາຕິນຕົວນ້ອຍ. ຕົວຢ່າງ: `school`. ຖ້າປ່ຽນ ການເຊື່ອມຕໍ່ເດີມຈະຂາດ |
| ປ້າຍປຸ່ມ | ຊື່ທີ່ຈະສະແດງໃນໜ້າເຂົ້າສູ່ລະບົບ |
| URL ຜູ້ອອກ (Issuer) | issuer ຂອງຜູ້ໃຫ້ບໍລິການ. `/.well-known/openid-configuration` ຕ້ອງຢູ່ພາຍໃຕ້ທີ່ຢູ່ນີ້ |
| Client ID, Client secret | ຄ່າທີ່ໄດ້ຮັບຫຼັງລົງທະບຽນແອັບກັບຜູ້ໃຫ້ບໍລິການ. ຄ່າລັບຖືກເຂົ້າລະຫັດເກັບໄວ້ |
| ຂອບເຂດ (scope) | ຄ່າເລີ່ມຕົ້ນ `openid email profile` |
| ນັບເປັນການຢືນຢັນສອງຂັ້ນຕອນ | ເປີດສະເພາະເມື່ອການເຂົ້າສູ່ລະບົບຂອງສະຖາບັນເອງຮຽກຮ້ອງການຢືນຢັນສອງຂັ້ນຕອນ. ຖ້າເປີດ ການເຂົ້າສູ່ລະບົບນີ້ຈະບໍ່ຖາມການຢືນຢັນສອງຂັ້ນຕອນຂອງລະບົບນີ້ອີກ |
| URI ປ່ຽນເສັ້ນທາງທີ່ຕ້ອງລົງທະບຽນກັບຜູ້ໃຫ້ບໍລິການ | ລົງທະບຽນທີ່ຢູ່ທີ່ສະແດງໃນໜ້າຈໍ (`https://<ເຊີບເວີ>/auth/sso/<ກະແຈ>/callback/`) ເຂົ້າໃນການຕັ້ງຄ່າແອັບຂອງຜູ້ໃຫ້ບໍລິການຕາມທີ່ເປັນ |

### ວິທີເຊື່ອມຕໍ່ບັນຊີ

| ວິທີ | ການເຮັດວຽກ |
|---|---|
| ຜູ້ໃຊ້ເຊື່ອມຕໍ່ບັນຊີດ້ວຍຕົນເອງ | ຜູ້ໃຊ້ເຂົ້າສູ່ລະບົບດ້ວຍລະຫັດຜ່ານ ແລ້ວ **ເຊື່ອມຕໍ່** ທີ່ **ຄວາມປອດໄພ > ການເຂົ້າສູ່ລະບົບຂອງສະຖາບັນ** ໃນພອດທໍ (ຕ້ອງຢືນຢັນລະຫັດຜ່ານອີກຄັ້ງ) |
| ເຊື່ອມຕໍ່ອັດຕະໂນມັດດ້ວຍອີເມວສະຖາບັນທີ່ຢືນຢັນແລ້ວ | ຖ້າອີເມວທີ່ຜູ້ໃຫ້ບໍລິການຢືນຢັນແລ້ວກົງກັບອີເມວສະຖາບັນໃນບັນທຶກນັກສຶກສາ ຈະເຊື່ອມຕໍ່ອັດຕະໂນມັດເມື່ອເຂົ້າສູ່ລະບົບຄັ້ງທຳອິດ |

- ຖ້າເຂົ້າສູ່ລະບົບດ້ວຍບັນຊີສະຖາບັນທີ່ຍັງບໍ່ໄດ້ເຊື່ອມຕໍ່ ຈະມີຂໍ້ຄວາມແນະນຳໃຫ້ເຂົ້າສູ່ລະບົບດ້ວຍລະຫັດຜ່ານແລ້ວເຊື່ອມຕໍ່. ບັນຊີໃໝ່ຈະບໍ່ຖືກສ້າງຈາກບັນຊີສະຖາບັນພຽງຢ່າງດຽວ.
- ການເຊື່ອມຕໍ່ ແລະ ການຍົກເລີກການເຊື່ອມຕໍ່ຖືກບັນທຶກໃນບັນທຶກຄວາມປອດໄພ.

### ການອະນຸຍາດເຂົ້າສູ່ລະບົບດ້ວຍລະຫັດຜ່ານ

ຖ້າປິດ **ອະນຸຍາດລະຫັດຜ່ານສຳລັບຜູ້ໃຊ້ທີ່ມີການເຂົ້າສູ່ລະບົບຂອງສະຖາບັນ** ຜູ້ໃຊ້ທີ່ເຊື່ອມຕໍ່ແລ້ວຈະໃຊ້ໄດ້ແຕ່ການເຂົ້າສູ່ລະບົບຂອງສະຖາບັນເທົ່ານັ້ນ. ເມື່ອຄຳນຶງເຖິງກໍລະນີທີ່ບັນຊີສະຖາບັນຫາຍໄປຫຼັງຈົບການສຶກສາ ແນະນຳໃຫ້ເປີດໄວ້ ແລະ ໃຫ້ຜູ້ທີ່ຈະຈົບການສຶກສາກະກຽມອີເມວສ່ວນຕົວ ແລະ ລະຫັດຜ່ານໄວ້. ຜູ້ຈົບການສຶກສາຈະສືບຕໍ່ເຂົ້າສູ່ລະບົບດ້ວຍອີເມວເຂົ້າສູ່ລະບົບຂອງບັນຊີ (ອີເມວສ່ວນຕົວ) ແລະ ລະຫັດຜ່ານ.
