# 4. ການເບິ່ງບັນທຶກການກວດສອບ

ສາມໜ້າຈໍໃນເມນູ **ການກວດສອບ** ສາມາດເບິ່ງໄດ້ເທົ່ານັ້ນ ແລະ ບໍ່ມີໃຜສາມາດແກ້ໄຂ ຫຼື ລຶບໄດ້ (ຕ້ອງມີສິດ `ເບິ່ງບັນທຶກການກວດສອບ`, `ເບິ່ງເຫດການຄວາມປອດໄພ`).

| ໜ້າຈໍ | ສະແດງຫຍັງ | ຕົວຢ່າງ |
|---|---|---|
| ບັນທຶກກິດຈະກຳ | ໃຜ, ເຮັດຫຍັງ, **ຍ້ອນຫຍັງ**. ເຫດຜົນ ແລະ ລາຍລະອຽດ | ການມອບບົດບາດ (ເຫດຜົນ: ປະຕິບັດໜ້າທີ່ແທນໃນລະຫວ່າງພາກຮຽນ), ການປ່ຽນສິດ (ລາຍການເພີ່ມ/ລຶບ), ການປ່ຽນການຕັ້ງຄ່າ (ກ່ອນ/ຫຼັງ), ການແລ່ນຄຳສັ່ງ |
| ການປ່ຽນແປງຂໍ້ມູນ | ຄ່າກ່ອນ/ຫຼັງຂອງແຖວໃນຕາຕະລາງ. ການປ່ຽນໂດຍກົງທີ່ບໍ່ຜ່ານໂປຣແກຣມກໍຖືກບັນທຶກໄວ້ | `users` UPDATE, ຖັນທີ່ປ່ຽນ `locale` |
| ເຫດການຄວາມປອດໄພ | ການເຂົ້າສູ່ລະບົບ, ການເຂົ້າສູ່ລະບົບລົ້ມເຫຼວ, ການຢືນຢັນສອງຂັ້ນຕອນ, ເຫດການກ່ຽວກັບສິດ, ການປ່ຽນລະຫັດຜ່ານ·ອີເມວ, ການລ້າງບັນທຶກການກວດສອບ (`audit_prune`) | ການເຂົ້າສູ່ລະບົບລົ້ມເຫຼວ (ຊື່ເຂົ້າສູ່ລະບົບ, IP) |

## ວິທີອ່ານ

- ຖັນ **ຜູ້ໃຊ້**: ການດຳເນີນງານຈາກໜ້າຈໍສະແດງເປັນຊື່ຜູ້ໃຊ້ ຫຼື `user:ເລກ`, ການດຳເນີນງານອັດຕະໂນມັດເປັນ `system:task:...`, ຄຳສັ່ງເປັນ `system:command:...`.
- ລະຫັດຜ່ານ, ຄ່າລັບຂອງການຢືນຢັນສອງຂັ້ນຕອນ ແລະ ອື່ນໆ ຈະຖືກປິດບັງເປັນ `[redacted]`.
- ບັນທຶກທີ່ມີ **ID ຄຳຮ້ອງຂໍ** ດຽວກັນແມ່ນເກີດຂຶ້ນພ້ອມກັນໃນຄຳຮ້ອງຂໍຈາກໜ້າຈໍຄັ້ງດຽວ. ຖ້າຄົ້ນຫາດ້ວຍ ID ຄຳຮ້ອງຂໍດຽວກັນໃນຫຼາຍໜ້າຈໍ ຈະເຫັນບັນທຶກທັງໝົດຂອງການດຳເນີນງານໜຶ່ງ.

## ການຄົ້ນຫາທີ່ໃຊ້ເລື້ອຍໆ

| ສິ່ງທີ່ຢາກຮູ້ | ວິທີ |
|---|---|
| ສິດຂອງຜູ້ໃຊ້ໃດໜຶ່ງຖືກປ່ຽນເມື່ອໃດ | ໃນບັນທຶກກິດຈະກຳ ບັນທຶກ `security`, ເຫດການ `role.assigned`, `role.assignment_revoked` |
| ບັນຊີທີ່ມີການເຂົ້າສູ່ລະບົບລົ້ມເຫຼວຫຼາຍ | ໃນເຫດການຄວາມປອດໄພ ຕົວກອງເຫດການ `ການເຂົ້າສູ່ລະບົບລົ້ມເຫຼວ`, ຖັນຊື່ເຂົ້າສູ່ລະບົບ |
| ໃຜປ່ຽນນະໂຍບາຍຄວາມປອດໄພ | ເຫດການ `settings.updated` ໃນບັນທຶກກິດຈະກຳ |
| ແຖວໃດໜຶ່ງຖືກປ່ຽນແນວໃດ | ໃນການປ່ຽນແປງຂໍ້ມູນ ໃຊ້ຕົວກອງຕາຕະລາງ ແລະ ຄົ້ນຫາ ID ບັນທຶກ |
