# 3. ການຢືນຢັນສອງຂັ້ນຕອນ

## ວິທີທີ່ຜູ້ໃຊ້ລົງທະບຽນ

ດຳເນີນການທີ່ໜ້າ **ຄວາມປອດໄພ** ຂອງພອດທໍ (ເມນູຜູ້ໃຊ້ໃນໜ້າບໍລິຫານ **ການຢືນຢັນສອງຂັ້ນຕອນ**). ກ່ອນລົງທະບຽນ ຫຼື ຍົກເລີກ ຈະຕ້ອງຢືນຢັນລະຫັດຜ່ານອີກຄັ້ງ.

### ແອັບຢືນຢັນຕົວຕົນ (ແນະນຳ)

1. ກົດ **ເປີດໃຊ້ການຢືນຢັນສອງຂັ້ນຕອນ**.
2. ສະແກນລະຫັດ QR ດ້ວຍແອັບຢືນຢັນຕົວຕົນ ເຊັ່ນ Google Authenticator, Microsoft Authenticator.
3. ປ້ອນລະຫັດ 6 ຕົວເລກທີ່ສະແດງໃນແອັບ ແລ້ວກົດ **ຢືນຢັນ**.
4. ເກັບ **ລະຫັດກູ້ຄືນ** ທີ່ສະແດງໃນໜ້າຈໍໄວ້ໃນບ່ອນທີ່ປອດໄພ. ໃຊ້ໄດ້ລະຫັດລະໜຶ່ງຄັ້ງເມື່ອໂທລະສັບເສຍ.

### ລະຫັດທາງອີເມວ

ສະແດງສະເພາະເມື່ອຜູ້ບໍລິຫານລະບົບອະນຸຍາດ. ເປັນວິທີສຳລັບຜູ້ໃຊ້ທີ່ບໍ່ສາມາດໃຊ້ແອັບຢືນຢັນຕົວຕົນໄດ້ ແລະ ມີຄວາມປອດໄພຕ່ຳກວ່າແອັບຢືນຢັນຕົວຕົນ.

1. ທີ່ສ່ວນ **ລະຫັດທາງອີເມວ** ກົດ **ສົ່ງລະຫັດເພື່ອຕັ້ງຄ່າ**.
2. ປ້ອນລະຫັດ 6 ຕົວເລກທີ່ສົ່ງໄປຫາອີເມວຂອງບັນຊີ ແລ້ວກົດ **ຢືນຢັນ**.
3. ຫຼັງຈາກນັ້ນ ທຸກຄັ້ງທີ່ເຂົ້າສູ່ລະບົບຈະມີລະຫັດສົ່ງໄປທາງອີເມວ. ລະຫັດໃຊ້ໄດ້ຄັ້ງດຽວພາຍໃນ 10 ນາທີ ແລະ ຖ້າປ້ອນຜິດ 5 ຄັ້ງ ຕ້ອງຂໍລະຫັດໃໝ່. ສາມາດສົ່ງລະຫັດໄດ້ 1 ຄັ້ງຕໍ່ນາທີ ແລະ ສູງສຸດ 5 ຄັ້ງຕໍ່ຊົ່ວໂມງ.

ສາມາດລົງທະບຽນທັງສອງວິທີໄດ້. ຖ້ານະໂຍບາຍເປັນ "ບັງຄັບ" ຈະບໍ່ສາມາດຍົກເລີກວິທີສຸດທ້າຍທີ່ເຫຼືອຢູ່ໄດ້.

## ການຕັ້ງຄ່ານະໂຍບາຍ (ຜູ້ບໍລິຫານລະບົບ)

ກຳນົດທີ່ **ການຕັ້ງຄ່າ > ຄວາມປອດໄພ**. ເມື່ອບັນທຶກແລ້ວ ຈະມີຜົນກັບຜູ້ໃຊ້ທຸກຄົນທັນທີຕັ້ງແຕ່ການເປີດໜ້າຈໍຄັ້ງຕໍ່ໄປ.

| ລາຍການ | ຄຳອະທິບາຍ |
|---|---|
| ນະໂຍບາຍ | **ບໍ່ໃຊ້** / **ແນະນຳ (ທາງເລືອກ)**: ພຽງແຕ່ແຈ້ງເຕືອນຜູ້ໃຊ້ທີ່ຍັງບໍ່ລົງທະບຽນ / **ບັງຄັບສຳລັບບົດບາດທີ່ເລືອກ**: ຜູ້ໃຊ້ທີ່ມີບົດບາດທີ່ເລືອກຕ້ອງໃຊ້ / **ບັງຄັບສຳລັບທຸກຄົນ** |
| ບົດບາດທີ່ຕ້ອງໃຊ້ການຢືນຢັນສອງຂັ້ນຕອນ | ເລືອກເມື່ອເປັນ "ບັງຄັບສຳລັບບົດບາດທີ່ເລືອກ" |
| ໄລຍະຜ່ອນຜັນ (ວັນ) | ໄລຍະເວລາທີ່ຜູ້ໃຊ້ທີ່ນະໂຍບາຍບັງຄັບມີຜົນເປັນຄັ້ງທຳອິດ ຍັງສາມາດໃຊ້ງານໄດ້ໂດຍບໍ່ຕ້ອງລົງທະບຽນ. ໃນໄລຍະນີ້ ຈະມີການແຈ້ງກຳນົດວັນຢູ່ດ້ານເທິງໜ້າຈໍ. ເມື່ອໝົດກຳນົດ ຈະໃຊ້ໄດ້ພຽງໜ້າຄວາມປອດໄພເທົ່ານັ້ນ. ຖ້າເປັນ 0 ຈະມີຜົນທັນທີ |
| ຈື່ອຸປະກອນເປັນເວລາ (ວັນ) | ໄລຍະເວລາທີ່ບໍ່ຕ້ອງປ້ອນລະຫັດໃນອຸປະກອນທີ່ເລືອກ **ຈື່ອຸປະກອນນີ້**. ຖ້າເປັນ 0 ຈະບໍ່ໃຊ້ |
| ອະນຸຍາດລະຫັດທາງອີເມວ | ຖ້າປິດ ລະຫັດທາງອີເມວຈະບໍ່ຖືກນັບເປັນການຢືນຢັນສອງຂັ້ນຕອນ. ຜູ້ໃຊ້ທີ່ລົງທະບຽນສະເພາະລະຫັດທາງອີເມວຈະຖືກຮຽກຮ້ອງໃຫ້ລົງທະບຽນແອັບຢືນຢັນຕົວຕົນຕາມນະໂຍບາຍ |

ການນຳໃຊ້ທີ່ແນະນຳ: ບົດບາດພະນັກງານ (ຜູ້ຮັບຜິດຊອບທະບຽນນັກສຶກສາ, ຜູ້ຮັບຜິດຊອບວຽກງານການສອນ, ຜູ້ບໍລິຫານລະບົບ ແລະ ອື່ນໆ) ຕັ້ງເປັນ **ບັງຄັບສຳລັບບົດບາດທີ່ເລືອກ**, ນັກສຶກສາຕັ້ງເປັນແນະນຳ.

## ການຣີເຊັດ (ກໍລະນີໂທລະສັບເສຍ ແລະ ອື່ນໆ)

1. ທີ່ **ຜູ້ໃຊ້ ແລະ ສິດເຂົ້າໃຊ້ > ຜູ້ໃຊ້** ເປີດຜູ້ໃຊ້.
2. ກົດ **ຣີເຊັດການຢືນຢັນສອງຂັ້ນຕອນ** ແລ້ວປ້ອນເຫດຜົນ (ຕ້ອງມີສິດ `ຣີເຊັດການຢືນຢັນສອງຂັ້ນຕອນ`).
3. ແອັບຢືນຢັນຕົວຕົນ, ລະຫັດກູ້ຄືນ, ລະຫັດທາງອີເມວ ແລະ ອຸປະກອນທີ່ຈື່ໄວ້ຂອງຜູ້ໃຊ້ຈະຖືກຍົກເລີກທັງໝົດ. ໄລຍະຜ່ອນຜັນຈະເລີ່ມນັບໃໝ່.

ບໍ່ສາມາດຣີເຊັດບັນຊີຂອງຕົນເອງໄດ້. ການຣີເຊັດຈະຖືກບັນທຶກພ້ອມເຫດຜົນໄວ້ໃນເຫດການຄວາມປອດໄພ ແລະ ບັນທຶກກິດຈະກຳ.

ຖ້າຜູ້ບໍລິຫານພຽງຄົນດຽວເຮັດໂທລະສັບເສຍ ແລະ ເຂົ້າໜ້າບໍລິຫານບໍ່ໄດ້ ຜູ້ດຳເນີນງານ IT ສາມາດຣີເຊັດດ້ວຍ `uv run manage.py security_reset_mfa` (Docker: `docker compose exec app uv run manage.py security_reset_mfa`, [ເອກະສານອ້າງອີງຄຳສັ່ງ](../operations/commands.md)).
