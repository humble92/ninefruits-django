# 23. ໃບຢັ້ງຢືນ

ເມນູ: **ໃບຢັ້ງຢືນ > ໃບຢັ້ງຢືນທີ່ອອກແລ້ວ**, **ໃບຢັ້ງຢືນ > ປະເພດໃບຢັ້ງຢືນ**, **ການຕັ້ງຄ່າ > ການຕັ້ງຄ່າໃບຢັ້ງຢືນ**. ການອອກໃບຢັ້ງຢືນເຮັດດ້ວຍປຸ່ມ **ອອກໃບຢັ້ງຢືນ** ໃນໜ້າບັນທຶກນັກສຶກສາ (**ນັກສຶກສາ ແລະ ພະນັກງານ > ບັນທຶກນັກສຶກສາ**, ເປີດບັນທຶກໜຶ່ງ). ນັກສຶກສາດາວໂຫຼດ PDF ໃບຢັ້ງຢືນຂອງຕົນໃນພອດທໍ **ໃບຢັ້ງຢືນ**. ໃຜກໍສາມາດກວດສອບຄວາມຖືກຕ້ອງໄດ້ທີ່ໜ້າ `/verify/{ລະຫັດ}/`.

| ສິດ | ສິ່ງທີ່ເຮັດໄດ້ |
|---|---|
| `ອອກ, ສ້າງໃໝ່ ແລະ ຖອນໃບຢັ້ງຢືນ` | ອອກ, ສ້າງໃໝ່, ຖອນ, ເບິ່ງທະບຽນການອອກ (ພາຍໃນຂອບເຂດເບິ່ງບັນທຶກນັກສຶກສາ) |
| `ຈັດການປະເພດ, ແມ່ແບບ ແລະ ການຕັ້ງຄ່າໃບຢັ້ງຢືນ` | ປະເພດ ແລະ ແມ່ແບບຕາມພາສາ, ຮູບແບບເລກທີ, ຜູ້ລົງນາມ |

ຄ່າເລີ່ມຕົ້ນຂອງບົດບາດ: ພະນັກງານອອກໃບຢັ້ງຢືນມີສິດອອກ, ພະນັກງານທະບຽນມີທັງສອງ, ພະນັກງານວິຊາການມີສິດຈັດການປະເພດ·ແມ່ແບບ. ໃຫ້ສິດອອກໃບຢັ້ງຢືນໃນ **ຂອບເຂດທັງໝົດ** (ນະໂຍບາຍຂອງ DB ຮັບພຽງການມອບສິດຂອບເຂດທັງໝົດ); ນັກສຶກສາຄົນໃດທີ່ອອກໃຫ້ໄດ້ ແມ່ນຕາມຂອບເຂດເບິ່ງບັນທຶກນັກສຶກສາ. ຕົວຢ່າງ: ໃຫ້ພະນັກງານອອກໃບຢັ້ງຢືນຂອງຄະນະໜຶ່ງມີ `ອອກ, ສ້າງໃໝ່ ແລະ ຖອນໃບຢັ້ງຢືນ` ໃນຂອບເຂດທັງໝົດ ແລະ `ເບິ່ງບັນທຶກນັກສຶກສາ` ໃນຂອບເຂດຂອງຄະນະນັ້ນ.

## ສິ່ງທີ່ຕ່າງຈາກລະບົບເກົ່າ

- **ທະບຽນການອອກ.** ລະບົບເກົ່າ (YUSTIC) ພິມໂດຍກົງຈາກໜ້າຈໍ (`aca3/cti_*`) ແລະ ທະບຽນ (`SRCERT`) ມີໄວ້ເພື່ອສ້າງເລກທີເທົ່ານັ້ນ ຈຶ່ງບໍ່ຮູ້ວ່າໃຜອອກ ຫຼື ຖືກຖອນຫຼືບໍ່. ລະບົບໃໝ່ບັນທຶກເລກທີ, ລະຫັດກວດສອບ, ພະນັກງານ, ຈຸດປະສົງ, ຈຳນວນສະບັບ, ໄຟລ໌ PDF ແລະ ເຊັກຊຳ ທຸກຄັ້ງທີ່ອອກ ແລະ ເຖິງຖອນກໍບໍ່ລຶບແຖວ.
- **ການກວດສອບຄວາມຖືກຕ້ອງ.** ລະບົບເກົ່າບໍ່ມີ. ທຸກໃບຢັ້ງຢືນພິມລະຫັດກວດສອບ ແລະ QR ແລະ ໜ້າສາທາລະນະສະແດງຂໍ້ເທັດຈິງຂອງການອອກ, ປະເພດ, ວັນທີອອກ ແລະ ຊື່ເຈົ້າຂອງທີ່ປິດບາງສ່ວນ (ຕົວອັກສອນທຳອິດ·ສຸດທ້າຍຂອງຊື່, 4 ຕົວທຳອິດຂອງລະຫັດນັກສຶກສາ).
- **ແມ່ແບບ.** ລະບົບເກົ່າມີສະຄຣິບສ້າງ PDF ແຍກຕາມປະເພດ ແລະ ພາສາ. ລະບົບໃໝ່ແກ້ໄຂແມ່ແບບຕາມພາສາ (ຫົວຂໍ້, ເນື້ອໃນ, ສ່ວນທ້າຍ, ຜູ້ລົງນາມ) ຂອງແຕ່ລະປະເພດໃນໜ້າຈໍ.
- **ການຂັດຂວາງການອອກ.** ລະບົບເກົ່າອອກໂດຍບໍ່ກ່ຽວກັບລາຍຊື່ປະຕິເສດການລົງທະບຽນ. ລະບົບໃໝ່ບໍ່ອອກໃຫ້ນັກສຶກສາທີ່ຖືກຂັດຂວາງໃບຢັ້ງຢືນ ([ບົດທີ 20](20-registration.md)).
- ບໍ່ບັນທຶກຄ່າທຳນຽມການອອກ (ລະບົບເກົ່າກໍບັນທຶກພຽງຈຳນວນເງິນ).
- ບໍ່ມີການຂໍອອນລາຍຂອງນັກສຶກສາ (ແຜນ 17.5). ພະນັກງານເປັນຜູ້ອອກ.

## ປະເພດ ແລະ ແມ່ແບບ

**ປະເພດໃບຢັ້ງຢືນ**: ລະຫັດ (ໃຊ້ໃນເລກທີ), ຊື່ (ຕາມພາສາ), ສຳລັບ (ບັນທຶກນັກສຶກສາທຸກປະເພດ / ນັກສຶກສາ (ຍັງບໍ່ຈົບ) / ຜູ້ຈົບການສຶກສາ), ລວມເກຣດ, ລວມຮູບຖ່າຍ, ເປີດໃຊ້, ລຳດັບ. ໂປຣໄຟລ໌ມະຫາວິທະຍາໄລເກົາຫຼີ (`setup_install --profile=korean-university`) ໃສ່ສາມປະເພດ ແລະ ແມ່ແບບ 4 ພາສາ (ເກົາຫຼີ, ອັງກິດ, ຈີນຕົວຫຍໍ້, ລາວ). ເມື່ອມີປະເພດໃດໜຶ່ງແລ້ວ ຈະບໍ່ໃສ່ອີກ ດັ່ງນັ້ນສິ່ງທີ່ແກ້ໄຂຈະຄົງຢູ່.

| ລະຫັດ | ປະເພດ | ສຳລັບ | ໝາຍເຫດ |
|---|---|---|---|
| `ENR` | ໃບຢັ້ງຢືນການເປັນນັກສຶກສາ | ນັກສຶກສາ (ຍັງບໍ່ຈົບ) | |
| `GRD` | ໃບຢັ້ງຢືນການຈົບການສຶກສາ | ຜູ້ຈົບການສຶກສາ | ວັນທີຈົບ, ເລກທີປະລິນຍາ |
| `TRN` | ໃບຢັ້ງຢືນຜົນການຮຽນ | ບັນທຶກນັກສຶກສາທຸກປະເພດ | ຕາຕະລາງເກຣດທີ່ຢືນຢັນແລ້ວຕາມພາກຮຽນ, GPA ສະສົມ ແລະ ໜ່ວຍກິດທີ່ໄດ້ຮັບ |

**ແມ່ແບບ** (ສ່ວນ **ແມ່ແບບ** ຢູ່ລຸ່ມໜ້າແກ້ໄຂປະເພດ): ໜຶ່ງອັນຕໍ່ພາສາ. ພາສາ, ຫົວຂໍ້, ເນື້ອໃນ (ແຍກຫຍໍ້ໜ້າດ້ວຍແຖວວ່າງ), ສ່ວນທ້າຍ, ຜູ້ລົງນາມ. ໃນເນື້ອໃນໃຊ້ຕົວແທນຄ່າໃນວົງປີກກາ.

| ລາຍການ | ຄ່າ |
|---|---|
| `{institution}` | ຊື່ສະຖາບັນ (ພາສານັ້ນ) |
| `{student_name}`, `{student_number}` | ຊື່ (ການຂຽນໃນພາສານັ້ນ ຖ້າບໍ່ມີ ໃຊ້ຕົວອັກສອນລາຕິນ), ລະຫັດນັກສຶກສາ |
| `{program}`, `{org_unit}` | ຫຼັກສູດ, ໜ່ວຍງານສັງກັດ |
| `{admission_date}`, `{graduation_date}`, `{degree_number}` | ວັນທີເຂົ້າຮຽນ, ວັນທີຈົບ, ເລກທີປະລິນຍາ |
| `{status}`, `{year_level}` | ສະຖານະບັນທຶກນັກສຶກສາ, ປີຮຽນ |
| `{birth_date}`, `{gender}`, `{nationality}` | ວັນເດືອນປີເກີດ, ເພດ, ສັນຊາດ |
| `{issue_date}`, `{serial_number}`, `{purpose}`, `{copies}` | ວັນທີອອກ, ເລກທີ, ຈຸດປະສົງ, ຈຳນວນສະບັບ |

ວັນທີພິມຕາມຮູບແບບຂອງພາສານັ້ນ. ຖ້າບໍ່ມີຄ່າ (ຕົວຢ່າງ: ວັນທີຈົບ) ຈະເປັນຊ່ອງວ່າງ; ລາຍການທີ່ບໍ່ຢູ່ໃນຕາຕະລາງນີ້ຈະຄົງຢູ່ຕາມທີ່ຂຽນ. ເທິງເນື້ອໃນຈະມີຕາຕະລາງຂໍ້ມູນສ່ວນຕົວ (ຊື່, ລະຫັດນັກສຶກສາ, ວັນເດືອນປີເກີດ, ເພດ, ສັນຊາດ, ຫຼັກສູດ, ວັນທີເຂົ້າຮຽນ ແລະ ຖ້າເປັນຜູ້ຈົບການສຶກສາ ວັນທີຈົບ ຖ້າບໍ່ແມ່ນ ສະຖານະບັນທຶກນັກສຶກສາ ແລະ ປີຮຽນ) ໃສ່ໃຫ້ອັດຕະໂນມັດ. ໃບຢັ້ງຢືນທັງໝົດ (ຫົວຕາຕະລາງ, ວັນທີ, ສະຖານະ) ພິມເປັນພາສາຂອງແມ່ແບບ.

## ການຕັ້ງຄ່າ

**ການຕັ້ງຄ່າ > ການຕັ້ງຄ່າໃບຢັ້ງຢືນ** (ສິດ `ຈັດການປະເພດ, ແມ່ແບບ ແລະ ການຕັ້ງຄ່າໃບຢັ້ງຢືນ`)

- **ຮູບແບບເລກທີ**: ຄ່າເລີ່ມຕົ້ນ `{TYPE}-{YYYY}-{SEQ:6}` → `ENR-2026-000001`. ລາຍການແມ່ນ `{TYPE}` (ລະຫັດປະເພດ), `{YYYY}` ແລະ `{YY}` (ປີທີ່ອອກ ຕາມເຂດເວລາຂອງສະຖາບັນ) ແລະ `{SEQ:n}` (ເລກລຳດັບ n ຫຼັກ). ຕ້ອງມີ `{SEQ:n}` ໜຶ່ງອັນພໍດີ ແລະ ຫຼັງຈາກມັນມີໄດ້ພຽງຂໍ້ຄວາມທຳມະດາ. ເລກລຳດັບນັບແຍກກັນທຸກຄັ້ງທີ່ສ່ວນໜ້າ (ຄຳນຳໜ້າ) ຕ່າງກັນ: `{TYPE}-{SEQ:6}` ນັບຕໍ່ເນື່ອງຕາມປະເພດ, `{YYYY}{SEQ:5}` ນັບຕໍ່ເນື່ອງຕາມປີ. ເຖິງອອກພ້ອມກັນ ເລກທີກໍບໍ່ຊ້ຳກັນ (ເພີ່ມແບບອະຕອມໃນ DB).
- **ການຢືນຢັນໃຊ້ໄດ້ເປັນເວລາ (ວັນ)**: 0 ແມ່ນຕະຫຼອດໄປ. ເມື່ອໝົດອາຍຸ ໜ້າກວດສອບຈະຕອບວ່າ "ໝົດອາຍຸ". ຂໍ້ເທັດຈິງຂອງການອອກຍັງຄົງຢູ່ໃນທະບຽນ.
- **ຜູ້ລົງນາມຕາມພາສາ**: ຊື່ທີ່ພິມເໜືອກາປະທັບ ("ອະທິການບໍດີ ມະຫາວິທະຍາໄລ Ninefruits"), ມີຊ່ອງໜຶ່ງຕໍ່ພາສາທີ່ສະຖາບັນຮອງຮັບ. ຖ້າແມ່ແບບມີຜູ້ລົງນາມ ຈະໃຊ້ຂອງແມ່ແບບກ່ອນ.

## ການອອກ

**ອອກໃບຢັ້ງຢືນ** ໃນໜ້າບັນທຶກນັກສຶກສາ: ປະເພດ (ທີ່ເປີດໃຊ້), ພາສາ (ພາສາຂອງສະຖາບັນ), ຈຸດປະສົງ, ຈຳນວນສະບັບ (1~20). ກົດ **ອອກໃບຢັ້ງຢືນ** ແລ້ວ PDF ຈະຖືກສ້າງ ແລະ ເກັບໄວ້ ແລະ ກັບໄປໜ້າບັນທຶກນັກສຶກສາ; ການແຈ້ງເຕືອນສະແດງເລກທີ ແລະ ລິ້ງ **PDF**.

ກໍລະນີທີ່ປະຕິເສດການອອກ (ໜ້າຈໍບອກເຫດຜົນ):

- ເປົ້າໝາຍຂອງປະເພດບໍ່ກົງ (ໃບຢັ້ງຢືນການເປັນນັກສຶກສາໃຫ້ຜູ້ຈົບການສຶກສາ, ໃບຢັ້ງຢືນການຈົບການສຶກສາໃຫ້ນັກສຶກສາປັດຈຸບັນ)
- ປະເພດທີ່ຢຸດໃຊ້ງານແລ້ວ
- ບໍ່ມີແມ່ແບບຂອງພາສານັ້ນ
- ນັກສຶກສາຖືກ **ຂັດຂວາງໃບຢັ້ງຢືນ** ຢູ່ (ການລະງັບການລົງທະບຽນ, [ບົດທີ 20](20-registration.md)). ປົດກ່ອນແລ້ວຈຶ່ງອອກ. ເຖິງພະນັກງານຈະບໍ່ເຫັນການລະງັບນັ້ນ ກໍຍັງປະຕິເສດ.
- ບັນທຶກນັກສຶກສາຢູ່ນອກຂອບເຂດເບິ່ງ ຫຼື ບໍ່ມີສິດອອກ
- ບໍລິການ PDF (Gotenberg) ບໍ່ຕອບ: ບໍ່ມີຫຍັງຖືກອອກ ແລະ ສະແດງ "ບໍ່ສາມາດສ້າງ PDF ໄດ້". ໃຫ້ອອກໃໝ່ພາຍຫຼັງ.

ການອອກຖືກບັນທຶກໃນບັນທຶກການກວດສອບກິດຈະກຳ (`certificate.issued`: ລະຫັດນັກສຶກສາ, ປະເພດ, ພາສາ, ເລກທີ, ຈຳນວນສະບັບ; ຈຸດປະສົງເປັນເຫດຜົນ).

## ທະບຽນການອອກ

**ໃບຢັ້ງຢືນ > ໃບຢັ້ງຢືນທີ່ອອກແລ້ວ**: ວັນທີອອກ, ເລກທີ, ປະເພດ ແລະ ພາສາ, ລະຫັດນັກສຶກສາ, ຊື່, ຈຸດປະສົງ, ຈຳນວນສະບັບ, ສະຖານະ, ພະນັກງານ ແລະ ລິ້ງ **PDF**·**ໜ້າຢືນຢັນ** (ແຖບໃໝ່). ກັ່ນຕອງຕາມປະເພດ ແລະ ສະຖານະ, ຄົ້ນຫາດ້ວຍເລກທີ, ລະຫັດນັກສຶກສາ ຫຼື ຊື່. ຂອບເຂດເບິ່ງຄືກັບຂອບເຂດເບິ່ງບັນທຶກນັກສຶກສາ.

- **PDF**: ເປີດໄຟລ໌ທີ່ເກັບໄວ້. ບໍ່ສ້າງຄືນ ຈຶ່ງຄືກັບຕອນອອກທຸກປະການ.
- **ໜ້າຢືນຢັນ**: ເປີດໜ້າສາທາລະນະ.
- **ສ້າງໃໝ່** (ເມນູແຖວ): ສ້າງ PDF ໃໝ່ດ້ວຍຂໍ້ມູນປັດຈຸບັນແລ້ວແທນທີ່ ເຊັ່ນ ຫຼັງຈາກແກ້ໄຂແມ່ແບບ. ເລກທີ ແລະ ລະຫັດກວດສອບຄົງເດີມ ແຕ່ເຊັກຊຳປ່ຽນ. ບັນທຶກການກວດສອບ `certificate.rerendered`. ຄືກັບຄຳສັ່ງ `certificate_render`. ໃບຢັ້ງຢືນທີ່ຖອນແລ້ວບໍ່ສ້າງໃໝ່.
- **ຖອນ** (ເມນູແຖວ): ຕ້ອງໃສ່ເຫດຜົນ. ແຖວ ແລະ ໄຟລ໌ຍັງຄົງຢູ່ ສະຖານະປ່ຽນເປັນຖອນແລ້ວ ແລະ ໜ້າກວດສອບຈະຕອບວ່າ "ໃບຢັ້ງຢືນນີ້ຖືກຖອນແລ້ວ". ບັນທຶກການກວດສອບ `certificate.revoked`. ໃບຢັ້ງຢືນທີ່ຖອນແລ້ວບໍ່ຟື້ນຄືນ ແຕ່ອອກໃໝ່.

ແຖວໃນທະບຽນແກ້ໄຂ ຫຼື ລຶບຈາກໜ້າຈໍບໍ່ໄດ້ (ກົດແຖວເພື່ອເບິ່ງລາຍລະອຽດແບບອ່ານຢ່າງດຽວ ແລະ ເຊັກຊຳ).

## ການກວດສອບຄວາມຖືກຕ້ອງ

- ທ້າຍໃບຢັ້ງຢືນພິມ URL ກວດສອບ (`{ທີ່ຢູ່ສະຖາບັນ}/verify/{ລະຫັດ}/`) ແລະ QR. ລະຫັດເປັນສະຕຣິງສຸ່ມ 20 ຕົວອັກສອນ (ຕົວພິມໃຫຍ່ ແລະ ຕົວເລກ) ບໍ່ແຍກຕົວພິມ. ທີ່ຢູ່ສ້າງຈາກຕົວແປສະພາບແວດລ້ອມ `APP_URL`.
- ໜ້ານີ້ເປີດໄດ້ໂດຍບໍ່ຕ້ອງເຂົ້າສູ່ລະບົບ ແລະ ຈຳກັດ 30 ຄັ້ງຕໍ່ນາທີຕໍ່ທີ່ຢູ່ (IP; ເກີນແມ່ນ HTTP 429), ບໍ່ໃຫ້ເຄື່ອງມືຄົ້ນຫາເກັບ (`noindex`). ສະແດງວ່າອອກແລ້ວຫຼືບໍ່, ປະເພດ, ເລກທີ, ວັນທີອອກ, ຊື່ ແລະ ລະຫັດນັກສຶກສາທີ່ປິດບາງສ່ວນ. ລະຫັດທີ່ຖອນແລ້ວ·ໝົດອາຍຸ·ບໍ່ມີ ຈະຕອບແຕກຕ່າງກັນ. ກວດສອບດ້ວຍຊ່ອງປ້ອນລະຫັດໃນໜ້າກໍໄດ້ (`/verify/?code=...`).
- ຖ້າຕ້ອງການກວດສອບໄຟລ໌ PDF ທີ່ໄດ້ຮັບມາເອງ ໃຫ້ທຽບເຊັກຊຳ (SHA-256) ໃນລາຍລະອຽດທະບຽນກັບແຮັດຂອງໄຟລ໌. ກວດສອບດ້ວຍຄຳສັ່ງ `uv run manage.py certificate_verify {ລະຫັດ}` ກໍໄດ້ ([ຄຳສັ່ງ](../operations/commands.md)).
- API JSON ກວດສອບຄວາມຖືກຕ້ອງສຳລັບລະບົບພາຍນອກຈະເພີ່ມໃນ Phase 12 (ເກນ ແລະ ລາຍການດຽວກັນ).

## ພອດທໍຂອງນັກສຶກສາ

**ໃບຢັ້ງຢືນ** (ເມນູນັກສຶກສາ ແລະ ສິດເກົ່າ): ລາຍການໃບຢັ້ງຢືນທີ່ອອກໃຫ້ບັນທຶກນັກສຶກສາຂອງຕົນ (ວັນທີອອກ, ປະເພດ ແລະ ພາສາ, ເລກທີ, ສະຖານະ) ແລະ PDF. ໃບທີ່ຖອນແລ້ວກໍສະແດງພ້ອມສະຖານະ ແຕ່ບໍ່ມີລິ້ງ PDF ແລະ ນັກສຶກສາດາວໂຫຼດ PDF ຂອງໃບຢັ້ງຢືນທີ່ຖອນແລ້ວບໍ່ໄດ້ (ພະນັກງານອອກໃບຢັ້ງຢືນເປີດໄດ້ເພື່ອກວດບັນທຶກ). ເປີດໄຟລ໌ຂອງນັກສຶກສາຄົນອື່ນບໍ່ໄດ້ (ທັງແອັບພລິເຄຊັນ ແລະ DB). ທີ່ຢູ່ PDF ແມ່ນ `/certificates/{ID ການອອກ}/download/`.

## ຄຳຖາມທີ່ພົບເລື້ອຍ

- **ການຂຽນຊື່ຜິດ.** ແກ້ໄຂຊື່ແບບອື່ນຂອງບຸກຄົນ (ພາສານັ້ນ) ແລ້ວ **ສ້າງໃໝ່**. ຖ້າເປັນໃບຢັ້ງຢືນທີ່ສົ່ງໄປແລ້ວ ໃຫ້ຖອນແລ້ວອອກໃໝ່.
- **ແກ້ໄຂແມ່ແບບແລ້ວ ແຕ່ໃບຢັ້ງຢືນທີ່ອອກໄປແລ້ວເດ?** ບໍ່ປ່ຽນ. ຖ້າຈຳເປັນ ໃຫ້ **ສ້າງໃໝ່** (ຫຼາຍໃບໃຊ້ຄຳສັ່ງ `certificate_render`).
- **ເລກທີຖືກຂ້າມ.** ຖ້າເກີດຂໍ້ຜິດພາດລະຫວ່າງການອອກ (ບໍລິການ PDF ຢຸດ ແລະ ອື່ນໆ) ເລກທີຖືກໃຊ້ໄປແລ້ວ ແລະ ບໍ່ມີແຖວໃນທະບຽນ. ເລກທີຮັບປະກັນພຽງຄວາມເປັນເອກະລັກ ບໍ່ຮັບປະກັນຄວາມຕໍ່ເນື່ອງ.
- **QR ຊີ້ໄປ `localhost`.** ຕັ້ງ `APP_URL` ຂອງເຊີບເວີທີ່ໃຊ້ງານຈິງເປັນທີ່ຢູ່ຂອງສະຖາບັນ ແລ້ວ **ສ້າງໃໝ່** ໃບຢັ້ງຢືນທີ່ກ່ຽວຂ້ອງ.

## ໜ້າຈໍຂອງການຕິດຕັ້ງນີ້

ໜ້າຈໍ ແລະ ໜ້າທີ່ຄືກັນກັບລະບົບເດີມ (Filament, Livewire); ວິທີໃຊ້ແຕກຕ່າງເລັກນ້ອຍ.

- **ອອກໃບຢັ້ງຢືນ** ເປີດໜ້າປ້ອນຂໍ້ມູນແທນກ່ອງໂຕ້ຕອບ. ລະບົບເດີມເປີດ PDF ໃນແຖບໃໝ່ຫຼັງອອກ; ການຕິດຕັ້ງນີ້ກັບໄປໜ້າບັນທຶກນັກສຶກສາ ແລະ ເປີດດ້ວຍລິ້ງ **PDF** ໃນການແຈ້ງເຕືອນ.
- ໃນທະບຽນ **PDF** ແລະ **ໜ້າຢືນຢັນ** ເປັນລິ້ງທ້າຍແຖວ; **ສ້າງໃໝ່** (ໜ້າຢືນຢັນການກະທຳ) ແລະ **ຖອນ** (ໜ້າປ້ອນເຫດຜົນ) ຢູ່ໃນເມນູແຖວ. ສ້າງໃໝ່ເຮັດໄດ້ສະເພາະໃບຢັ້ງຢືນທີ່ຍັງບໍ່ຖອນ.
- ແກ້ໄຂແມ່ແບບຢູ່ລຸ່ມໜ້າແກ້ໄຂປະເພດ. ບໍ່ສາມາດມີສອງແມ່ແບບສຳລັບພາສາດຽວກັນ. ຖ້າມີພຽງສິດ `ເບິ່ງຂໍ້ມູນອ້າງອີງ` ຈະເບິ່ງປະເພດ ແລະ ແມ່ແບບໄດ້ຢ່າງດຽວ.
- ເມື່ອບໍລິການ PDF ຜິດພາດລະຫວ່າງການອອກ ບໍ່ມີຫຍັງຖືກອອກ (ລະບົບເດີມອາດມີແຖວທະບຽນທີ່ບໍ່ມີ PDF).
