# ການຄຸ້ມຄອງກະແຈ

- ກຸ່ມເປົ້າໝາຍ: ຜູ້ປະຕິບັດງານ IT
- ກ່ຽວຂ້ອງ: [ການຕິດຕັ້ງ](installation.md), [ເອກະສານອ້າງອີງຄຳສັ່ງ](commands.md)

| ກະແຈ | ຈຸດປະສົງ | ຖ້າເຮັດເສຍ | ການປ່ຽນ |
|---|---|---|---|
| `DJANGO_SECRET_KEY` | ເຊສຊັນ, CSRF, ການລົງລາຍເຊັນ (ລິ້ງຕັ້ງລະຫັດຜ່ານໃໝ່, ລິ້ງຢືນຢັນອີເມວ, ຄຸກກີຈື່ອຸປະກອນ), ການເຂົ້າລະຫັດຄວາມລັບການຢືນຢັນສອງຂັ້ນຕອນ (ຄວາມລັບ TOTP ຂອງແອັບຢືນຢັນ, ລະຫັດກູ້ຄືນ) ແລະ ຄວາມລັບ client ຂອງ SSO | ຜູ້ໃຊ້ທຸກຄົນຖືກອອກຈາກລະບົບ, ລິ້ງທີ່ສົ່ງໄປແລ້ວໃຊ້ບໍ່ໄດ້, ແອັບຢືນຢັນ ແລະ ລະຫັດກູ້ຄືນທີ່ລົງທະບຽນແລ້ວໃຊ້ບໍ່ໄດ້ (ຕ້ອງຣີເຊັດການຢືນຢັນສອງຂັ້ນຕອນເປັນລາຍຜູ້ໃຊ້) | ຕາມຫຼັກການບໍ່ປ່ຽນ. ຂັ້ນຕອນການປ່ຽນ (ຖອດລະຫັດດ້ວຍກະແຈເກົ່າແລ້ວເຂົ້າລະຫັດໃໝ່) ຈະກຳນົດໃນ Phase 13 |
| `PII_ENCRYPTION_KEY` | ການເຂົ້າລະຫັດຂໍ້ມູນສ່ວນບຸກຄົນ ເຊັ່ນ ເລກບັດປະຈຳຕົວ (AES-256-GCM) | **ກູ້ຄືນຂໍ້ມູນສ່ວນບຸກຄົນທີ່ເຂົ້າລະຫັດແລ້ວບໍ່ໄດ້** | ຕາມຂັ້ນຕອນຂ້າງລຸ່ມ |
| `PII_HASH_KEY` | ແຮດຊ໌ສຳລັບຄົ້ນຫາຂໍ້ມູນສ່ວນບຸກຄົນແບບກົງກັນທຸກຕົວ (HMAC-SHA256) | ຄົ້ນຫາບໍ່ໄດ້ (ຂໍ້ມູນຍັງຢູ່) | ຕາມຫຼັກການບໍ່ປ່ຽນ |

ສ້າງ `DJANGO_SECRET_KEY` ດ້ວຍ `uv run python -c "import secrets; print(secrets.token_urlsafe(50))"` ແລະ ສ້າງກະແຈຂໍ້ມູນສ່ວນບຸກຄົນທັງສອງດ້ວຍ `uv run manage.py pii_generate_key`.

ຫຼັກການເກັບຮັກສາ

- ເກັບກະແຈທັງສາມໄວ້ຢ່າງໜ້ອຍສອງຊຸດ ແຍກຈາກການຕັ້ງຄ່າຂອງເຊີບເວີ ໃນບ່ອນເກັບຄວາມລັບ (Vault, ບໍລິການຈັດການຄວາມລັບຂອງຄລາວ ແລະ ອື່ນໆ) ຫຼື ການເກັບແບບອອບລາຍທີ່ປະທັບຕາ.
- ບໍ່ເກັບໄວ້ບ່ອນດຽວກັນກັບໄຟລ໌ສຳຮອງ. ເຖິງແມ່ນໄຟລ໌ສຳຮອງ DB ຮົ່ວໄຫຼ ກໍຕ້ອງອ່ານຂໍ້ມູນສ່ວນບຸກຄົນບໍ່ໄດ້ຖ້າບໍ່ມີກະແຈ.
- ຢ່າໃຊ້ກະແຈຂອງ `.env` ສຳລັບພັດທະນາ ຫຼື ການຕັ້ງຄ່າທົດສອບໃນການນຳໃຊ້ຈິງ.

## ຂັ້ນຕອນການປ່ຽນກະແຈຂໍ້ມູນສ່ວນບຸກຄົນ

1. ສ້າງກະແຈໃໝ່ດ້ວຍ `uv run manage.py pii_generate_key` (ໃຊ້ສະເພາະ `PII_ENCRYPTION_KEY` ຈາກຜົນລັບ).
2. ໃສ່ກະແຈປັດຈຸບັນໄວ້ໃນ `PII_PREVIOUS_KEYS` (ຫຼາຍອັນໃຫ້ຂັ້ນດ້ວຍຈຸດ) ແລະ ໃສ່ກະແຈໃໝ່ໄວ້ໃນ `PII_ENCRYPTION_KEY`.
3. ໃຫ້ໂປຣເຊສອ່ານການຕັ້ງຄ່າໃໝ່: ເລີ່ມ gunicorn ແລະ Celery worker ໃໝ່ (Docker: `docker compose restart app worker beat`).
4. ສຳລັບແຕ່ລະໂມເດລທີ່ມີຂໍ້ມູນສ່ວນບຸກຄົນ ກວດຈຳນວນດ້ວຍ `uv run manage.py pii_reencrypt {ແອັບ.ໂມເດລ} --dry-run` (ຕົວຢ່າງ `person.Person`) ແລ້ວແລ່ນໂດຍບໍ່ມີ `--force` (ຕອບຄຳຖາມຢືນຢັນ).
5. ຫຼັງຈາກ Flower ສະແດງວ່າວຽກສຳເລັດ ແລະ ຜົນ `--dry-run` ເປັນ 0 ແລ້ວ ໃຫ້ລຶບກະແຈເກົ່າອອກຈາກ `PII_PREVIOUS_KEYS`.
6. ເກັບກະແຈເກົ່າແບບປະທັບຕາໄວ້ຕະຫຼອດໄລຍະເກັບຮັກສາໄຟລ໌ສຳຮອງ (ຕ້ອງໃຊ້ເມື່ອກູ້ຄືນໄຟລ໌ສຳຮອງເກົ່າ).
