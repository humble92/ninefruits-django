# ການແກ້ໄຂບັນຫາ

- ກຸ່ມເປົ້າໝາຍ: ຜູ້ປະຕິບັດງານ IT
- ກ່ຽວຂ້ອງ: [ລາຍການກວດສອບການນຳໃຊ້ລະບົບ](deployment-checklist.md), [ວຽກຕາມກຳນົດເວລາ](scheduled-jobs.md), [ເອກະສານອ້າງອີງຄຳສັ່ງ](commands.md)

| ອາການ | ສິ່ງທີ່ຕ້ອງກວດ |
|---|---|
| ຫຼັງເຂົ້າສູ່ລະບົບຖືກພາໄປໜ້າຄວາມປອດໄພທັນທີ | ນະໂຍບາຍການຢືນຢັນສອງຂັ້ນຕອນເປັນ "ບັງຄັບ" ແລະ ໄລຍະຜ່ອນຜັນໝົດແລ້ວ. ແກ້ໄດ້ເມື່ອຜູ້ໃຊ້ລົງທະບຽນ. ນະໂຍບາຍຢູ່ທີ່ **ການຕັ້ງຄ່າ > ຄວາມປອດໄພ** |
| ໜ້າບໍລິຫານສະແດງ 403 | ຜູ້ໃຊ້ບໍ່ມີການມອບບົດບາດທີ່ຍັງມີຜົນ ເຊິ່ງມີສິດ `admin_panel.access` (`ເປີດໜ້າບໍລິຫານ`). ເປີດຜູ້ໃຊ້ທີ່ **ຜູ້ໃຊ້ ແລະ ສິດເຂົ້າເຖິງ > ຜູ້ໃຊ້** ແລະ ກວດລາຍການ **ການມອບບົດບາດ** (ໄລຍະເວລາ, ຂອບເຂດ) |
| ບໍ່ເຫັນເມນູ | ບົດບາດບໍ່ມີສິດຂອງໜ້ານັ້ນ (ຕົວຢ່າງ: `roles.view`) |
| ລະຫັດທາງອີເມວບໍ່ມາ | ການຕັ້ງຄ່າເມວ (`MAIL_*`, `DEFAULT_FROM_EMAIL`), ບັນທຶກ `ສົ່ງລະຫັດທາງອີເມວ` ໃນ **ການກວດສອບ > ເຫດການຄວາມປອດໄພ**, ຂີດຈຳກັດການສົ່ງ (ຕໍ່ຜູ້ໃຊ້ 1 ຄັ້ງຕໍ່ນາທີ, 5 ຄັ້ງຕໍ່ຊົ່ວໂມງ) |
| ໜ້າເຂົ້າສູ່ລະບົບຕອບ `429 Too Many Requests` | ທີ່ຢູ່ດຽວພະຍາຍາມເຂົ້າສູ່ລະບົບເກີນ `LOGIN_RATE_LIMIT_PER_IP` (ຄ່າເລີ່ມຕົ້ນ 30) ຄັ້ງຕໍ່ນາທີ. ຖ້າຜູ້ໃຊ້ຫຼາຍຄົນຖືກບລັອກພ້ອມກັນ ໃຫ້ກວດວ່າ `TRUSTED_PROXY_COUNT` ກົງກັບຈຳນວນ proxy ຕົວຈິງ (ທຸກຄົນເບິ່ງຄືມາຈາກທີ່ຢູ່ Nginx ຫຼືບໍ່); ຖ້າຢູ່ຫຼັງ NAT ຂອງວິທະຍາເຂດ ໃຫ້ເພີ່ມຄ່າ ([ລາຍການກວດສອບການນຳໃຊ້ລະບົບ](deployment-checklist.md)) |
| ລະຫັດຜ່ານຖືກແຕ່ເຂົ້າສູ່ລະບົບບໍ່ໄດ້ | ການເຂົ້າສູ່ລະບົບຖືກລັອກ (`ການເຂົ້າສູ່ລະບົບຖືກລັອກ` ໃນ **ເຫດການຄວາມປອດໄພ**) ຫຼື ບັນຊີຖືກປິດໃຊ້ງານ. ປົດລັອກ: `uv run manage.py security_unlock_user <ອີເມວ> --reason="..."` |
| ໜ້າຈໍສະແດງຂໍ້ມູນຂອງຄົນອື່ນ 0 ລາຍການ | ອາດເປັນເລື່ອງປົກກະຕິ (ຄວາມປອດໄພລະດັບແຖວ). ກວດວ່າຜູ້ປະຕິບັດຂອງເຊສຊັນ DB ຖືກຕັ້ງແລ້ວຫຼືບໍ່ ຈາກຖັນຜູ້ໃຊ້ໃນ **ການກວດສອບ > ການປ່ຽນແປງຂໍ້ມູນ** |
| `400 Bad Request` | ຊື່ host ທີ່ຮ້ອງຂໍບໍ່ຢູ່ໃນ `DJANGO_ALLOWED_HOSTS` |
| `403 CSRF verification failed` | `DJANGO_CSRF_TRUSTED_ORIGINS` ບໍ່ມີທີ່ຢູ່ `https://` ຫຼື Nginx ບໍ່ສົ່ງ `X-Forwarded-Proto` |
| ການປ່ຽນເສັ້ນທາງ HTTPS ວົນບໍ່ສິ້ນສຸດ | Nginx ບໍ່ສົ່ງ `X-Forwarded-Proto $scheme` ເຮັດໃຫ້ Django ເຫັນເປັນຄຳຮ້ອງຂໍ HTTP (`SECURE_PROXY_SSL_HEADER`) |
| ໜ້າຈໍບໍ່ມີ style ຫຼື script, ຂໍ້ຜິດພາດ `manifest.json` | `npm ci && npm run build` (`static/dist/`), `collectstatic`, ເສັ້ນທາງ `/static/` ຂອງ Nginx. ການນຳໃຊ້ຈິງໃຊ້ `VITE_DEV_MODE=false` |
| ບາງສ່ວນຂອງໜ້າຈໍເປັນພາສາອັງກິດ | ບໍ່ໄດ້ແລ່ນ `compilemessages --ignore=.venv` (ບໍ່ມີ `.mo`). ຖ້າເປັນຂໍ້ຄວາມໃໝ່ ໃຫ້ແລ່ນ `uv run manage.py i18n_missing <locale>` |
| `permission denied for schema public` | ແອັບພລິເຄຊັນພະຍາຍາມແລ່ນ DDL ດ້ວຍ `app_runtime`. ແລ່ນ migration ດ້ວຍ `uv run manage.py migrate` ຫຼື `setup_install` ເທົ່ານັ້ນ (ໃຊ້ `app_migrator` ອັດຕະໂນມັດ) |
| `Audit records are append-only` | ມີການພະຍາຍາມແກ້ໄຂ/ລຶບຕາຕະລາງບັນທຶກການກວດສອບ. ນີ້ຄືການຂັດຂວາງທີ່ຖືກຕ້ອງ |
| ສ້າງ PDF ບໍ່ສຳເລັດ | `uv run manage.py pdf_sample`, ສະຖານະ Gotenberg, `GOTENBERG_URL`, `GOTENBERG_TIMEOUT` |
| ວຽກໃນຄິວຢຸດຄ້າງ | ກວດການເຊື່ອມຕໍ່ຂອງ worker ແລະ ວຽກທີ່ລົ້ມເຫຼວໃນ Flower, `uv run celery -A config inspect active`, ການເຊື່ອມຕໍ່ Redis (`REDIS_URL`) |
| ວຽກຕາມກຳນົດເວລາບໍ່ແລ່ນ, `/api/v1/health/` ຕອບ `degraded` | beat ຢຸດແລ້ວ (ບໍ່ມີສັນຍານຊີບຂອງຕົວກຳນົດເວລາເກີນ 5 ນາທີ). ກວດໂປຣເຊສ beat ແລະ log. beat ມີພຽງໂຕດຽວ |
| log ຂອງ worker ມີ `Received unregistered task` | worker ຍັງແລ່ນໂຄດເກົ່າຢູ່. ເລີ່ມ worker ໃໝ່ຫຼັງການນຳໃຊ້ລະບົບ |
| ການປິດພາກຮຽນບໍ່ສຳເລັດ | ວຽກ `grading.close_term_records` ທີ່ລົ້ມເຫຼວໃນ Flower. ແກ້ສາເຫດແລ້ວເລີ່ມການປິດພາກຮຽນໃໝ່ (ການຄຳນວນຕໍ່ນັກສຶກສາແລ່ນຊ້ຳໄດ້ຜົນດຽວກັນ) |

ການຕິດຕາມລະດັບຄຳຮ້ອງຂໍ: ດ້ວຍຄ່າຂອງ header ຕອບກັບ `X-Request-Id` ສາມາດຄົ້ນຫາ log (`request_id` ໃນ JSON), ບັນທຶກການກວດສອບທາງທຸລະກິດ, ການປ່ຽນແປງຂໍ້ມູນ ແລະ ເຫດການຄວາມປອດໄພໄດ້ພ້ອມກັນ. ຖ້າ Nginx ສົ່ງ `X-Request-Id $request_id` ກໍເຊື່ອມກັບ access log ຂອງ Nginx ໄດ້ນຳ. ການແລ່ນຄຳສັ່ງໃຊ້ ID ການແລ່ນທີ່ຂຶ້ນຕົ້ນດ້ວຍ `cmd-`.
